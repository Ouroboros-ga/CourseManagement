# 任务4操作说明的真实页面勘误

本文件记录任务5实际浏览器发现，原任务4手册保留为编写时快照。“已实现”表示存在实现，不等于本次验收通过；运行结果以[任务5报告](REPORT.md)为准。

| 原说明/预期 | 本次实际页面 | 使用方式/边界 |
| --- | --- | --- |
| 组织/组规则主要列在教师手册 | 已委任负责人可新建组、保存规则、加成员并启用 | 以当前有效权限为准，不能一律要求教师办理；不推导每名负责人都有全部能力 |
| 下发排班(N)、智能抽查 | 当前按钮“确认下发并排班 (1)”“智能抽查推荐”；任务列表为“智能排班（筛选全部）” | 下发和派发仍两阶段，0安排保留已生成任务 |
| 导入资格可直接准备排班 | 两个有效资格导入者无底册账号，排班被拒绝 | F01未修复，不能把手工建号写成正常必要步骤 |
| 批量自习生成后查课表 | 成功弹窗但未保存 | F02未修复，不将弹窗当成功完成 |
| B3多表首表缺席不删除 | 本次06通用多表被识别层拒绝，原B3专用格式未验 | 使用支持的单表路径；不能宣称B3已通过或已回归 |
| 窄屏展开菜单后退出 | 菜单无登出，宽屏才见登出 | 记录UI-06；现有宽屏登出有效 |
| 负责人身份 | 实际标签只显示学生，管理功能可用 | UI-07，不靠标签判断权限 |
| 审核/统计文案 | “提交审核”“初审”“已审核通过”等仍残留 | 志愿者提交即生效、学生异议一次审核的规则不变 |
| 更正理由 | 预填特定假条审批事实 | 应替换为真实核对依据；本轮仅合成理由，不沿用不实默认 |
| 截止历史查看办理人 | 页面历史只有版本、时刻、修改时间和说明 | 当前无法从此页面确认办理账号，不推导后台没有审计 |
| 两处教学周筛选 | 顶栏换周后课表本地筛选仍保持原周 | 查询前同时核对课表自身周次，避免读错范围 |
| 学生端课表高保真预览 | 属Web管理端预览 | 不作为微信小程序已发布或真机通过证据 |
