## 1. 产品目标与范围

将现有查课系统扩展为学校统一管理、学院独立运营的查课平台：各学院管理自己的课表、作息、早晚自习、志愿者组织、任务、考勤和报表；校级人员按授权进行监管及跨院协调。

同时提供绑定后的学生个人课表便利功能。个人课表以学生自己的内容为准，完全独立于查课业务；学校发布更新只在小程序内提示。

本期规划按一所学校下辖多个二级学院设计，不以跨学校 SaaS、多级任意组织树、通用审批引擎或教务自动抓取为交付目标。开发范围见配套文档；完整产品交付以分阶段验收为准。

## 2. 业务对象与用户

| 对象 | 定义 |
| --- | --- |
| 学院工作区 | 学院负责的教学、查课和管理范围；不是仅供筛选的标签 |
| 学期与日历 | 日期、教学周、停课与调休规则 |
| 作息方案 | 某范围、某时间段有效的节次名称与实际起止时间 |
| 课程与课表 | 普通课程及名为“早自习”“晚自习”的课程统一登记，包含对象、周次、星期、时间和地点 |
| 课程类型 | 学院维护的课程分类，如普通课、早自习、晚自习、集中训练；用于查课范围和统计，不另建业务流程 |
| 具体课次 | 某一天实际发生的一次课程，早晚自习使用同一展开方式 |
| 志愿者组 | 学院下可维护的人员组织，有成员、负责人、查课范围和冲突规则；名称不决定其业务能力 |
| 查课任务 | 针对具体场次的检查安排，具有归属、名单、时间和受派信息 |
| 个人课表 | 学生自己的显示副本，独立于上述正式业务事实 |

校级超管负责学校配置、学院和管理员任命；学院教师管理员绑定有效主学院后执行全部本院工作区管理，不逐人配置本院权限；跨学院管理或支援仍需超管显式授权。组织负责人管理指定组的成员与任务；志愿者执行本人受派；学生查看本人考勤、提交异议并维护个人课表。

保留现有五类核心身份。异议一次审核、人工考勤更正、导出、统计和组织管理作为可单独配置的能力，不靠大量增加固定角色满足所有组合；旧初核字段只保留历史，不恢复初核写入流程。

## 3. 功能需求

### PR-01 学院工作区

Web 顶部提供学院与学期选择，单学院用户默认进入其授权范围，多学院用户可切换。校级汇总为独立入口，“全部学院”不能成为普通批量编辑目标。

学院启停、更名和归档保留历史。停用后停止新增业务，已有未来任务进入待处理清单。课表、班级、学生、任务、考勤、异议、文件、导入批次、统计和导出都执行一致的隔离规则；无权访问的学院数据不能通过搜索和计数泄露。

### PR-02 可配置管理权限

每份授权明确：被授权人、动作、学院、课程或组织限制、有效期和授予人。权限配置提供模板、范围选择、有效期、变更预览及审计记录。

示例：张老师在 A 学院可排班，在 B 学院只读统计。B 学院不能因张老师在 A 的权限而变得可写。组织负责人不自动取得全院名单或异议终审权。

| 操作 | 超管 | 学院教师管理员 | 组织负责人 | 志愿者/学生 |
| --- | --- | --- | --- | --- |
| 学院、管理员任命 | 校级配置 | 无 | 无 | 无 |
| 课表、作息、活动 | 按校级授权 | 授权学院及功能 | 默认仅执行所需读取 | 本人有关资料 |
| 成员和排班 | 按校级授权 | 授权学院 | 指定组织及类型 | 本人受派/换班 |
| 考勤更正、异议一次审核 | 按对应能力授权 | 本院默认能力 | 默认无，需另授权 | 本人记录/异议 |
| 报表与明细导出 | 汇总与明细分别授权 | 授权学院范围 | 本组织执行统计 | 本人可见内容 |

角色与范围不能替代资源状态、本人身份和乐观锁校验。停用、解绑、撤权与会话联动继续有效，保留最后有效超管保护。

### PR-03 跨学院协作

跨院管理给管理者增加目标学院的明确授权；跨院支援给执行组织指定目标学院、课程范围和有效期。支援志愿者仅看到受派所必需的信息，不能遍历目标学院学生。

任务具有唯一负责学院、负责组织及执行规则快照。同人多组时按本次受派指定的组解释规则，不能自动选其所有组中最宽松的一套。撤销成员或支援资格时，停止新派发，并列出既有未来受派供撤回/改派；历史不丢失。

### PR-04 灵活作息与教学日历

区分学期周次、教学日历和每日作息。学校可提供模板，学院配置自己的版本；院内校区/年级确有差异时，教学班或活动显式选用方案。

每个时段有稳定名称、起止时间和排序，支持早自习、普通节次和晚自习。冲突按实际时间计算；同名节次不一定同时，不同节次也可能重叠。

方案按草稿、发布、生效、归档管理；发布后通过新版本修改。发布前列出未来课次、任务、受派和截止规则的影响；已完成任务保留原事实。默认时区建议为 Asia/Shanghai，首期建议只支持当日结束的活动，跨午夜范围见 D08。

学校停课、学院停课和补课来源要明确。课程统一使用日历规则；如某课程需要固定星期，可在通用课表字段选择，不为早晚自习另建日历流程。

### PR-05 普通课与早晚自习

所有课程共用“课程 → 教学班/名单 → 课表 → 日期课次 → 查课任务”流程。早自习、晚自习直接作为课程名称录入，与普通课使用同样的学院、学期、班级/名单、周次、星期、起止时间和地点字段，不另建活动计划或专用生成流程。自习无授课教师时，教师字段可空。

课程名称回答“这是什么课”，课程类型回答“它属于哪一类”。例如“2026 级早自习”属于“早自习”，“高等数学”属于“普通课”；名称相同不代表类型相同。每个学院、学期内的教学班只选一个课程类型，该教学班的课表和课次继承它。不同分类需要拆成不同教学班，不在每条课表里重复维护分类。

#### 课程类型维护

学院有权限的管理员可新建类型，修改名称、说明、排序及展示颜色，并启用/停用。首批可提供“普通课、早自习、晚自习”初始配置，后续可增设“集中训练”等类型，无需开发发版。类型本身不自带特殊时间、冲突豁免或考勤流程；这些分别由课表和组规则决定。

同一学院内类型名称不重复，跨院可以同名；后台按稳定标识关联，改名不破坏课程和组规则。跨院支援必须明确选择目标学院的实际类型，不能把两个学院同名类型自动视作同一授权。校级报表保留学院与类型维度，不凭名称强行合并。

停用前展示关联教学班、组配置和未来任务。停用后不再用于新增分类、生成新任务或新派发；已有正式课表仍正常显示，并参与本人课程冲突。已受派任务保留并列入待处理清单，管理员明确保留、改派或取消；停用不自动删课、取消受派或改变考勤。存在引用的类型只能停用，未被引用的类型才可删除。

调整教学班类型前预览未来影响：旧抽查/排班预览失效，未派任务需更新分类并复核组范围，已受派任务进入待处理；已完成任务和历史报表保留当时类型及名称。仅修改类型名称、颜色或排序不改变业务资格，历史快照也不被覆盖。

#### 按组范围抽查

先选择执行组、目标学院与学期，再筛选该组负责的类型、班级和日期范围，在得到的合法课次中手选或随机抽查，最后预览、生成和排班。抽查数量针对这个已筛选的集合；“每班抽 N 次”也只能从该班在范围内的课次中选。

例如 A 组只选“早自习”，它的随机候选就没有普通课和晚自习；B 组选“普通课”，不会因为早自习也在统一课表里而抽到它。候选不足时显示各班可选数量和缺额，不能自动混入其他类型补数。手选课次、导入任务、直接生成、人工改派也遵守同一组范围，不能绕开筛选。

管理员正向勾选需要查的场次，先预览，再生成任务，再针对生成结果排班。排班失败保留已生成任务。重复生成和重试不产生重复正式考勤。

分别配置学生参与活动的时间、志愿者查课占用时间、提交截止。继续保留“不得在查课日期之前提交、允许逾期补交且保留逾期事实”；若需限制到开始时刻再提交，按 D09 另行确认。

### PR-06 志愿者组织与生命周期

组具有所属学院、名称、查课范围、负责人、成员、有效期、状态与配置版本。管理员可新建、编辑、更名、启用、停用组；同一学院组名不重复。可以先保存未配齐的草稿，启用前必须明确负责人、有效期及非空查课类型。同人多组；成员身份、学期资格和实际受派分开记录。

组配置分为“基本信息、成员、查课范围、冲突规则”四部分。查课范围至少选择一个课程类型，并选择全部授权班级或指定班级，可用年级帮助批量勾选班级。类型间取并集，类型与班级取交集，再受学院/支援授权限制；年级筛选保存为明确班级选择，新班级不会悄悄进入指定名单。

类型留空不表示全部；新增类型不会自动被已有组接管。已选类型内新增的课次，只要满足班级、日期和授权范围即可进入候选。批次允许进一步缩小范围，不能扩大组权限。跨院支援为目标学院单独维护范围，超管的支援授权是上限，组负责人不能通过编辑范围获得新授权。

一个类型可以由多个组负责，一个组也可以负责多个类型。一次生成/排班批次必须明确一个执行组；同一课次首期只生成一份查课任务，多组范围重叠不产生重复任务。换执行组须重新检查新组范围、人员资格和冲突规则，不能用同一人的另一组宽松规则替代。

组更名保留成员和关联；所属学院不可直接修改，需要在目标学院新建组并明确转移。停用或缩小范围前展示未来任务影响，新生成/新派发立即按新配置校验，已有受派进入待处理并保留到明确处置，历史提交不丢失。被引用的组只能停用，不能级联删除成员历史和任务。恢复启用先核对类型、授权和有效期，不自动恢复撤回的受派。

支持成员批量导入、启停、入组/退组，停用、毕业、退组前展示未来任务影响。本版本不做组织学期复制或负责人完整交接；保留现有负责人字段与独立授权维护。

日/周上限在当前执行组配置，可以选择统计该组或全部组工作量；时间冲突查询始终涵盖本人各组受派，避免漏掉另一组同时安排。跨院支援同样计数。独立的志愿者请假/不可用声明属于组织业务，不能由个人显示课表自动生成。

### PR-07 可解释的组级规则

业务冲突规则只在组内配置，不再建立早自习、晚自习各一套规则，也不另建重复的校级冲突配置层。授权决定谁能修改组规则。规则结果采用禁止、人工确认后允许、允许；不把自动免到作为排班规则结果。

“本组检查哪些课程类型”和“遇到本人哪些课程冲突可以放行”是两个独立选项。例如早自习组只检查早自习，同时允许与本人的早自习重叠；这不表示可以忽略本人其他课程。类型不预设冲突结果，所有结果在执行组配置。

本人课程冲突先看具体教学班例外，再看该课程所属类型规则，最后用本组默认规则。同一对象只能有一条生效规则；每一门重叠课程分别判断，只要仍有禁止项就不能派。跨院同名类型不共享例外，未配置的外院课程按默认规则处理。例外匹配的是志愿者本人正在上的课程，不是待检查任务的类型。

| 来源或约束 | 推荐起点 | 制度状态 |
| --- | --- | --- |
| 本人正式课程（包括早晚自习） | 默认禁止；组可按类型配置，必要时按具体教学班覆盖为允许/人工确认/禁止 | 按稳定类型和教学班标识配置，不按课程名称硬编码 |
| 另一项同时到场的查课任务 | 默认禁止 | 合并巡查需求待 D02 |
| 检查本人班级 | 可配置禁止、提醒或允许 | 具体组规则待业务配置，不开放自改考勤/自审 |
| 成员、资格或支援授权无效 | 拒绝，需先修正授权 | 不用规则放宽绕过身份与学院范围 |
| 每日/每周上限、移动缓冲 | 在组内配置并展示计数口径 | 上限可统计本组或全部组，没有重复的校级规则入口 |
| 获批请假/不可用 | 始终禁止新增排班 | 本人所有组统一生效；组内 WARN/ALLOW 不能绕过，不读取个人课表 |

预览显示冲突原因、规则来源与后果；人工确认只对具体任务/人员/版本有效，自动排班不能自行代替人工确认。个人内容无论如何修改，都不得影响候选、规则或工作量。

### PR-08 大一早自习值勤场景

此节只是 C05/PR-07 的配置示例，不建立独立功能：

1. 在统一课表中给大一班级登记“早自习”，例如 07:00–07:40。
2. 给这些教学班选择“早自习”类型，新建检查组并加入若干大一学生，查课范围选择“早自习”类型及负责班级。
3. 该组将“本人课程类型为早自习时的重叠”设为允许；普通课程等未配置的重叠仍按默认规则处理。
4. 小王虽有本人早自习，也可派去检查 B 班；不需要判断年级等于大一或时间等于七点。
5. 如果小王已有另一组同时间查课任务，仍按本组的任务冲突规则处理，不能因课程冲突已放行而漏检。

排班允许重叠并不自动决定小王在 A 班的考勤结果。本人考勤沿用现有登记/更正流程，值勤人员具体记法见 D01；首期不因此新增自动免到模型或改变统计分母。C05 已覆盖“能否派出”，剩余只是学校对本人考勤如何登记的约定。

### PR-09 考勤、异议与报表

保留志愿者提交自动生成正式考勤、学生异议一次审核、人工更正与历史版本；旧初核字段仅作历史展示。支持按学院、课程类型、具体课程和执行组筛选；正式历史按任务当时分类统计，当前课表按当前分类展示，两种口径明确标注。学生出勤与志愿者履职分开。

按事实发生时的学生学院与任务归属追溯，转院不搬移旧记录。跨学院重复检查的结果分别归任务负责学院；校级汇总区分检查人次、去重学生数及学生课次数，不自动合成为唯一全校考勤。汇总标明学院、类型和分母；分母不可靠时不制造比例。异议审核、人工更正、明细导出、校级汇总独立授权。

跨院合班见 D05：建议一个真实场次只有一个负责学院和事实来源，参与学院按范围读取本人学生相关结果。未闭环前歧义数据进入待处理，不根据第一名学生猜归属。

### PR-10 导入、发布与配置影响

上传和预览时确认学院、学期、资料类型和作息来源；提供行级错误及重复项说明，禁止静默覆盖其他学院。发布前展示受影响课表、名单、任务和配置；草稿与正式发布分开。

导入默认普通课，不按文件类别或课程名称自动识别/映射类型。每院初始普通课、早自习、晚自习，仍可自行新增类型；早晚自习由前端按钮调用统一建课/课表API并明确传实际类型ID。已有教学班分类不因重复导入而静默重置。类型维护、组维护、成员维护、规则发布分别授权；拥有组编辑权不等于拥有学院类型维护权。

配置显示继承来源和学院可覆盖项。所有正式更新保留版本与操作人；学校课表发布后才成为个人课表更新提示的来源，内容没变不重复提示。

## 4. 微信小程序产品需求（不含开发实现）

### PR-11 个人课表初始化与查看

绑定后按学期从已明确发布的教务资料初始化云端个人副本。管理端总课表查询不是学生下发接口；初始化使用独立本人接口。只包含部分同学的选修不能导入全班所有人。

提供今日/周视图、周切换、课程详情、学期选择。已有内容始终读取个人保存结果，重复登录或绑定不重新覆盖；删空也是有效状态。新学期独立初始化，旧学期可查阅；转班转院提示来源变化，不重建本人当前课表。

未绑定、未分班、学校未发布、资料不完整和本周无课分别展示。跨作息课程按实际时间显示，不用本院节次号重新解释外院课程。

### PR-12 自主增删改

学生可添加选修和手动课程，编辑名称、教师、地点、周次、星期、时间和备注，可删除及恢复。支持整条规则或仅本次修改。编辑不审批，以最后成功保存为准。

编辑仅改变本人显示，不改变正式选课关系、排班冲突、受派、考勤或报表。课程重叠可以提示，但不因查课规则阻止学生保存。个人课表中不提供通过删除卡片取消正式任务的交互。

教务后续修改作息、教学周、日期或删除课程，都不能暗中移动/删除个人内容。多设备保存冲突时保留已保存内容并让学生选择重试；离线编辑建议不纳入首期，缓存查看显示更新时间。

### PR-13 站内教务更新提示

小程序提供简单通知列表，展示相关学期、教务发布版本、发布时间和说明。不设计已读/未读计数、忽略或采用流程；通知没有修改个人课表的副作用。相同内容再次发布不产生重复通知，与本人课程无关的变化不产生个人通知；移出正式名单的学生仍应收到该次变更提示。

个人修改保存在云端，后续读取以本人最后成功保存为准。教务再发布不覆盖、移动或删除个人内容；本轮不提供整份学校课表覆盖个人副本的操作。

提示基于本系统已收到且发布的教务资料，不承诺自动发现外部教务系统变化。内置提示不等于微信订阅推送，无需在此产品范围内承诺小程序关闭时通知送达。

### PR-14 小程序原有业务适配要求

本人受派任务、考勤和异议继续受服务端真实身份及资源范围保护；跨院支援只展示任务必需信息。任务展示学院、组织、课程名称、实际时间和截止，避免混淆。

个人课表与正式业务入口分清。换绑、退出、换账号不能看到上一人的个人内容。小程序的页面实现、文件改造、开发工具操作和端侧测试方案不在本轮开发文档内；以上仅为产品验收要求。

### 2026-10-15 确认：请假／不可用跨组统一生效

申请由有效组受理，待审批不影响排班；获批后与任务实际活动时间重叠的时段，本人所有组均不能新增排班，也不按学院拆分。统一采用左闭右开时间区间。

批准前展示已有受派数量并明确确认。既有受派不自动撤销，未来有效任务进入各自负责学院可见的变更影响清单，由有权限的人员保留、取消或改派；不会改写考勤或截止时事实。跨院管理者不会因此取得其他学院任务明细或请假原因。

拒绝或撤销后不再限制新排班。已批准申请不原地改时间，调整需撤销后重新申请、审批，保留原记录和操作人。本人只能申请本人、查看本人及撤回本人申请，不能自行批准。后端及Web提供管理流程，小程序页面仍不属于本轮开发范围。

## 2026-10-15 学校作息模板补充边界

学校模板由超管维护，仅包含节次名称、稳定标识、编号和时间；修改产生新版本，引用后不直接删除。学院选择同校有效模板的具体版本，复制为本学院本学期的独立草稿，可调整后按既有流程预览、发布和绑定教学班。学校更新只在学院作息入口提示，不覆盖学院草稿、已发布配置或任务快照；停用阻止新引用，既有配置继续保留。采用新版需明确创建新草稿并发布/绑定，不自动接管学院默认作息。产品与接口细节见 [学校作息模板说明](../development/SCHOOL_TIME_TEMPLATE_API.md)。

真实学院、课程与成员数据由使用者导入/维护；功能开发和共用逻辑验收可使用少量虚构数据，不要求先补齐生产数据。本次不包含组织学期复制或负责人完整交接。


## 2026-10-15 最终确认的接口增量
