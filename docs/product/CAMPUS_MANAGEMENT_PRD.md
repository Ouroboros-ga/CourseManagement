# CourseManagement 系统功能产品需求文档（全校多学院升级）

## 2026-10-14 实施边界

本次已实现固定教师学院、学生负责人当前学籍学院及功能开关、管理员全校统筹、显式平台管理能力，以及后端/Web 的学籍异动和学生数据交接。平台管理员沿用 SUPER_ADMIN，只增加 `administrator_account.manage`，不新增角色或登录入口。普通教师不能办理跨院异动，跨院由管理员办理。

正式学籍以生效区间解析，支持转班/转专业/转院、休学、复学、毕业、退学、未来计划撤销和明确的过去日期纠错。学号、学生 ID 和微信绑定保持稳定；过去纠错保留后续区间，不自动重写历史考勤。离校本人历史访问暂定十个日历年，归档不等于物理删除。

老师通过“学生交接与学籍”导出可回导的 XLSX，上传单文件或平铺 ZIP，预览新增/字段更新/异动/错误/缺失项，确认时重新核验权限、学生版本和行政班归属版本。全量对比的缺失项只提示核查；不会自动删人、归档或恢复学籍。每批只刷新一次受影响的未来正式任务名单。已开始、有提交或已有截止事实的任务保留原快照；无法确定来源或人工人数口径的任务进入待核定队列。

学校初始化名称为“绍兴理工学院”；正式学院为“人工智能学院（低空技术与工程学院）”，软件学院保留为“软件学院（测试）”。原软件学院两个班级及其学生、账号、业务历史全部保留。测试学院目前是独立学院工作区，未实现全校汇总自动排除测试数据；历史学校报表仍保留原内容。

**仍属规划：**学院独立作息/日历及实际时间排班、动态课程类型与志愿者组规则接入抽查/排班、小程序个人课表。已有类型/组配置表不等于上述业务已接入；本轮没有小程序新功能开发。无法可靠核定的存量课程、任务、批次和报表由管理员继续核定，不根据当前学生成员猜测历史归属。

实现、验收和部署边界见 [本次交付记录](../development/ENROLLMENT_IMPLEMENTATION_ACCEPTANCE_20261014.md)。其余章节保留完整设计目标，不能将规划验收项全部视为本次已通过。

## 1. 产品目标与范围

将现有查课系统扩展为学校统一管理、学院独立运营的查课平台：各学院管理自己的课表、作息、早晚自习、志愿者组织、任务、考勤和报表；管理员统一统筹全校业务，具备额外权限的平台管理员还可管理管理员账号。

同时提供绑定后的学生个人课表便利功能。个人课表以学生自己的内容为准，完全独立于查课业务；学校发布更新只在小程序内提示。

本期规划按一所学校下辖多个二级学院设计，不以跨学校 SaaS、多级任意组织树、通用审批引擎或教务自动抓取为交付目标。开发范围见配套文档；开发状态按本次实施边界和交付记录逐项核对。

## 2. 业务对象与用户

| 对象 | 定义 |
| --- | --- |
| 学院工作区 | 学院负责的教学、查课和管理范围；不是仅供筛选的标签 |
| 学期与日历 | 日期、教学周、停课与调休规则 |
| 学籍与专业 | 同一学生按生效日期所属学院、专业、行政班、就读状态；独立于永久身份和正式选课 |
| 作息方案 | 某范围、某时间段有效的节次名称与实际起止时间 |
| 课程与课表 | 普通课程及名为“早自习”“晚自习”的课程统一登记，包含对象、周次、星期、时间和地点 |
| 课程类型 | 学院维护的课程分类，如普通课、早自习、晚自习、集中训练；用于查课范围和统计，不另建业务流程 |
| 具体课次 | 某一天实际发生的一次课程，早晚自习使用同一展开方式 |
| 志愿者组 | 学院下可维护的人员组织，有成员、负责人、查课范围和冲突规则；名称不决定其业务能力 |
| 查课任务 | 针对具体场次的检查安排，具有归属、名单、时间和受派信息 |
| 个人课表 | 学生自己的显示副本，独立于上述正式业务事实 |

平台管理员管理管理员账号；管理员统筹全校业务、学院、教师账号及学院绑定；教师拥有所属学院完整业务权限；学生负责人按本院功能配置开展工作；组负责人管理本院指定组事务；志愿者执行本人受派；学生查看本人考勤、提出异议并维护私人课表。

保留原有五类身份，SUPER_ADMIN 在界面称“管理员”；持额外 administrator_account.manage 能力时显示“平台管理员”标记，不新增 PLATFORM_ADMIN 角色。教师固定拥有本院业务能力，负责人只配置本院允许的功能；组负责人是组内职责，不新增身份。当前异议已是一次审核，旧初核只读。

## 3. 功能需求

### PR-01 学院工作区

Web 顶部提供学院与学期选择，单学院用户默认进入其授权范围，多学院用户可切换。校级汇总为独立入口，“全部学院”不能成为普通批量编辑目标。

学院启停、更名和归档保留历史。停用后停止新增业务，已有未来任务进入待处理清单。课表、班级、学生、任务、考勤、异议、文件、导入批次、统计和导出都执行一致的隔离规则；无权访问的学院数据不能通过搜索和计数泄露。

### PR-02 固定角色与学院范围

| 账号/职责 | 业务范围 | 可操作内容 | 不可操作内容 |
| --- | --- | --- | --- |
| 平台管理员（SUPER_ADMIN＋额外能力） | 全校业务＋管理员账号 | 沿用管理员业务；额外创建、查询、启停、重置管理员账号密码及配置同类能力 | 不因该能力代学生编辑私人课表或代执行者提交 |
| 管理员 SUPER_ADMIN | 全校 | 学院、教师账号/所属学院、全校教学与查课业务、跨学院学籍办理、校级配置及统筹 | 创建/停用其他管理员或授予平台管理员身份；代学生修改私人课表、代执行者提交事实 |
| 教师 TEACHER_ADMIN | 注册时绑定的唯一学院 | 本院完整教学/学生/名单/组/查课/考勤/异议/导入导出/业务审计；本院负责人任命及功能配置 | 其他学院业务、教师账号创建与所属学院调整、学校级配置、管理员账号 |
| 学生负责人 STUDENT_AFFAIRS_MANAGER | 本人当前学院 | 在已启用的本院功能内执行课表、查课、统计等工作 | 跨学院工作区、学籍变更/归档、角色提权、管理员/教师账号和私人课表 |
| 志愿者、学生 | 本人 | 本院组受派、本人考勤/异议、个人课表 | 本人关系之外的数据和管理操作 |

“本院全部权限”指本院业务管理能力，仍受账号状态、资源归属、版本、审核回避和事实保护限制，不意味着代学生/志愿者提交或读取私人课表。没有学院归属的教师不能默认进入全校；停用学院不开放其新业务。

权限配置简化为账号角色、教师所属学院、负责人本院功能开关；不建设教师动作矩阵、跨院授权、转授模板或通用规则编辑器。学生负责人范围从有效学籍核验且与获任命学院一致，前端只读展示，后台拒绝任何外院 ID。

### PR-03 管理员统筹与账号分层

管理员可切换学院处理业务并查看校级汇总，普通账号不能选择其他学院。批量操作仍明确学院或明确全校范围，不因管理员身份隐含作用于全部数据。跨学院转专业由管理员一次办理，同院转班/转专业由本院教师或管理员办理。

教师所属学院调整仅由管理员执行，先展示待办、未结异议和组负责事务交接，旧院管理范围立即停止，新院范围按新绑定生效；历史事实仍归原学院。学生负责人转院时旧任命失效，新院教师/管理员重新任命后才取得新院负责人能力，不自动把旧权限带过去；本人历史查询不受此管理限制牵连。

平台管理员继续使用现有管理员登录与业务页面，额外显示管理员账号管理区域，不另建平台门户。普通管理员没有这项能力，即使能管理教师也不能管理其他管理员。旧角色分配、通用密码重置、可选权限等入口必须执行相同保护，不能让普通管理员给自己开启平台能力。保留最后有效管理员及最后具备账号管理能力者的保护；初始平台能力通过明确的运维初始化赋给指定现有管理员，不自动赋给所有管理员。

### PR-04 灵活作息与教学日历

区分学期周次、教学日历和每日作息。学校可提供模板，学院配置自己的版本；院内校区/年级确有差异时，教学班或活动显式选用方案。

每个时段有稳定名称、起止时间和排序，支持早自习、普通节次和晚自习。冲突按实际时间计算；同名节次不一定同时，不同节次也可能重叠。

方案按草稿、发布、生效、归档管理；发布后通过新版本修改。发布前列出未来课次、任务、受派和截止规则的影响；已完成任务保留原事实。默认时区建议为 Asia/Shanghai，首期建议只支持当日结束的活动，跨午夜范围见 D08。

学校停课、学院停课和补课来源要明确。课程统一使用日历规则；如某课程需要固定星期，可在通用课表字段选择，不为早晚自习另建日历流程。

### PR-05 普通课与早晚自习

所有课程共用“课程 → 教学班/名单 → 课表 → 日期课次 → 查课任务”流程。早自习、晚自习直接作为课程名称录入，与普通课使用同样的学院、学期、班级/名单、周次、星期、起止时间和地点字段，不另建活动计划或专用生成流程。自习无授课教师时，教师字段可空。

课程名称回答“这是什么课”，课程类型回答“它属于哪一类”。例如“2026 级早自习”属于“早自习”，“高等数学”属于“普通课”；名称相同不代表类型相同。每个学院、学期内的教学班只选一个课程类型，该教学班的课表和课次继承它。不同分类需要拆成不同教学班，不在每条课表里重复维护分类。

#### 课程类型维护

学院有权限的管理员可新建类型，修改名称、说明、排序及展示颜色，并启用/停用。首批可提供“普通课、早自习、晚自习”初始配置，后续可增设“集中训练”等类型，无需开发发版。类型本身不自带特殊时间、冲突豁免或考勤流程；这些分别由课表和组规则决定。

同一学院内类型名称不重复，跨院可以同名；后台按稳定标识关联，改名不破坏课程和组规则。各院维护自己的实际类型，同名类型不共享权限；管理员校级查看时也保留学院维度。校级报表保留学院与类型维度，不凭名称强行合并。

停用前展示关联教学班、组配置和未来任务。停用后不再用于新增分类、生成新任务或新派发；已有正式课表仍正常显示，并参与本人课程冲突。已受派任务保留并列入待处理清单，管理员明确保留、改派或取消；停用不自动删课、取消受派或改变考勤。存在引用的类型只能停用，未被引用的类型才可删除。

调整教学班类型前预览未来影响：旧抽查/排班预览失效，未派任务需更新分类并复核组范围，已受派任务进入待处理；已完成任务和历史报表保留当时类型及名称。仅修改类型名称、颜色或排序不改变业务资格，历史快照也不被覆盖。

#### 按组范围抽查

先选择执行组、目标学院与学期，再筛选该组负责的类型、班级和日期范围，在得到的合法课次中手选或随机抽查，最后预览、生成和排班。抽查数量针对这个已筛选的集合；“每班抽 N 次”也只能从该班在范围内的课次中选。

例如 A 组只选“早自习”，它的随机候选就没有普通课和晚自习；B 组选“普通课”，不会因为早自习也在统一课表里而抽到它。候选不足时显示各班可选数量和缺额，不能自动混入其他类型补数。手选课次、导入任务、直接生成、人工改派也遵守同一组范围，不能绕开筛选。

管理员正向勾选需要查的场次，先预览，再生成任务，再针对生成结果排班。排班失败保留已生成任务。重复生成和重试不产生重复正式考勤。

分别配置学生参与活动的时间、志愿者查课占用时间、提交截止。继续保留“不得在查课日期之前提交、允许逾期补交且保留逾期事实”；若需限制到开始时刻再提交，按 D09 另行确认。

### PR-06 志愿者组织与生命周期

组具有所属学院、名称、查课范围、负责人、成员、有效期、状态与配置版本。管理员可新建、编辑、更名、启用、停用组；同一学院组名不重复。可以先保存未配齐的草稿，启用前必须明确负责人、有效期及非空查课类型。同人多组；成员身份、学期资格和实际受派分开记录。

组配置分为“基本信息、成员、查课范围、冲突规则”四部分。查课范围至少选择一个课程类型，并选择本院全部班级或指定班级，可用年级帮助批量勾选班级。类型间取并集，类型与班级取交集，所有关联强制属于该学院；年级选择保存具体班级，不自动扩大名单。

类型留空不表示全部；新增类型不会自动被已有组接管。已选类型内新增的课次，只要满足班级、日期和授权范围即可进入候选。批次允许进一步缩小范围，不能扩大组权限。组范围只能引用本院类型及班级，管理员也不能将一个组配置成跨学院组。

一个类型可以由多个组负责，一个组也可以负责多个类型。一次生成/排班批次必须明确一个执行组；同一课次首期只生成一份查课任务，多组范围重叠不产生重复任务。换执行组须重新检查新组范围、人员资格和冲突规则，不能用同一人的另一组宽松规则替代。

组更名保留成员和关联；所属学院不可直接修改，需要在目标学院新建组并明确转移。停用或缩小范围前展示未来任务影响，新生成/新派发立即按新配置校验，已有受派进入待处理并保留到明确处置，历史提交不丢失。被引用的组只能停用，不能级联删除成员历史和任务。恢复启用先核对类型、授权和有效期，不自动恢复撤回的受派。

支持成员批量导入、启停、入组/退组、负责人交接和新学期配置复制。学期复制不复制正式受派和履职历史。停用、毕业、退组前展示未来任务影响。

日/周上限在当前执行组配置，可以选择统计该组或全部组工作量；时间冲突查询始终涵盖本人各组受派，避免漏掉另一组同时安排。本人既有历史受派仍参与实际冲突核对。独立的志愿者请假/不可用声明属于组织业务，不能由个人显示课表自动生成。

### PR-07 可解释的组级规则

业务冲突规则只在组内配置，不再建立早自习、晚自习各一套规则，也不另建重复的校级冲突配置层。授权决定谁能修改组规则。规则结果采用禁止、人工确认后允许、允许；不把自动免到作为排班规则结果。

“本组检查哪些课程类型”和“遇到本人哪些课程冲突可以放行”是两个独立选项。例如早自习组只检查早自习，同时允许与本人的早自习重叠；这不表示可以忽略本人其他课程。类型不预设冲突结果，所有结果在执行组配置。

本人课程冲突先看具体教学班例外，再看该课程所属类型规则，最后用本组默认规则。同一对象只能有一条生效规则；每一门重叠课程分别判断，只要仍有禁止项就不能派。跨院同名类型不共享例外，未配置的外院课程按默认规则处理。例外匹配的是志愿者本人正在上的课程，不是待检查任务的类型。

| 来源或约束 | 推荐起点 | 制度状态 |
| --- | --- | --- |
| 本人正式课程（包括早晚自习） | 默认禁止；组可按类型配置，必要时按具体教学班覆盖为允许/人工确认/禁止 | 按稳定类型和教学班标识配置，不按课程名称硬编码 |
| 另一项同时到场的查课任务 | 默认禁止 | 合并巡查需求待 D02 |
| 检查本人班级 | 可配置禁止、提醒或允许 | 具体组规则待业务配置，不开放自改考勤/自审 |
| 成员、资格或学院归属无效 | 拒绝，需先修正授权 | 不用规则放宽绕过身份与学院范围 |
| 每日/每周上限、移动缓冲 | 在组内配置并展示计数口径 | 上限可统计本组或全部组，没有重复的校级规则入口 |
| 组织内请假/不可用 | 默认禁止 | 通过组织流程调整，不读取个人课表 |

预览显示冲突原因、规则来源与后果；人工确认只对具体任务/人员/版本有效，自动排班不能自行代替人工确认。个人内容无论如何修改，都不得影响候选、规则或工作量。

### PR-08 大一早自习值勤场景

此节只是 C05/PR-07 的配置示例，不建立独立功能：

1. 在统一课表中给大一班级登记“早自习”，例如 07:00–07:40。
2. 给这些教学班选择“早自习”类型，新建检查组并加入若干大一学生，查课范围选择“早自习”类型及负责班级。
3. 该组将“本人课程类型为早自习时的重叠”设为允许；普通课程等未配置的重叠仍按默认规则处理。
4. 小王虽有本人早自习，也可派去检查 B 班；不需要判断年级等于大一或时间等于七点。
5. 如果小王已有另一组同时间查课任务，仍按本组的任务冲突规则处理，不能因课程冲突已放行而漏检。

排班允许重叠并不自动决定小王在 A 班的考勤结果。本人考勤沿用现有登记/更正流程，值勤人员具体记法见 D01；首期不因此新增自动免到模型或改变统计分母。C05 已覆盖“能否派出”，剩余只是学校对本人考勤如何登记的约定。

### PR-09 考勤、异议与报表

保留志愿者提交自动生成正式考勤、人工更正与历史版本。学生考勤异议采用当前工作区的一次审核：有审核权限者通过或驳回，需要改变认定时同时具备考勤更正能力；旧初核记录只作为历史参考，不再要求先初核再终审。支持按学院、课程类型、具体课程和执行组筛选；正式历史按任务当时分类统计，当前课表按当前分类展示，两种口径明确标注。学生出勤与志愿者履职分开。

按事实发生时的学生学院与任务归属追溯，转院不搬移旧记录。校级汇总需要去重并标明学院、类型和分母；分母不可靠时不制造比例。异议审核、考勤更正、明细导出、校级汇总独立授权；学生工作负责人不会仅因组负责人身份而取得审核能力。

跨院合班见 D05：建议一个真实场次只有一个负责学院和事实来源，参与学院按范围读取本人学生相关结果。未闭环前歧义数据进入待处理，不根据第一名学生猜归属。

### PR-10 导入、发布与配置影响

上传和预览时确认学院、学期、资料类型和作息来源；提供行级错误及重复项说明，禁止静默覆盖其他学院。发布前展示受影响课表、名单、任务和配置；草稿与正式发布分开。

导入增加课程类型映射：可为整批指定一个类型，也可将文件中的类别映射到本学院已有类型。未知类型先新建或更正映射，不因拼写差异自动创建，也不能默认为普通课。类型维护、组维护、成员维护、规则发布分别授权；拥有组编辑权不等于拥有学院类型维护权。

配置显示继承来源和学院可覆盖项。所有正式更新保留版本与操作人；学校课表发布后才成为个人课表更新提示的来源，内容没变不重复提示。

## 4. 微信小程序产品需求（不含开发实现）

### PR-11 个人课表初始化与查看

绑定后首次自动取得本人共同课程和正式选课的个人副本。只包含部分同学的选修不能导入全班所有人。

提供今日/周视图、周切换、课程详情、学期选择。已有内容始终读取个人保存结果，重复登录或绑定不重新覆盖；删空也是有效状态。新学期独立初始化，旧学期可查阅；转班转院提示来源变化，不重建本人当前课表。

未绑定、未分班、学校未发布、资料不完整和本周无课分别展示。跨作息课程按实际时间显示，不用本院节次号重新解释外院课程。

### PR-12 自主增删改

学生可添加选修和手动课程，编辑名称、教师、地点、周次、星期、时间和备注，可删除及恢复。支持整条规则或仅本次修改。编辑不审批，以最后成功保存为准。

编辑仅改变本人显示，不改变正式选课关系、排班冲突、受派、考勤或报表。课程重叠可以提示，但不因查课规则阻止学生保存。个人课表中不提供通过删除卡片取消正式任务的交互。

教务后续修改作息、教学周、日期或删除课程，都不能暗中移动/删除个人内容。多设备保存冲突时保留已保存内容并让学生选择重试；离线编辑建议不纳入首期，缓存查看显示更新时间。

### PR-13 站内教务更新提示

小程序首页/消息入口提供未读提示，展示变化课程、前后值、发布时间和生效日期。学生可查看、标为已读、忽略或主动采用；已读不意味着采用。

采用前预览哪些个人字段会改变，未选课程和个人新增内容保留。恢复整份学校课表先显示影响，提供恢复操作前内容的方式。多次更新合并提示避免刷屏；过期提示先刷新，不用旧内容覆盖最新个人修改。

提示基于本系统已收到且发布的教务资料，不承诺自动发现外部教务系统变化。内置提示不等于微信订阅推送，无需在此产品范围内承诺小程序关闭时通知送达。

### PR-14 小程序原有业务适配要求

本人受派任务、考勤和异议继续受服务端真实身份及资源范围保护；不新增跨院支援入口，任务仅展示本人合法受派所需信息。任务展示学院、组织、课程名称、实际时间和截止，避免混淆。

个人课表与正式业务入口分清。换绑、退出、换账号不能看到上一人的个人内容。小程序的页面实现、文件改造、开发工具操作和端侧测试方案不在本轮开发文档内；以上仅为产品验收要求。

## 6. 非功能与数据要求

历史可追溯、重复操作幂等、并发覆盖有明确冲突提示。姓名、名单、附件和私人内容按任务最小范围提供；隔离涵盖列表、计数、下载和批量操作。

正式流程中人工备注继续选填，不为新增业务恢复无必要必填。性能先以实际学院、班级、场次、人员和导出规模建立基准，不承诺未经压测的容量与响应时间。

产品文档采用学生/教师可理解的语言；页面不用暴露内部锁、数据库版本等细节，只提供可操作原因。

## 11. 角色工作流与落地顺序

### W01 新学院首次启用（PR-01—07/10）

1. 平台管理员创建管理员账号；管理员建立学院并创建绑定该学院的教师账号，教师进入本院工作区并拥有本院完整业务能力。
2. 管理员选择学期，核对开学基准、教学周和校历，配置并发布有效作息。
3. 建立行政班和学生底册，确认学籍；准备课程类型，按共同课程或正式选课录入教学班、名单和课表。
4. 预览正式课次，检查日期、实际时间、地点、人数和资料完整性；发布正式资料。
5. 新建志愿者组，设置负责人、有效期、类型/班级范围及冲突规则；录入成员与学期资格，明确谁仍未绑定。
6. 先用少量课次预览候选、冲突及抽查缺额，再生成与派发。志愿者看到本人任务，管理员核对结果。

首次准备页按上述项目显示“未配置、需核对、可使用”，提供对应页面入口。未满足必要数据时允许保存草稿和修正数据，不显示“已启用查课”。空名单、缺时间、未知学院或未发布组范围均不能用猜测值生成正式任务。

### W02 新学期接续（PR-04/06/10/11）

管理员可复制上学期作息、类型引用、组范围及规则作为待核对配置；班级、学生学籍、名单、成员有效期和学期资格必须重新确认。课程类型和组本身可跨学期沿用，不为每学期重复创建同名对象；历史配置与新学期资格区分。

复制不能复制旧任务、旧受派、提交、考勤、人工确认和个人课表。新学期正式发布后，学生可独立初始化该学期私人副本；不会重置旧学期个人内容。学期归档后保留查询/导出，停止新建课程和任务；确需处理归档前的补交或异议，应由有权管理员明确恢复可处理范围，不能通过切到别的学期规避限制。

### W03 每周选择、抽查、生成与派发（PR-05—08）

1. 选学院、学期、执行组、日期区间；显示组实际负责范围和配置更新时间。
2. 选择班级及组范围内的类型，查看可用课次；采用具体场次勾选或每班抽查数量。
3. 获取预览：选中课次、逐班抽查数量、已存在任务、缺资料、停课和范围外项分别列明。
4. 确认生成。页面显示新生成、已存在及需处理结果，并可打开此次任务批次。
5. 对本次生成结果中可排任务预览排班，展示候选人数、成功安排、未分配原因和须人工确认项。
6. 确认派发；缺人任务留在未分配列表，允许缩小批次、补成员、调整已获准规则或人工选择合格者。
7. 管理员核对全部结果，后续改派及取消仍针对明确任务，不因页面筛选改变而作用于全院。

抽查选课次与给任务找志愿者是两个步骤。不会因找不到志愿者就偷偷换一门课，也不会因派发失败删除生成结果；用户修改抽查条件需重新预览并明确生成新的选择。

### W04 志愿者执行与调班（PR-09/14）

志愿者打开本人任务，核对日期、实际时间、学院、组、地点和名单。需调班时提交申请；在改派真正成功前，页面继续展示实际受派关系和“申请处理中”。管理员可拒绝申请，或在同意后完成合法改派；同意申请本身不代表任务已经交接。

执行时选择全部正常或录入异常学生，按需上传材料，检查后提交。成功即形成正式考勤，显示提交时间及是否补交；历史原始提交不可被后续更正覆盖。管理员发现错误使用考勤更正，学生可对本人认定提异议。

### W05 学生异议处理（PR-09/14）

学生进入本人考勤详情 → 查看原认定 → 选择期望认定、可选说明与证明材料 → 提交 → 查询待审核/通过/驳回。管理者进入当前学院待审核列表，查看考勤事实、学生诉求及材料，一次作出决定。

通过需明确最终认定；驳回保持原认定。处理结果展示审核账号、时间、结论和可选意见。旧初核资料可查看，但不要求补做流程。原考勤已变更或已被另一人处理时，刷新并重新核对；不能把旧窗口的“通过”覆盖到最新记录。

### W06 个人课表使用（PR-11—13）

绑定有效学生 → 首次获取本人已发布课程副本 → 自主增删改 → 学校更新时仅收提示 → 比较变化 → 选择采用或忽略。私人新增选修及改动始终由本人维护，所有查课行为只读取正式资料。

### FD01 工作区与首页（PR-01/02）

工作概览只聚合当前授权范围内今日任务、未分配任务、待处理调班、异议和配置影响。每个数字都能打开相同范围的明细；没有该能力时不显示计数。未发布数据、没有任务和没有权限分开反馈，避免用空页面混淆原因。本期概览使用现有业务待办，不另建通用消息/审批中心。

| 身份绑定 | 经核验的学生身份与一次性绑定凭据 | 本人身份唯一，失败解释已使用/失效/资料不匹配，不展示他人绑定详情 |
| 任命负责人/配置功能 | 本院有效学生、本院任命、允许的功能开关 | 学院由本人学籍校验，不可输入外院；教师本身不做动作开关配置 |
| 撤权/停用/解绑 | 当前对象、影响预览 | 新操作失效；未来任务待处置，历史事实保留 |
| 管理员账号维护 | 管理员账号、状态、版本、口令重置及平台能力开关 | 仅持额外能力的管理员；不返回目标账号业务会话或原密码 |

教师固定拥有本院完整业务能力，学生负责人只在本院已启用功能内工作；组负责人只管本院组事务。平台管理是管理员的一项额外能力，沿用原业务权限；不能只隐藏按钮来保护账号操作。具备学生身份的管理者仍只能提本人异议，审核时须回避本人记录。

### FD03 学期、班级、学生与正式名单（PR-01/05/10）

行政班表示学生学籍所在班；教学班表示一门课程实际参加的学生集合。共同课程按明确行政班名单形成，选修按正式选课名单形成；合班课不能把某一个行政班等同于全部教学班。

学生底册至少确认稳定身份、学号、姓名、所属学院/专业/行政班、入学年份、当前就读年级、学籍状态及生效区间。原入学年份不随留级或换班改变。名单导入先校验重复学号、未知学生、学院不符、同名歧义和生效日期；无法确定时阻止相应正式发布。换班/转专业/转院走 PR-15 异动，不直接改当前班作为完整办理；身份、学籍、选课、账号和档案可见性分开，不能搬移或删除既有考勤。

名单修改前列出未来任务影响。尚未执行任务可明确更新名单并通知当前受派者；已有提交按提交时名单追溯，不用最新学生名单补造正常记录。只调整“应到总人数”不等于改名单，必须使用独立操作并展示两者差异。

### FD04 统一课程与课表录入（PR-04/05）

| 信息 | 是否必需 | 产品规则 |
| --- | --- | --- |
| 学院、学期 | 必需 | 从当前工作区带入，不能在同一录入表随意改归属 |
| 课程名称 | 必需 | 自由名称；“早自习”也是普通录入，不由名称决定权限或冲突 |
| 课程类型 | 必需 | 选本学院有效类型；同一教学班一致，改分类需影响预览 |
| 教学班及名单来源 | 必需 | 共同课程或正式选课；缺完整名单不得生成正式查课任务 |
| 教学周与星期/日期 | 必需 | 支持周次区间、明确周次及单双周；不落入学期有效日期的场次提示修正 |
| 作息及时间 | 必需 | 选有效方案时段或明确起止时间；结束晚于开始，按实际时间展示 |
| 教室/地点 | 可在草稿为空，生成前必需 | 无地点无法执行；不使用“待定”当已确认地点 |
| 任课教师 | 可选 | 自习无教师不阻止保存；教师信息不代替负责学院 |
| 备注 | 可选 | 用于补充执行信息，不承担分类或授权含义 |

课表提供周视图和列表，筛选学院、学期、班级、类型、教师、地点及日期。详情同时展示课程规则与某一天展开的实际课次；单次停课/调课和整条课表修改分别操作，不能通过改整条规则误移动所有周次。

保存前检查同一教学班重复场次及明显学生/教室时间重叠，展示冲突对象。教务确有重叠的，不由系统偷偷删除或合并，需有教学维护权者核对后发布；重复同一场次则必须消歧。体育等已有明确排除规则继续生效：不生成查课任务的课程，仍可能占用学生本人时间。

### FD05 作息、日历与调课（PR-04/10）

作息编辑展示名称、适用学院/对象、生效日期、时区和时段清单；每个时段包含名称、实际起止时间和顺序。可以直接录入 07:00–07:40、19:00–20:30 等自习时段，不要求塞进固定“第一大节”。管理员统筹时也按各学院实际场次时间计算。

草稿可修改；发布需确认未来影响，已发布版本通过新版本变更。两个同时适用且无法唯一解析的配置不能发布或生成任务。校历支持停课、补课及调休；学院例外与学校日历来源要展示，同层级冲突须解决，不能按最后一条数据随意覆盖。

改变已有未来课次时保留场次身份，显示原时间、新时间及需重验的受派；已发生场次不由新作息重写。停课进入任务取消/处置预览，恢复上课不自动恢复旧受派。正式发布会形成个人课表提示，私人卡片仍保留原显示。

### FD06 课程类型维护（PR-05/10）

列表展示名称、说明、颜色、顺序、状态、引用教学班数、关联组数及操作。搜索只查授权学院；详情可查看有权的关联对象，不能因引用计数泄露外院数据。

新建最少填名称，其他展示字段可选；去首尾空格后与本学院已有名称重名则拒绝并指向已有类型，停用类型也保留原名称占用。修改名称不改关联标识，改颜色不影响规则。类型不设置独立考勤状态机，也不自带“允许课程冲突”。

停用预览分别列教学班、组配置、未派和已派未来任务；页面明确“课表仍有效，新的查课安排受限”。有引用只显示停用，不提供可成功的删除操作。恢复后需核对组范围，不能自动把新类型加入其他组。

### FD07 组及成员维护（PR-06）

| 配置区 | 字段/操作 | 关键行为 |
| --- | --- | --- |
| 基本信息 | 名称、所属学院、负责人、有效期、状态 | 学院固定；草稿允许缺配置，启用前核对负责人和范围 |
| 成员 | 学生、多组关系、入退组时间、学期资格、启停及绑定状态 | 组成员、有效资格、登录身份分别呈现，不能将“在名单里”等同“可提交” |
| 查课范围 | 目标学院、明确类型、全部授权/指定班级 | 为空不能执行，新增类型不自动加入；只能引用本院类型/班级 |
| 冲突规则 | 本人课程默认及例外、本班回避、上限、缓冲、组织不可用 | 与查课范围分别编辑，一次发布明确生效配置 |

成员录入可搜索已有学生或导入底册，不为同一学生创建多个账号。重复导入同一有效成员给出“已存在”，不累计配额或重复受派。尚未绑定微信但已有可靠学生底册/资格的志愿者可参与排班准备；派发预览单列未绑定人数，明确未完成绑定不能实际登录提交。

首期组织请假/不可用由有权限管理者维护日期/实际时间，不新增多级请假审批。影响已派任务时列出改派清单。成员离组/停用后历史归属不变，未来任务按失效资格流程撤回或改派，不能保持无权执行却仍显示“已成功交接”。

### FD08 查课范围与候选课次（PR-05/06）

类型多选取并集，类型、班级、时间、授权条件取交集。选择“全部授权班级”会随有效授权范围变化；选择“指定班级”保存明确班级名单，新增班级不会加入。使用年级批量选择后展示实际班级，不以隐蔽表达式自动扩大范围。

一个多人合班场次只有一个任务；组仅负责其中部分班级时，不把全部合班名单放入候选，提示范围不完整。首期须完整覆盖负责班级，跨院合班按 D05 决定启用条件。

候选表最少显示日期、实际时间、课程/类型、教学班及行政班、地点、人数、可选状态和已有任务。不能选择的行显示可操作原因；已生成行提供已有任务入口。后续页面缩小过滤时，不保留隐藏行继续生成；批量确认前显示最终完整选择。

### FD09 冲突规则配置与解释（PR-07/08）

| 配置 | 推荐初始值 | 解释和限制 |
| --- | --- | --- |
| 本人正式课程冲突 | 禁止 | 可按类型放行或提醒，再按具体教学班覆盖；作用于本人课程 |
| 其他同时到场任务 | 禁止 | 查询各组及跨院受派；一人同时巡查多班待 D02，不由课程例外放宽 |
| 本班回避 | 禁止作为初始建议 | 组可依制度设为提醒/允许，但不开放自改考勤或自审 |
| 每日/每周次数上限 | 明确填写有限值或“不设上限” | 选择本组或全部组计数；周按自然周，不按当前筛选日期切割 |
| 移动缓冲 | 可配置非负分钟 | 不同地点接续任务考虑实际时间，不能用节次名称替代 |
| 组织不可用 | 禁止 | 先修正正式不可用记录，不从私人课表推断请假 |

规则界面给出示例试算，不改变真实受派。试算可解释“本人早自习允许，但另一门选修仍禁止”等组合。禁止项不能被一条允许规则整体吞掉；提醒项必须由具备确认能力的人对本次任务和人员确认，规则改变后旧确认失效。

资格、账号状态和学院授权属于身份边界，不提供“忽略”按钮。合格的未绑定学生底册可用于排班准备，但本人实际提交必须有有效绑定；这两条分别检查，不能把未绑定误作已完成登录验收。自动排班不会替管理员点击提醒确认，也不自动在候选的不同组之间选择最宽松规则。

### FD10 抽查及生成批次（PR-05/06/10）

手选按日期课次逐行勾选；随机模式明确班级和每班目标次数。系统先得到范围内可用集合，再抽取；预览显示计划次数、可选次数、选中次数和缺额。共享课次可计入涉及班级的要求，但任务不重复；完整配额无法满足时阻止这次确认，用户明确调整后再预览。

生成确认展示执行组、目标学院、日期、选中场次及总数。确认后不会重抽；重复点击和网络重试不能再次生成同轮任务。其他组已有同一课次任务时提示已有归属，管理员走换组/改派流程，不新建一份考勤来源。

任务详情保留生成时课程名称、类型、组、时间、名单和原始应到信息。资料或规则改变后出现“需重新核对”，不能在用户不知情时把旧任务换成另一门课。抽样本期不引入课程权重、评分模型或自动学习偏好。

### FD11 排班、人工改派、调班与取消（PR-06—09）

排班只处理明确勾选或本次生成返回的可派任务；页面显示目标数、成功数、未分配数。未分配原因至少能区分无有效成员、本人课程冲突、已有任务冲突、本班回避、日/周上限、范围无效和资料变化。一次失败原因不声称穷举了每位候选的所有冲突，也不声称求得全局最优。

公平以正式受派工作量为依据，并展示日/周计数口径；不会通过为已过期、未绑定或范围外成员扩大候选来凑数。人工指派、改派、换组、修改任务时间均重新检查相同规则；确认提示只处理可确认的提醒，不能放宽资格和禁止项。

调班申请列表展示申请人、实际任务、申请时间、可选原因、当前安排和处理结果。批准加改派可作为同一次明确操作，但成功必须以新受派真实落地为准；独立同意申请后仍待改派时保留待处理提示。改派后原执行者不能继续提交，原历史提交只读保留。

取消先显示受派、提交、正式考勤及报表影响。未执行且无事实任务可取消；已有事实任务不采用同一“删除任务”动作抹除记录，应进入有权更正流程。恢复仅对未开始、无执行事实且来源兼容的任务开放，恢复后未分配，需重新排班。原因选填，但操作人、时间和影响仍记录。

### FD12 查课提交、附件与考勤更正（PR-09/14）

志愿者仅查看本人当前受派及必要名单，正常提交不填写异常学生；异常提交至少一人，逐人选择请假、迟到或旷课，同一学生不能出现两种互斥认定。异常学生须在任务名单中；发现名单不对可反馈管理员，不能手工输入名单外学号制造考勤。

照片和说明按现有业务要求提供，备注选填；本版不额外引入“所有任务必须照片”的校级新规定。附件显示上传中、成功或失败，失败文件不得提交为已上传。提交前汇总异常人数及学生清单，成功自动形成名单内学生的正式认定；“全体正常”与“未提交”严格区分。

禁止查课日期之前提交；允许逾期补交，提示实际提交时间与原截止结果。新提交自动入账，不在新流程中再次要求管理员先审核全部正常记录。旧待审核提交保留管理处理入口，仅用于历史兼容，不创建新的双重认定。

有权限者可更正单个学生认定，展示原值、新值和历史；应到总人数调整独立进行，不能小于当前异常人数，不改变学生名单。提交、考勤更正和应到变更分别留痕，不反向修改原始志愿者提交。学生可查本人认定和变更来源。

### FD13 考勤异议一次审核（PR-09/14）

学生只能对本人正式记录在有效窗口内申请，选择期望认定，说明和证明按已有规则选填；同一考勤已有未完成异议时打开既有申请，不另建重复待办。超窗显示原因，不允许选他人记录。

管理列表分“全部审核、待审核、审核通过、审核驳回”，支持学院、日期、班级及本人有权范围内学生筛选和分页。详情展示课程/任务、原认定、诉求、证明、历史更正和旧初核信息；审核操作只有通过和驳回，不再显示初核按钮。

通过需选择最终认定，修改考勤须同时具备更正能力；驳回不改认定，意见选填。记录实际审核账号和时间。本人记录须回避；已经完成、考勤版本变化或权限被撤销时禁止旧窗口提交。不能靠勾选“忽略版本”强制覆盖。

审核通过是否改变考勤、是否导致报表需要新版本分别呈现，不用“已通过”暗示一定改判。历史初核但尚未最终处理的旧异议仍归待审核。首期不增加异议二次审批或无限重开已完成申请；后续复议制度另行讨论。

### FD14 统计、导出、材料访问与审计（PR-09/10）

| 指标/输出 | 明确口径 |
| --- | --- |
| 有效应到人次 | 当前范围内有正式有效考勤且未取消任务的应到数累计；同一学生多次上课计多个人次 |
| 正常出勤人次 | 当前有效 NORMAL 认定数量；请假、迟到、旷课分别统计 |
| 到课率 | 正常出勤人次 ÷ 有效应到人次；分母不可用显示“无法计算”，不是 0% 或 100% |
| 考勤异常率 | 请假＋迟到＋旷课人次之和 ÷ 有效应到人次；不能将其标成仅“旷课率” |
| 当前未完成 | 当前尚无正式有效提交的任务，与历史截止考核分开 |
| 截止时未执行 | 原截止考核事实；后来补交不能抹除 |
| 学院/校级汇总比例 | 累加分子与分母后计算，不简单平均各班百分比；同一任务去重 |
| 当前导出 | 按当前已授权筛选及当前事实生成，注明统计时间与口径 |
| 归档报表 | 固定历史版本，保留来源与生成时间；后续变化提示落后，不覆盖旧文件 |

页面以学院、学期、日期/周次、课程类型、课程、班级和本院执行组筛选，导出范围与页面预览一致。类型/组历史用任务当时快照，当前课程分类另标；不要把更名或调组解释成历史事实变化。

只改任务总应到、无法可靠推导班级分母时，班级比例显示不可用及剔除任务数，整体与班级口径差异有解释；不能均摊总人数或把缺数据当零。未经查课的课次不记全体缺勤。迟到折算、纪律处罚、绩效评分不在本版自行新增。

Word/Excel 导出需可辨认中文、完整表头、范围和统计口径；无数据也显示有效空结果，不生成假的零出勤结论。文件生成失败保留筛选供重试，旧版本下载不等于刷新当前统计。

附件限业务相关授权者读取，支持预览、访问失败提示与短期链接更新；链接不是永久共享地址。撤权后不再签发新链接，已签发链接存在短期剩余窗口，不能宣称即时撤销。未完成异议的引用材料不能被到期清理误删；学生明细和证明不提供无授权公开页。

审计至少可追溯学院、操作者、对象、动作、时间和变化；本期复用现有审计能力，不新增复杂审计产品。允许查看日志也不自动允许下载所有学生材料；对外共享产品示例和验收材料使用脱敏身份。

## 13. 微信小程序产品细则

本节仅定义用户入口、显示、操作及验收，不约定小程序文件结构、组件、技术接口或端侧实现任务。

### MP01 身份、首页与角色入口（PR-11/14）

学生首次登录先完成绑定；受限身份显示绑定指引，资料不匹配时保留本人输入并给出可联系管理者的说明。已经绑定但没有正式课表的学生仍可创建私人课程，不因学校未发布资料阻止本人使用。

首页入口建议为“我的课表、我的查课、我的考勤、我的异议、教务更新、个人信息”。查课入口按有效志愿者身份和本人受派显示；没有任务不是登录失败。兼任管理者不会在小程序自动取得其他学院明细，本轮不扩大成移动管理后台。

显示当前学期、最近数据时间及更新提示；退出、换绑或换账号后不再显示上一人的内容。组织任务与私人课表使用分开的卡片与动作，避免学生以为删私人卡片就能取消任务。

### MP02 私人初始化与缺失资料（PR-11）

| 场景 | 用户看到的内容 | 允许操作 |
| --- | --- | --- |
| 未绑定 | 绑定说明，无其他学生信息 | 完成本人绑定 |
| 学校尚未发布 | 暂无学校来源，可自行添加 | 手动建课，之后发布仅提示 |
| 部分正式选课缺失 | 已确认的共同课程/本人选课，明确资料不完整 | 自行补充或联系管理员，不能拉入全班选修并集 |
| 首次初始化成功 | 显示来源学期、资料时间及本人副本 | 后续自由增删改 |
| 已初始化但删空 | 显示空个人课表 | 添加、主动恢复；不自动再初始化 |
| 新学期 | 独立的初始化或手动创建入口 | 原学期保留查阅 |
| 转班转院 | 提示正式来源发生变化，个人显示保留 | 查看更新并主动采用 |

本人已手动创建的内容也视为已保存私人课表；后续有学校资料时提供比较/采用，不能把它当“从未初始化”整体覆盖。部分数据初始化后不会因重新登录自动补齐，后续增补走同一更新提示流程。

### MP03 今日/周视图与课程详情（PR-11/12）

今日视图按真实时间排序；周视图支持本周、上一周、下一周、指定周及回到今天。早自习、晚自习及外院课程可以在普通节次以外显示，不要求同一学院节次号对齐所有卡片。

卡片显示个人保存的课程名称、实际起止时间、地点，详情增加教师、重复周次、备注及来源标记。当前没有课显示“本日/本周无课”，缺学校数据显示“资料未发布/未完整”，不混为同一个错误。重叠课程均保留，可提示时间重叠，不隐藏后添加的课程。

私人显示可以保留本人修改的分类/颜色，但不因此改变正式课程类型；学校作息/日历更新后仍按个人已保存的日期和时刻显示。志愿者执行时间始终从正式任务入口读取，不能从私人课表推导。

### MP04 自主增删改、选修与单次修改（PR-12）

| 操作 | 用户提供的信息 | 保存与边界 |
| --- | --- | --- |
| 添加选修/手动课程 | 名称、星期/日期、周次、起止时间；地点/教师/备注可选 | 只新增私人卡片，不完成正式选课、不生成查课任务 |
| 编辑整条课程 | 明确“修改全部适用周次” | 影响该个人条目的规则，不改正式教务资料 |
| 仅改本次 | 选定原课次，改时间/地点/名称或取消本次 | 保留与原课次对应关系，其他周次不变 |
| 删除/恢复 | 明确整条或本次 | 删除不退课、不解除值勤；可恢复本人之前保存内容 |
| 重复课程 | 提示相近内容 | 用户确认后可保留不同私人课程，不按名称自动合并 |

保存必须满足有效日期、周次和起止时间，名称不能空；备注选填。课程时间与其他私人课程重叠只提示，不使用志愿者组的禁止规则阻止保存。取消编辑不改变已保存结果；提交失败保留表单，让用户修正或重试。

多人多设备冲突时以最后成功保存内容为准，旧页面不能无提示覆盖它。提示当前已变化，保留此次编辑供用户比较、刷新或重新提交；未保存/保存失败的操作不能显示为已经同步。首期离线只用于有更新时间的缓存查看，不承诺离线写入自动合并。

### MP05 教务更新、主动采用与整表恢复（PR-13）

教务更新入口显示未读数量和按课程合并的变化摘要，包含发布时间、生效时间、前后值、本人当前值以及来源新增/删除。消息说明“学校资料有更新，你的课表尚未改变”，不暗示必须采用。

用户可以标为已读、忽略、查看比较或选择采用。已读只消除未读状态；忽略保留私人内容，不屏蔽后续不同发布的新变化。采用按课程及变化字段明确选择，未选条目、私人新增课程和其他本人的修改保留；学校删除某课时，默认只是通知，只有本人选择采用删除才移除私人卡片。

整表恢复是单独入口，预览将替换/删除的内容，尤其私人新增和单次例外，并保存操作前副本供恢复。不会把整表恢复藏在“全部标为已读”中。恢复历史副本同样以成功保存后的内容为准，不倒改正式学校资料。

来源或私人数据在比较后又变化时，原预览不能继续采用，提示刷新比较。第一次采用成功后重复点击不重复加课。对单次例外有影响的更新必须明确展示其保留或替换结果，不能静默删掉本人改过的某一天。

教务提示仅来自本系统发布的正式资料；不做外部教务自动抓取，不承诺微信外推送和后台提醒送达。手动私人课程无正式来源，不凭同名绑定到另一门学校课程。

### MP06 本人任务、考勤与异议（PR-09/14）

本人任务列表按日期显示待执行、已完成、已逾期和已取消，另标受派是否有效、组和变更提示；历史待审核提交仅在确有旧记录时显示。详情包括正式时间、地点、名单、截止、受派组、提交状态及历史截止考核。

本人考勤按学期、日期和认定筛选，仅列有正式认定的记录；未被查课不能显示成“正常出勤”，缺任务也不能显示成旷课。详情提供认定历史、对应课程及可提出异议的入口。异议只显示本人待审核、通过、驳回，旧初核资料只读。

任务改派或权限失效后，已打开的旧页面不能继续提交，反馈“安排已变化，请刷新任务”；已保存的本人历史仍按允许范围读取。照片预览与证明材料权限失败时说明需重新申请访问，不让用户复制永久公开地址解决权限问题。

## 14. 业务状态与异常反馈

### 14.1 少状态、分维度显示

| 对象 | 状态/维度 | 允许的主要流转与限制 |
| --- | --- | --- |
| 学院 | 有效/停用/归档 | 新业务受启停限制，历史不删除 |
| 课程类型 | 启用/停用 | 引用保留；无引用才可删除，不自动切换关联教学班类型 |
| 志愿者组 | 草稿/启用/停用 | 启用要求有效配置；没有成员可保存，但没有候选可派 |
| 作息/组配置 | 草稿/已发布/归档 | 草稿可编辑，发布后通过新版本变更；指定日期生效是时间属性 |
| 正式课表资料 | 草稿/已发布 | 只有有效正式来源参与任务及更新提示，已完成事实不回写 |
| 任务当前状态 | 待执行/待审核/已完成/已逾期/已取消 | 已取消优先；有正式有效提交为已完成；待审核仅兼容旧提交；无有效提交且超过截止为已逾期 |
| 受派 | 未分配/有效受派/历史受派 | 与任务当前状态独立；“未分配”不是新任务状态 |
| 配置影响 | 待处理/已处理 | 作为辅助标记，不自动取消任务或删除受派；未派不符范围者禁止新派发 |
| 截止考核 | 未到期/截止时有效提交/截止时未执行/截止时已取消 | 到期结算形成历史事实，晚交不能覆盖；截止时刻相等仍按时 |
| 正式考勤 | 正常/请假/迟到/旷课 | 一人一任务一个当前认定，变更追加历史；无认定不等于正常 |
| 异议 | 待审核/通过/驳回 | 一次审核完成；初核不是新待办阶段，通过可以维持原认定 |
| 个人课表 | 未建立/已建立 | 删除全部条目仍已建立，不触发自动初始化 |
| 教务提示 | 阅读状态＋采用情况 | 未读/已读/忽略与是否采用分别表达，不用一个状态混淆两者 |

取消后的恢复只面向符合 FD11 条件的任务；历史更正是明确事实变更，不能通过停用类型/组或归档学院伪装完成。主列表可同时显示“已完成、补交、截止时未执行”，这些描述可以同时成立。

### 14.2 异常时提供可继续操作的反馈

| 情况 | 产品反馈 | 下一步 |
| --- | --- | --- |
| 无工作区权限/授权撤销 | 当前范围不可操作，不显示隐藏学院明细 | 回到可进入学院或联系授权者 |
| 资料不完整 | 缺少类型、名单、时间或地点，指出授权内对象 | 保存草稿，进入对应维护页补齐 |
| 抽查候选不足 | 每班目标、可用数和缺额 | 调整明确条件/数量，不能越过组范围 |
| 排班无候选/部分未分配 | 已生成任务保留，展示具体原因与未派列表 | 补成员/资格、明确改规则或合法人工改派 |
| 数据被他人修改 | 预览已过期；保留可用输入 | 刷新并重新预览，不自动重抽或强制覆盖 |
| 当前已受派者失效 | 本次提交/新派发不可进行 | 管理者处理原任务，不把历史删除 |
| 类型/组仍被引用 | 不能删除，展示引用及可用停用操作 | 停用并处理未来影响 |
| 上传失败或链接过期 | 材料尚未就绪/访问已过期 | 保留表单，重传或重新获取有权访问链接 |
| 网络中断结果未知 | 显示正在核对结果，避免连续新建 | 查询原操作结果，重试同一操作不重复入账 |
| 异议已处理/考勤已变 | 展示最新已授权结果 | 刷新核对，不再次覆盖；需更正走有权流程 |
| 无统计分母/无数据 | 无法计算及原因，或明确空结果 | 查看缺数据/剔除任务明细，不展示假的比例 |
| 个人保存或采用冲突 | 最新内容未覆盖，本次编辑仍可查看 | 比较后重新保存/采用 |

页面提示中文业务原因，不显示数据库锁或堆栈。所有批量写操作在确认前展示明确目标；默认不允许一批混入无权对象，失败不能显示整批成功。完成反馈区分成功、已存在、未完成及需处理数量。

## 15. 完整场景验收与交付证据

验收使用脱敏数据，不以真实学生名单作为共享样例。以下用例不增加新制度，只串联前文已有需求；名称、时间、人数均为示例。

| 场景 | 操作与预期 | 关联 |
| --- | --- | --- |
| T01 两院隔离与不同作息 | A/B 学院同名“第一节”分别 08:00/08:30；A 教师不能读写 B，管理员/平台管理员可统筹；展示和冲突按实际时间 | AC01/02/04/11 |
| T02 早自习查课 | A 学院建“早自习”类型、两个大一班 07:00–07:40，混入普通课和晚自习；组只选早自习，本人同类型重叠允许；随机只抽早自习，其他课程重叠仍阻止 | AC08/20/25 |
| T03 新类型和多组 | 新建“集中训练”类型及负责组，同人加入早自习/训练组；新类型不自动进入旧组，跨组任务重叠不能派，不重复账号或任务 | AC07/19/21/24 |
| T04 变更与历史 | 生成并派发后，更名类型、改教学班分类或停用组；旧预览失效，未来影响可处理，历史任务名称/分类及提交不被覆盖 | AC22/23/28/29 |
| T05 生成成功但排班失败 | 可查课次足够但志愿者都忙；保留生成任务及缺人原因；补入合格成员重新排班，不重复生成 | AC06/30 |
| T06 调班与失效身份 | 调班同意后故意选冲突人员，改派失败不假显示交接；再选合法人员完成，新旧执行权限正确；撤权/退组不删除历史 | AC03/31 |
| T07 正式认定与补交 | 正常和异常分别提交，名单外学生被拒；两次点击不重复入账；逾期补交可完成，但仍显示原截止时未执行；私人课表删除不改变结果 | AC10/16/32 |
| T08 单次异议审核 | 学生诉求改认定；具备审核和更正能力者一次处理，驳回不改考勤；另一人先更正时旧窗口不能覆盖；历史含实际账号/时间，本人自审被拒 | AC09/33 |
| T09 统计与材料 | 人工只改任务总应到后，班级分母不能可靠推导；比例不可用有解释；更正后当前导出更新，旧归档可读且提示落后；过期材料不变公开 | AC34/35/39 |
| T10 私人副本完整流程 | 同班两人正式选修不同，只导入各自课程；本人改时间/新增选修/删空，重复登录不覆盖；学校调课仅提示；已读不采用，选采用不动未选内容 | AC12—17/36/37 |
| T11 异常与并发 | 两人同时改配置、两设备保存、切学院后旧响应返回、上传失败及结果未知重试；明确失败/过期原因，输入可恢复，不串范围和重复写入 | AC26/35/38 |

产品验收记录应包含所用角色及授权范围、前置数据、实际操作、预期/实际结果、必要截图、当前版本和未验证项。界面按钮可见不能证明权限，静态文档不能证明流程已跑通；后端/Web 与小程序分别记录已交付、待开发、待适配。

首期交付必须覆盖 C01—05、C07—15 和 AC01—54；编号 C06 已并入 C05，不重复要求独立模块。业务决策按第 10 节各自已确认/暂定/待确认状态执行，未确认的制度不静默定案。小程序产品用例定义完整，并不在本轮授权内开始端侧开发。

建议试点先覆盖两个学院、不同作息、早/晚自习和普通课、一个自定义类型、同人多组、管理员办理转院及一次名单/配置变更；用最小完整场景验证结果，再扩大到全校。业务正确性、缺额解释、权限隔离和私人副本独立是交付条件，容量和节省时间需在试点后测量，不先写未经验证的收益比例。

## 16. 学籍与教师数据流转补充

### PR-15 学籍异动、名单对账与分类归档

详细现状、老师操作流程、导入导出约定和 24 类行政场景见[学籍异动与行政场景分析](ACADEMIC_LIFECYCLE_ANALYSIS.md)。本节形成正式产品要求；D10/D12/D13 已确认、D11 暂定 10 年。保持最小可解释流程，不增加通用教务系统和多级审批引擎。

| 功能 | 入口与最小操作 | 必须保证 |
| --- | --- | --- |
| 当前/历史学生档案 | 当前在籍列表、历史/归档列表、同一身份详情 | 可按日期看学院/专业/班级，历史不按当前班搬移；与账号禁用分开 |
| 专业及班级维护 | 稳定代码、名称、学院、有效期；更名或重组分别办理 | 新名字不另建身份；合并/拆班按时间与目标核验，不整体改文本抹历史 |
| 单人学籍异动 | 选学生→旧新归属/状态→生效日期→影响预览→有权确认 | 登记与生效区分，转班/转院不新建学生或默认换绑 |
| 批量异动 | 专用异动模板，逐人显示旧新值、日期及影响 | 同人矛盾、旧学籍不符、身份不明或权限不足阻止正式办理 |
| 普通学生导入 | 默认增量，核对普通字段，异动另列候选 | 不自动跨院迁移、不把停用者激活、不根据缺行删除或推定离校 |
| 完整名单对账 | 明确学院/班、截至日、完整性及差异清单 | 缺行只成待核对项；与正式教学班名单替换、毕业清单分开 |
| ZIP/整包资料 | 统一解析依赖、差异预览，再按明确批次确认 | 同一学生多个目标先消歧；不假称逐文件提交为整包原子 |
| 课程/任务交接 | 退出、保留、新增课程及生效区间；名单变化与受派影响 | 选修/补修不一刀切；未来未执行任务明确更新，已发生事实保持 |
| 资格/权限/异议交接 | 原组资格和负责人任命结束、受派与未结事项交接 | 旧权不自动延续或复制，原院教师/管理员处理旧事实，不提供跨院支援 |
| 学生导出 | 当前清单、异动交接、历史归档、考勤报告分别导出 | 用途、截至日、稳定代码和版本清楚；普通清单不含绑定凭据 |
| 毕业/休学/离校归档 | 选明确人员、日期、状态→影响预览→办理 | 归档不删人、不删任务、不重置学期；本人访问按校规单独处理 |
| 撤销/更正/复学 | 未生效取消；已生效反向事件或有权更正；新有效资格 | 中间历史保留，旧受派/管理权限不自动重放 |

“生效日期”首期精确到学校当地日期零点，涉及课次的判断采用其实际发生日期。学籍归属与正式选课分别建模：转院仍可保留已核验的外院课程，不因新学院默认课表而漏掉本人课程冲突。

未来任务名单更新必须同时展示增减学生、名单版本及应到变化，已派任务让受派者看到新名单并刷新旧提交页。已开始、已提交或已形成截止考核的任务不自动改名单；晚到资料和错误历史走明确更正，报表变化有来源记录。私人课表只提示来源变化。

权限按对象和日期处理：原院老师可按已授权范围追溯旧事实，不因此能修改转入新院后的当前学籍；新院老师管理当前学籍，不自动获得旧院全部材料。本院异动由本院教师或管理员办理，跨院转专业由管理员统筹，不配置教师跨院授权。转专业学号不变，老师不需要为该流程生成第二份学生身份。

归档用状态和可见目录保留历史，与登录、绑定、志愿者资格、教师/负责人授权分别处理。现有停用解绑可用于明确的身份停用，不能默认替代所有休学、毕业和跨院操作。档案导出也不能作为删除原数据的理由。

补充试点场景：同一人未来日期转院且保留一门旧课，转出时有已派任务和待审异议；完整名单缺一人但未被判退学；已停用者出现在旧文件不被激活；毕业后依法定校方策略保留本人历史；旧清单回导不改变新学籍。分别记录老师差异预览、任务/权限处置、历史报告与私人提示结果，对应 AC40—49。
