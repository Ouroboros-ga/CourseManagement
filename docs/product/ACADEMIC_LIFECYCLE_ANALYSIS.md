# 学籍异动、名单流转与行政教学场景分析

## 2026-10-14 实施边界

本次已实现固定教师学院、学生负责人当前学籍学院及功能开关、管理员全校统筹、显式平台管理能力，以及后端/Web 的学籍异动和学生数据交接。平台管理员沿用 SUPER_ADMIN，只增加 `administrator_account.manage`，不新增角色或登录入口。普通教师不能办理跨院异动，跨院由管理员办理。

正式学籍以生效区间解析，支持转班/转专业/转院、休学、复学、毕业、退学、未来计划撤销和明确的过去日期纠错。学号、学生 ID 和微信绑定保持稳定；过去纠错保留后续区间，不自动重写历史考勤。离校本人历史访问暂定十个日历年，归档不等于物理删除。

老师通过“学生交接与学籍”导出可回导的 XLSX，上传单文件或平铺 ZIP，预览新增/字段更新/异动/错误/缺失项，确认时重新核验权限、学生版本和行政班归属版本。全量对比的缺失项只提示核查；不会自动删人、归档或恢复学籍。每批只刷新一次受影响的未来正式任务名单。已开始、有提交或已有截止事实的任务保留原快照；无法确定来源或人工人数口径的任务进入待核定队列。

学校初始化名称为“绍兴理工学院”；正式学院为“人工智能学院（低空技术与工程学院）”，软件学院保留为“软件学院（测试）”。原软件学院两个班级及其学生、账号、业务历史全部保留。测试学院目前是独立学院工作区，未实现全校汇总自动排除测试数据；历史学校报表仍保留原内容。

**仍属规划：**学院独立作息/日历及实际时间排班、动态课程类型与志愿者组规则接入抽查/排班、小程序个人课表。已有类型/组配置表不等于上述业务已接入；本轮没有小程序新功能开发。无法可靠核定的存量课程、任务、批次和报表由管理员继续核定，不根据当前学生成员猜测历史归属。

实现、验收和部署边界见 [本次交付记录](../development/ENROLLMENT_IMPLEMENTATION_ACCEPTANCE_20261014.md)。其余章节保留完整设计目标，不能将规划验收项全部视为本次已通过。


版本：2.0 · 日期：2026-10-14 · 类型：现状核对＋产品补充方案，未实施。

最新决定：教师固定拥有唯一所属学院完整业务权限，学生负责人仅在本人学院工作；管理员统筹全校及跨院学籍办理。在现有管理员上增加管理员账号管理能力即可作为平台管理者，沿用业务访问，不新增角色或独立平台隔离。取消普通跨院授权/志愿者支援；转专业不换学号，离校历史暂定 10 年，日期补录/纠错按范围办理且不自动重写事实。

关联：[系统功能产品文档](CAMPUS_MANAGEMENT_PRD.md)、[后端与 Web 设计](../development/CAMPUS_BACKEND_WEB_DESIGN.md)。本文分析老师实际办理转专业、转院、转班、导入、导出和归档的行为；不代表已实现学籍管理，也不替学校决定学籍制度。

本次静态基线为 `dev-main / efa62b5`，含工作区既有未提交变更。运行复核仅使用 SQLite 内存数据库、虚构学生及实际行政班名单导入方法；未连接业务数据库，未执行线上变更，未核验真实 Excel 全流程或 MySQL 并发。

## 1. 结论与设计缺口

当前系统能更新当前班级、按学号匹配学生、保留任务名单快照，也有学生停用和删除保护；**还没有完整的、按生效日期办理的学籍异动及老师数据交接流程**。原产品文档对“转院不搬历史”的原则已覆盖，但专业、批量异动、来源截止日、导出用途、在籍状态与归档、旧异议接管等缺乏明确规则。

必须分清四件事：学生是谁、在某日期属于哪里、某日期实际参加哪些课程、某个历史任务归谁负责。它们不能用“当前班级”一个字段同时表达。转班一般保留学生身份和微信绑定；归档是保留档案并停止相应新业务，不能通过删除或全学期重置完成。

### 2.1 本次运行复核

在 SQLite 内存中建立 A/B 两班、一名 A 班停用学生、另一名未导入的 A 班有效学生，以及前者的旧教学班成员关系。调用当前 `_apply_admin_roster` 将第一人导入 B 班：

- 学生 ID 保持不变，当前班改成 B，转班计数为 1。
- 原停用状态变为 ACTIVE。
- 未导入的另一学生仍有效、仍在 A 班。
- 转班者的旧教学班关系仍存在。

四项都经断言核对；这是局部方法行为证据，不证明完整 HTTP 权限、MySQL 锁、微信身份或真实文件联调。转出者继续出现在旧课名单/冲突中是可以由这些关系推导的风险，未在本轮执行真实排班端到端验证。

本地复现脚本为 `tmp/analysis-student-lifecycle-20261014/reproduce.py`，结果在同目录 `result.json`；仓库根可用 `backend/.venv/Scripts/python.exe tmp/analysis-student-lifecycle-20261014/reproduce.py` 重跑。脚本生成的测试密钥仅在子进程内使用，不输出或保存；SQLite 仅内存，证据目录按现有规则不提交。

## 3. 推荐的最小业务模型

| 层次 | 保存什么 | 变更原则 |
| --- | --- | --- |
| 永久学生身份 | 稳定学生 ID、当前姓名及已核验学号/来源标识 | 转专业不换学号；转班/转院不新建人、不重新绑定微信，身份录错另行核验更正 |
| 学籍归属 | 学院、专业、行政班、学籍状态、生效起止日期、来源批次 | 按日期查归属；不能重写整个人的过去 |
| 正式课程参加关系 | 教学班、学生、参加起止日期、共同课/正式选课/补修来源 | 转班不等于全部退选/全部重新选课；根据经核对的课程清单生效 |
| 历史事实 | 任务负责学院、学生当时学院/专业/班级快照、名单版本及考勤版本 | 历史归原发生范围；本人仍是同一学生，历史报告不按当前归属搬家 |
| 账号、资格与授权 | 微信绑定、组成员、学期资格、管理授权和有效期 | 根据异动影响复核，不能随新班导入自动复制全部旧权限 |
| 档案可见性 | 当前在籍、历史/归档目录、本人历史访问策略 | 离校生效日起历史保存/本人查询暂定 10 年；归档不等于删除，异议和管理员授权期限独立 |

专业至少有学院内稳定代码和名称；专业更名保留身份，真正合并/拆分建立新归属并保留关系。入学年份和当前就读年级分开，留级/复学不能用改班级年级字段抹掉原入学年份。

首期按生效日期零点处理，不引入日内多次学籍流转。允许先登记未来变更：生效前仍按旧学籍与课程，生效日起按新关系；**今天的办理时间不等于业务生效时间**。过去日期补录指今天登记早已实际生效的异动，纠正指修改此前误录的生效日；教师及管理员按范围先预览历史影响，不静默回写名单、考勤和归档报告，不增加专项角色。

## 4. 老师如何办理转专业/转班/转院

### 4.1 单人异动

1. 搜索当前学生，显示稳定身份、原学院/专业/班级和最近一次变更；不按同名学生猜身份。
2. 选择转班/转专业/转院/学籍状态变化、目标和生效日期，可附来源编号和选填说明。目标班级、专业及学院关系必须一致。
3. 预览旧新归属、正式课程退出/新增/保留、未来任务名单、本人受派、组资格、管理权限和未结异议。
4. 共同课按新班关系提出变化；已核验选修、补修和需继续旧课程不能自动退掉，列出供老师确认。没有目标名单/课表时显示“课程待确认”，不伪造零课程或全体缺勤。
5. 本院变更由本院教师或管理员确认一次，保存学籍事件和生效安排；跨院转专业由管理员办理。教师的名单导入不能搬走或接收另一学院学生。
6. 展示办理结果、生效日期与待处理影响。仅登记待生效不能显示“已转入”；生效后可查询新归属和历史。

采用单次办理及明确交接记录，不增加两院多级审批或临时跨院授权。跨院资料交管理员统筹，新院可准备草稿，不能另建同名/同学号学生绕过。

### 4.2 日期前后的业务处理

例如同一学生 10 月 14 日登记，10 月 20 日转入 B 院新班：

| 对象 | 10 月 20 日前 | 10 月 20 日起 |
| --- | --- | --- |
| 当前底册与搜索 | 仍显示 A 院在籍，标将于 20 日转出 | B 院当前在籍；A 院显示历史/已转出档案 |
| 正式课程 | 旧日期按旧课程；保留未来已登记安排供计算 | 按确认的新课程关系，保留选修/补修例外 |
| 已生成但未执行任务名单 | 日期在 20 日前仍旧名单 | 相关任务标需核对，明确更新名单和应到，不双算转出/转入 |
| 已开始/已有提交或考核事实 | 使用原名单版本，不隐式改动 | 仍保护原事实；确有错录走专项更正 |
| 本人志愿者任务 | 原安排是否仍合法按其发生日期核对 | 原组资格和负责人旧院任命不延续；管理员处置受派，新院重新核验成员/任命，不支持跨院支援 |
| 旧考勤和旧异议 | 归原任务和原事实学院处理 | 不搬到 B；学生可见本人历史，B 不自动看 A 全部明细 |
| 私人课表 | 显示本人最后保存 | 仅提示正式来源变化，任何卡片不自动覆盖 |

任务已派但未开始可由有权老师确认新名单，再让当前受派者看到变更；名单版本变化使旧提交页失效。系统同时说明人数变化与具体增减学生，不能只更新一个“应到人数”。

跨院后未结异议仍由原事实学院/明确接管者处理。原学院归档或审核人离岗时，由管理员统筹或交本院其他教师接管；不把学生转院等同于把原学院全量权限授给新学院。按本人历史和按管理员当前范围查询是两种权限。

## 5. 老师导入数据：不能一份 Excel 决定所有事实

### 5.1 三种明确用途

| 导入方式 | 正常用途 | 缺行/冲突怎么处理 |
| --- | --- | --- |
| 增量建档/资料更新（默认） | 新增学生、核对普通资料 | 缺行不归档；跨班/跨院、停用变有效、姓名明显不符列异动/身份差异，不能顺带生效 |
| 指定范围完整名单对比 | 本学院某班/某学期的完整在籍清单对账 | 明确来源日期和完整性声明；缺行形成待核对移出候选，不能推定退学/毕业或删除 |
| 学籍异动清单 | 多人明确转班/转院、休复学、毕业等办理 | 每行明确旧目标、新目标、变更类型和生效日期，逐项影响预览；权限不足项拒绝正式办理 |

“教学班名单替换”是另一项正式课程参加变更，不能直接拿它办理全校学籍变化。学生信息更正也不能默认同步微信实名绑定、管理员角色或旧任务姓名。

### 5.2 上传到确认的操作

上传时选择用途、学院/班级、学期、来源系统/批次、资料截至日期、生效日期和模板版本。自动识别格式只用于帮助填表，老师确认目标；文件名、班名和模糊匹配不能决定归属。

预览分组展示：新增、普通更新、完全相同、学籍异动候选、停用/复学候选、完整名单缺失候选、身份冲突、未知代码及错误。每行展示旧值/新值/来源行号和将影响的范围；“有转班人数”一个计数不能替代核对。能下载差异清单，修正后重新预览。

身份以学校内稳定标识和经核验学号匹配；转专业不换学号。Excel 学号应为文本，前导零、长数字转科学计数法、丢失位数要报错，不能补猜。相同学号不同姓名、转专业文件却出现新学号、文件内同学号归两个班列身份/归属冲突，不取第一条或最后一条自动覆盖，其他身份资料录错通过独立核验更正。

确认以本次预览为准。上传后学生已转班、来源旧名单晚到、相关授权变化或重复数据已新增时，旧预览失效；必须重新比较。普通资料空格/空列默认表示“不改”，清除已有值要明确选择；不能用空学院列清除已核验学籍。

重复导入同一确认批次只回看结果，不二次执行。相同文件重新上传也不追加重复课表和重复异动；已被较新有效资料覆盖的旧名单提示过时。来源截至日期不等于可信授权，导入者仍需核验。

### 5.3 整包与部分失败

首期建议 ZIP/多文件先统一解析、建立依赖及差异预览，再由老师确认一个明确范围的批次；默认批次原子生效，发现两个文件对同一学生给出不同班级则先解决矛盾。某班缺名单时不继续用旧名单“成功”发布新课表。

当前整包逐文件提交是现状，迁移前应在 UI 明示已成功文件和失败文件，不称整体原子；修复期间重试只针对明确失败项，并防止已成功课表再追加。正式支持部分成功时必须在操作前声明粒度、独立结果和恢复方式，不能半完成后只弹一句失败。

## 6. 老师导出、交接和回导

| 导出类别 | 目的与内容 | 回导边界 |
| --- | --- | --- |
| 当前学生管理清单 | 某截至日、已授权学院/班级在籍档案；学号、当前姓名、稳定组织代码、状态 | 提供单独可回导模板和基线，非任意报表都可覆盖学生表 |
| 学籍异动/交接清单 | 旧新归属、生效日期、办理结果、待处理课程/任务/权限、批次来源 | 供核对和办理，重复回导不重复执行，接收者权限仍需检查 |
| 历史/归档档案 | 曾属本院学生、历史归属与允许范围内事实 | 历史查看用途，不能普通回导重新激活 |
| 考勤/统计报告 | 事实时点所属学院/班级、任务、当前认定或固定归档版本 | 不是学生底册同步源，不因 Excel 修改而改变考勤 |
| 绑定码清单 | 一次性绑定办理 | 单独受控，普通学生清单不夹带绑定码、token 或其他身份凭据 |

每份导出至少注明用途、筛选范围、资料截至日、导出时间、模板/口径和批次基线。表内稳定代码作为匹配依据，名称用于老师阅读；学校/专业更名不导致另建对象。学号和代码使用文本单元格，保护前导零及大数字。

老师把系统清单改好再导入时，只能改模板明确可写列。旧清单不得把后来转院的人改回；行版本/预览基线过期须拒绝。学生改名可以更新当前资料，历史报告保留当时姓名并按权限标注当前身份关联，不重写已归档文件。

在 A 院能导出历史的老师，不因此能修改现属 B 院的学籍；B 院能管理当前学生，不因此能下载 A 院所有历史证据。跨院交接只含明确必要字段及事项。

## 7. 归档、停用与删除必须分开

毕业、退学、休学、转出校外是学籍事件；在籍/休学/毕业/离校是学籍状态；账号是否可登录、志愿者资格和档案是否在默认列表展示是不同维度。

归档前预览人员、有效日期、未执行受派、未结异议、课程参加和必要权限。归档后的处理建议：停止不再合法的排班/新学籍写入，保留稳定身份与微信关联，关闭到期组资格/管理授权；离校历史保存及本人查询暂定从离校生效日起 10 年，异议继续按独立窗口处理，管理员按当前授权访问。休学不自动开始永久离校的十年倒计时，附件期限另行明确。不能调用现有“一刀切停用解绑”来完成所有毕业/休学场景，也不在十年到期时自动删除有未结事项的历史。

休学结束后办理复学，恢复的是新有效区间及核验后的课程/资格；不重放旧受派、不自动恢复旧管理权，也不重建私人课表。退学误录或错误归档更正需展示后续影响，不能用上传旧名单激活代替。

物理删除仅用于经核对、无正式引用的误建档案；有历史名单、考勤、绑定/身份关系或归档事实时不删。归档导出不是数据库备份，也不是“导出后可以删原数据”；学期重置、删任务不属于毕业清理动作。

## 8. 还需要覆盖的真实场景

| 场景 | 容易遗漏的细节 | 推荐处理 |
| --- | --- | --- |
| 转专业文件出现新学号 | 已确认不换号，却可能因旧号/错号被当新学生 | 按原学号保留同一身份，矛盾进核对；身份录错另行更正，不靠姓名合并 |
| 改名/录错名字、同名学生 | 历史与当前显示混淆 | 当前更正＋原快照，匹配按稳定身份 |
| 留级、跳级、复学 | 入学年份与当前年级混成一个值 | 原入学年份保留，按有效学籍表示就读年级 |
| 休学、交换、实习 | 不再参加某些课被算旷课，或一停用失去全部历史 | 有效学籍状态＋正式课程参与区间，资格和历史访问分别处理 |
| 延毕或部分课程重修 | 毕业批次一键归档仍上课的人 | 毕业清单逐项核对，重修/延毕名单不按入学年机械结束 |
| 转专业继续旧课/公共选修 | 清空旧教学班造成课程遗漏 | 明确保留/退出/新加入，不按院籍一刀切 |
| 新学期班级改名/重号 | 名称匹配错对象，旧报表被改写 | 稳定代码＋学院/时间；同名不等于同班 |
| 专业更名、拆分、合并 | 全体历史看起来被转院/转专业 | 更名与真实组织重组分开，保留旧组织归属 |
| 班级合并/拆班、学院合并 | 整个班直接改 college 字符串，全部学生瞬移 | 批量有效区间变化，课程/任务/负责人和授权影响预览 |
| 新生预录、报到未到、撤销录取 | 未确认名单提前成为正式应到 | 待核验建档不自动生成完整正式选课和考勤 |
| 借读、交换学生、跨院合班 | 当前行政班不足以表示真实上课名单 | 明确参与关系、一个场次事实来源及管理员明确负责来源，普通账号不开放外院访问 |
| 学籍中断后再入学 | 误把旧号复用给别人或误合并身份 | 人工核验同一人，身份标识不可随意复用 |
| 学生转院时是组负责人/管理者 | 旧院负责人任命继续有效，或原任务无人处置 | 旧院负责人任命失效，新院重新任命，原受派由管理员处置；不复制权限 |
| 有待处理异议时毕业/转出 | 学生消失、旧审核人离职，流程无人接管 | 保留事项和处理窗口，校级明确接管者 |
| 教师/辅导员离岗交接 | 班级文字老师名改了但账号授权还在 | 联系信息和授权分别变更，交接开放事项 |
| 本周名单更新晚于已查课 | 今天名单覆盖昨天事实 | 按发生日的有效名单/快照，晚到资料走有权更正 |
| 老师导入上学期导出表 | 无意将转出、毕业、停用者重新激活 | 源截止日/版本比较，普通更新不变更学籍状态 |
| ZIP 同时含新旧两份名单 | 文件顺序决定最后归属 | 全包检测矛盾并阻止，不能按处理顺序取胜 |
| 半份名单/筛选导出当全量 | 未导出的学生被清空/归档 | 明确范围和完整性声明，缺行只作为核对候选 |
| Excel 前导零、长号、空列 | 身份串号，空值擦除真实数据 | 文本模板、损坏拒绝、空值不改与清除动作分开 |
| 重导课表/导入后失败再点一次 | 重复课表、重复任务、重复生效 | 源行指纹和批次幂等、明确成功粒度 |
| 退选在查课当天生效 | 已开始任务名单和新选课冲突 | 首期日级生效，已有事实保持，晚到更正另处理 |
| 错误转班撤销 | 简单改回导致中间发生事实丢失 | 生效前取消；生效后反向事件或有权更正，保留中间历史 |
| 归档学院无人管理 | 旧报告/材料/异议失去负责者 | 学院归档交接明确管理授权，不删除资源 |

## 9. 建议优先级与尚需学校确定的制度

P0：多学院开放前补稳定学籍/课程参与区间、固定角色和学院边界；禁止普通名单自动转院或重新激活；历史快照补稳定组织标识。此处 P0 是实施优先级，不宣称本次已评估线上事故等级。

P1：老师单人/批量异动向导、完整名单对比、整包统一预览、未来任务与授权影响清单、用途明确的学生导出和归档。

P2：组织重组批次、更完整的交接清单及大规模生效处理。转专业不换学号，不因此增加旧新学号转换子系统；异常身份资料仍需人工核验，禁止另建学生绕过。

已确认教师办理本院变更、管理员统筹跨院变更；平台管理复用管理员并加账号管理能力，不要求业务访问隔离。转专业学号不变、历史期限暂定 10 年；日期补录/纠错按范围办理且不自动改写事实。附件期限及到期处置仍需明确，十年历史查询不延长异议窗口。

完成标准：同一学生身份不断链；按日期能解释所属学院/专业/班级及课程；老师能看见每次导入到底会改变什么；文件缺行不造离校事实；转院后任务、资格、权限、异议有负责者；当前清单与历史报告口径清楚；归档保留可追溯记录且不靠删任务。
