# 小程序交接：查课任务异常（后端已上线，小程序待接入）

## 志愿者流程

在本人当前受派任务详情增加“上报异常”。用于临时换教室、停课、现场无人等无法正常查课场景，统一为“异常”。弹出确认，说明选填（最长512字）；说明“上报后立即记为异常，不计正常完成，也不生成学生考勤”。本轮无需另建异常统计页面，也无需管理员审核。

```http
POST /api/v1/inspection-tasks/{task_id}/exception
Authorization: Bearer <access_token>
Content-Type: application/json

{"lock_version": 0, "reason": "老师临时换教室，现场无人"}
```

返回标准 `data/requestId` 包装，`data` 是最新任务视图：

```json
{
  "id": "9007199254740993",
  "status": "异常",
  "lock_version": 1,
  "exception_reported_at": "2026-10-23T01:00:00",
  "exception_reported_by": "9007199254740995",
  "exception_reporter_name": "张同学",
  "exception_reason": "老师临时换教室，现场无人"
}
```

示例省略原有任务字段；任务ID/用户ID始终使用字符串。时间为UTC，兼容现有API无偏移时间，展示按北京时间转换一次。本人任务列表和任务详情均返回上述四个异常字段，`status` 新增中文“异常”。不要将其映射成已完成、已取消或逾期；隐藏正常提交、新调班等动作，刷新任务显示。请求过程中禁用重复点击，提交成功后刷新本人列表及详情。

沿用 `submission.create` 权限；服务端仍验证账号、志愿者角色、学籍资格、当前受派和任务状态。无需新登录或角色接口。已有提交或考勤（含撤回/驳回）不能改成异常；归档学期、取消/删除任务、未来日期任务均不接受上报。

## 错误处理

- 401：沿用现有刷新凭证与至多一次重试，不无限重放写操作。
- 403：当前账号/受派/资格不满足，刷新本人任务，不借用其他账号提交。
- 404：任务不存在或已删除，刷新列表。
- 409 `VERSION_CONFLICT`：刷新任务版本，让用户重新核对后确认，不自动换成新版再次上报。
- 409 `STATE_CONFLICT`：已异常、已提交或学期状态不允许，展示服务端提示并刷新。
- 422：未来任务日期或请求格式不合法，显示具体错误。
- 超时或网络中断：先重新查询任务判断上次是否成功；不因为超时本地改为正常完成或直接重复提交。

## 管理员恢复及教工查询

Web任务详情显示说明并提供“恢复查课”。恢复采用：
`POST /api/v1/colleges/{cid}/inspection-tasks/{task_id}/exception/clear`
（管理兼容路径为 `/api/v1/inspection-tasks/{task_id}/exception/clear`），请求仍为 `lock_version/reason`。需要本任务学院 `inspection.cancel` 权限，志愿者不能自行恢复。

恢复后异常字段清空，版本递增；当前态按截止时间重算，历史上报及截止考核不会删除。小程序刷新后应恢复相应按钮，不能一直依赖本地缓存隐藏。

教工 `GET /api/v1/me/inspection-records` 卡片新增 `attendance_state=EXCEPTION`，标签显示“异常”，不显示为正常出勤；原学生考勤不添加虚构记录。现有统计API新增 `exception_count`，不需要新增页面。
