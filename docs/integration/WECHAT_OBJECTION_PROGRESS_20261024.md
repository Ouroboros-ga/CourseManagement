## 接口与权限

`GET /api/v1/me/objections/{objection_id}/progress`，使用原Bearer登录；编号为1至2^63−1的规范整数，客户端始终保留为字符串。不能传学生编号、学院或内部任务编号来指定身份。

服务端重新读取实际账号状态、学生绑定及既有 `objection.read` 权限，同时限制申诉学生和考勤学生均为本人。同学院其他学生和不存在的申诉统一404。管理员身份也不会使此本人接口返回全院数据。历史归属不跟随当前学院筛选，已撤回考勤的本人申诉仍可看历史。

接口不要求学生拥有学院配置或管理权限；`AGENT_OBJECTION_PRECHECK_ENABLED=false` 时返回404，不访问预审任务表。请求不创建预审、不自动重试、不改任务/考勤/终审/审计。AI工具凭据不能替代学生登录。

成功示例：

```json
{
  "data": {
    "objection_id": "123",
    "stage": "ACADEMIC_REVIEW",
    "label": "等待教务审核",
    "description": "请等待教务管理员核验；预审意见不代表申诉通过或驳回。",
    "final_status": "PENDING",
    "updated_at": null
  },
  "requestId": "example"
}
```

仅返回以上六个业务字段。不返回预审任务编号、执行批次、授权人、错误堆栈、材料内容/链接、模型建议或工具凭据。正式意见及当前考勤继续使用已有本人可读接口。

## 页面口径

| stage | 展示与含义 |
| --- | --- |
| SUBMITTED | 已提交，等待教务受理；不承诺已自动发起预审 |
| PRECHECK_QUEUED | 当前资料及策略仍匹配，登记为等待预审 |
| PRECHECK_RUNNING | 当前资料及策略仍匹配，登记为正在预审；不是实时Worker心跳 |
| ACADEMIC_REVIEW | 等待教务审核；预审完成、失败、失效或策略已变均不直接判定申诉结果 |
| COMPLETED | 正式审核已完成，依据final_status区分APPROVED/REJECTED |
| RECORD_WITHDRAWN | 原考勤已撤回，只展示历史 |
| ARCHIVED | 学期已归档且申诉未结案，历史可读，不能呈现为仍在主动处理 |

`final_status` 始终取正式申诉状态。即使旧预审仍在排队，正式结果已存在时也显示COMPLETED；考勤撤回优先显示RECORD_WITHDRAWN，同时保留正式状态。结果跨环境隔离，不将其他环境的执行记录当作当前进度。

`updated_at` 是可确认的源状态记录时间，并非本次查询时间或预计完成时间。资料失效、策略变化、归档或撤回而没有可确认的对应时间时返回null，页面隐藏时间，不补造时间戳。

## 小程序接入步骤

1. 在本人申诉详情打开时读取已登录的 `/api/v1/me/campus-runtime`。明确的 `objection_precheck=false` 隐藏预审进度；读取失败展示“暂时无法读取进度”，不能解释为未提交或已关闭。
2. 在现有 `miniprogram/api/record.js` 增加进度读取方法；详情以当前申诉ID请求，保留字符串精度。只在用户打开/显式刷新时读取，避免为整个考勤列表逐条请求。
3. 在 `miniprogram/pages/record/list/index.js` 的申诉详情内展示label/description。正式APPROVED/REJECTED仍依据final_status；不要依据旧initial_status判断AI是否通过。
4. 切换账号、关闭弹窗、打开其他申诉或离开页面后拒绝旧响应回写。刷新失败清空旧进度并显示重试入口，保留原正式记录。
5. 401按现有刷新/重新登录处理；403清空不可读内容并提示权限变化；404提示当前不可读取，不能擅自创建新申诉；422核对ID。不要自动重新提交申诉或发起管理重试。
