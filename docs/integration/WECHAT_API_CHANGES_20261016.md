# 微信小程序：学院升级后的接口兼容说明

2026-10-16最终决定：**小程序继续使用升级前的接口，无需因学院隔离和Web重整而改版。**

## 原有调用保持不变

| 小程序功能 | 兼容规则 |
| --- | --- |
| 微信登录、学生绑定、刷新 | 原路径、参数和身份流程不变 |
| 本人任务、志愿者提交 | 原路径及请求结构不变，后端判断权限与业务范围 |
| 本人考勤列表 `GET /api/v1/me/attendance` | 恢复学院升级前响应结构；仍按绑定学生返回本人记录 |
| 学生考勤详情 `GET /api/v1/attendance/{id}` | 恢复学院升级前响应结构，按原考勤ID查询 |
| 现场照片、学生异议 | 保留此前已确认的照片访问与一次审核能力；原路径不变 |

小程序不传college_id，不增加学院选择器，不自行按学院筛选。后端根据当前绑定学生、任务归属和权限处理查询；管理端继续使用学院隔离、作息和组织排班功能。

本次从学生考勤响应撤回三个管理字段：`task.responsible_college_id`、`task.responsible_college_name`、`task.semester_status`。它们只在管理端扩展响应返回，小程序不用显示或依赖它们。原有`photo_file_ids`继续保留，不撤回此前的现场照片需求。

仍以考勤记录id识别记录，不按课程名覆盖；业务状态冲突继续按原有409提示处理。没有新增小程序必填参数，也不要求重新绑定或迁移客户端ID。

## 个人课表功能独立、可选

云端个人课表、正式来源对比、删除恢复、单次修改、自定义颜色等是此前单独确认的便捷功能，继续保留后端接口。**没有开发这些页面的小程序可以完全不调用这些新增接口，不影响已有功能。**

如后续决定开发个人课表，阅读[个人课表与通知接口](WECHAT_PERSONAL_TIMETABLE_API_20261015.md)中的“2026-10-16可选扩展”；不要把它当作本次学院升级必须实施的适配清单。通知仍仅展示，不增加已读/未读/自动采用流程。

## 验证边界

已用升级前219a087的Schema逐字段核对学生考勤契约，并在服务器隔离MySQL真实HTTP链路检查学生列表/详情不含三个管理字段，管理侧保留扩展字段，照片、提交、异议和统计链路不受影响。实际部署状态见[实施状态](../development/IMPLEMENTATION_STATUS.md)。
