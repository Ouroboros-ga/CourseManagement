# wxsign 小程序接入计划

来源：`Mo-Qiong/wxsign` 的 `30c219fb27e95527dec87c724e288c416a8823b6`。原生小程序完整源代码接入 `apps/wechat-miniapp/`；保留原 `project.config.json` 与 npm 依赖声明，不带上游 `.git`。

1. 禁用指向外部 Apifox 的默认请求地址；本地调试使用 `127.0.0.1:18080`，真机/上线由受控配置提供后端 HTTPS 域名。
2. 将请求成功/错误结构改为 FastAPI 契约；小程序 refresh 凭证走 JSON，401 单次轮换并串行化并发刷新，登出撤销后端会话。
3. 微信 `code` 登录后区分绑定状态；按 `student_no + binding_code` 完成绑定并读 `/me`。原页面的“姓名＋学号直接绑定”不符合后端规则。
4. 任务列表/详情、名单、异常类型、照片上传及提交使用实际 API、内部学生 ID 与文件 ID。保留逾期任务的可补交入口；具体是否能提交由后端校验。
5. 使用 Node 的微信 API 模拟测试验证客户端请求和页面行为，再用本地后端做接口联调。真实 `wx.login→code2session` 和真机请求需匹配 AppID、私有 AppSecret、可访问的 HTTPS 请求域名及微信开发者工具，不以模拟测试代替。

本轮只对接上游已有页面。学生考勤/异议、管理审核等尚无上游页面，记录为后续联调入口，不通过虚构路由代替。
