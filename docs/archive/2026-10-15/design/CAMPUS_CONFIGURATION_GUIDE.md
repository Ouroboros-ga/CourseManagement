# 学院配置底座：开发与验证

2026-10-13。当前完成的是升级的配置起点：独立学院实体、院级完整动作授权、课程类型、志愿者组基本信息及不可变范围/规则版本。正式课表、成员、抽查和排班尚未接入，不用于多学院真实业务上线。

## 本地入口

使用后端锁定环境，先核对目标数据库。新增迁移 `f26a1013c001` 接 `b2c3d4e5f6a7`，只创建 7 张配置表，不猜测存量学院归属或改写旧记录。运行库迁移需对应环境授权，本次未执行。

迁移完成的开发环境设置 `CAMPUS_CONFIGURATION_ENABLED=true` 后启动。默认 false 时新配置接口返回 503，避免旧数据库未建表却开放入口。Web 进入 `/dashboard/campus`，通过现有登录会话访问。

超管先初始化一所学校，再创建学院，维护本学院类型和组；给教师账号明确授予本学院配置动作。配置授权不会写入旧全局角色权限，也不自动授予旧课表/名单访问权。角色名称、负责人标签和前端隐藏按钮均不能代替新接口授权。

新组默认为草稿，负责人默认是 Web 当前创建者，后端 PATCH 支持交接有效账号。范围只显式纳入所选类型，新类型不会自动加入。查课范围与本人课程冲突例外分别配置，一次发布并递增版本；启用要求存在有效范围，停用的组仍可调整配置再恢复。

当前只接受本学院 `class_mode=ALL_AUTHORIZED` 配置；指定班级与跨院支援需可靠学院归属和业务隔离后接入。当前组没有新成员管理和真实派发能力；日周上限与冲突规则保存为将来接入所用版本，不能宣称旧排班已执行这些配置。

## 数据与行为边界

- 学院默认隔离；动作只在完整同学院授权内取并集，不把 A 的写能力和 B 的读范围拼在一起。
- 写入锁账号/学院锚点并当前读取角色和授权，复核有效期；乐观锁旧版本 409，失败回滚，审计同事务。撤权与配置写共享学院锚点，真实 MySQL 竞争需 P6 验证。
- 类型 ID/code 稳定，名称 NFKC/去首尾空白/casefold 规范化，院内唯一，跨院可同名；数据库用二进制规范化名称键，与服务规则一致。
- 组范围、冲突例外均维护类型外键引用，`is_inspection_scope` 区分检查范围与仅供冲突使用的引用，不得把引用并集当抽查白名单。历史发布版本保留，引用阻止硬删除。
- 组当前版本通过 `(group_id, config_version)` 指向不可变版本，服务在学院锁内推进；这一实施结构替代设计中的 active_config_version_id 指针，避免循环建表外键。
- 新表尚不关联正式教学班/任务，因此类型停用只影响新配置校验，未来任务影响清单须 P3/P4 接入。已发生的正式业务没有被这阶段代码改变。
- 个人课表仍是产品定义与后续后端阶段，不从私人内容加载任何排班数据。

## 定向验证

```powershell
# backend；无需运行库连接
.\.venv\Scripts\python.exe -m pytest tests/unit/test_campus_configuration.py tests/unit/test_campus_migration.py -q -p no:cacheprovider
.\.venv\Scripts\python.exe -m alembic heads

# apps/admin-web
npm.cmd run test:campus
npm.cmd run build
```

SQLite 回归验证服务事务、范围、引用、版本、HTTP envelope 和迁移对账；不能证明 MySQL 锁语义。浏览器用本机临时 SQLite 虚构账号/学院验证类型创建、组配置、再次发布/启用及学院切换，不连接实际学校数据库。
