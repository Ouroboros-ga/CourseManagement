## W01　微信登录和绑定本人学生身份

**实现状态：已实现**。小程序源码已实现；未核实发布版本或真机。

**入口与前置条件：**小程序 → 微信一键登录。 对应微信版本已发布并配置合法域名；本人已有学生档案和有效绑定码；不是 Web 密码。

**测试数据：**D-ACCOUNT、D-STUDENT；本人独立测试微信和一次性绑定码（见[测试数据说明](TEST_DATA.md)，未在本轮批量建立）。

**操作步骤：**

1. 点“微信一键登录”
2. 首次绑定填写“学号”“绑定码”，点“确认绑定”
3. 返回首页核对本人身份；失败时不要改填其他同学学号

**预期结果：**

- 本人学生身份绑定成功；志愿者入口仅在有效资格具备时显示
- 前端选择不能把普通学生变成管理员或志愿者

**常见错误与处理：**

- 绑定码错误/过期：联系本院授权人员重发
- 微信登录失败：维护者检查已发布版本和域名，不要求用户提供 Token
- 身份不符：停止提交，用个人中心重新绑定并核对

**核对依据：**SRC-MINIAPP、SRC-PERMISSION，详见[证据清单](EVIDENCE.md)。

**实现状态：已实现**。小程序源码已实现；未真机验证。

**入口与前置条件：**小程序首页 → 查课任务 → 任务详情。 有效志愿者资格、微信绑定和本人当前受派；非本人任务不可通过修改地址获取。

**测试数据：**D-TASK 的 TODAY-NORMAL、FUTURE；V1（见[测试数据说明](TEST_DATA.md)，未在本轮批量建立）。

**操作步骤：**

1. 打开“查课任务”，按列表状态找到本人任务
2. 进入详情核对查课日期、时间地点、应到和学生名单
3. 未来日期仅查看，按页面提示等待开放提交

**预期结果：**

- 只显示本人有权任务；服务端按当前受派身份限制
- 查课日期前不开放提交；已撤销/改派状态及时反映

**常见错误与处理：**

- 没有任务：核对资格、成员有效期和是否已实际派发
- 任务消失：负责人可能已改派或取消，先确认
- 名单错误：联系负责人处理正式资料，不用异常申报补造名单

## W03　提交正常或异常查课并上传现场照片

**实现状态：已实现**。小程序源码已实现；本轮未提交。

**入口与前置条件：**本人任务详情 → 全部正常／存在异常学生。 查课日期已到，任务可提交、本人当前受派；异常必须属于有效名单；证据为本人正确类别可用文件。

**测试数据：**D-ATTENDANCE、D-FILE；分别使用 NORMAL 与 ABNORMAL 独立任务（见[测试数据说明](TEST_DATA.md)，未在本轮批量建立）。

**操作步骤：**

1. 核对名单后选择“全部正常 (无迟到、旷课、请假)”或“存在异常学生”
2. 异常时点“添加学生”，搜索并选择本人看到的学生，设置迟到/旷课/请假，点“确定添加 (N)”
3. 按页面必填/选填提示上传合成现场照片；当前小程序最多选 3 张
4. 点“提交记录”，重新打开任务和考勤核对结果

**预期结果：**

- 提交成功立即生成正式考勤，不等待旧人工审核
- 异常学生状态与填报一致，其余名单生成正常考勤
- 逾期补交仍可办理但不擦除截止时考核事实；失败不能显示虚假成功

**常见错误与处理：**

- 未来日期：等待对应查课日，不改手机时间绕过
- 照片缺失/上传失败：先完成上传再提交，不只传手机临时路径
- 名单外学生或重复异常：核对名单和选择；版本变化刷新

**核对依据：**SRC-MINIAPP、SRC-CORRECTION，详见[证据清单](EVIDENCE.md)。

## W04　首次提交后两小时内修改

**实现状态：已实现**。源码已实现；纠错时间提示显示缺陷待真机复核。

**入口与前置条件：**已提交本人任务详情 → 修改本次查课。 服务端允许纠错；自首次成功提交起未满 120 分钟；没有任何异议或管理更正；仍是本人受派，学期和任务可办理。

**测试数据：**D-TASK 的 REVISE；T0 首次提交时间；D-FILE（见[测试数据说明](TEST_DATA.md)，未在本轮批量建立）。

**操作步骤：**

1. 在服务端允许时点“修改本次查课”
2. 重新核对正常/异常名单和保留照片，必要时增减材料
3. 点“提交记录”，重开任务核对当前结论；不想保存可返回，不提交不改变原结论

**预期结果：**

- 旧提交被保留为历史，新提交成为唯一有效版本，考勤同步更新
- 修改失败原提交和原考勤保持有效
- 修改不重置首次提交截止，满两小时即关闭

**常见错误与处理：**

- 无修改按钮：查看是否超时、改派、取消或存在异议/管理员更正
- 409：刷新当前任务，不覆盖新结论
- 小程序截止提示格式存在源码显示缺陷：以服务端是否允许和准确截止为准，不能以手机显示误推延长

**核对依据：**SRC-MINIAPP、SRC-CORRECTION，详见[证据清单](EVIDENCE.md)。

## W05　撤回与重新提交

**实现状态：已实现**。小程序源码已实现；本轮未撤回或重交。

**入口与前置条件：**已提交本人任务详情 → 撤回本次查课；撤回后回到任务提交。 与 W04 相同纠错保护；撤回和重新提交均不能超过首次提交窗口。

**测试数据：**D-TASK 的 WITHDRAW、RESUBMIT、EXPIRED，均独立（见[测试数据说明](TEST_DATA.md)，未在本轮批量建立）。

**操作步骤：**

1. 点“撤回本次查课”，核对影响，按需填写原因，再点“确认撤回”
2. 重开任务及考勤记录核对撤回状态
3. 仍在原窗口且允许时按 W03 重新提交

**预期结果：**

- 撤回保留提交/照片/考勤历史，退出当前有效统计；任务不冒充已完成
- 重交恢复一份有效结论，不能重置两小时窗口
- 管理员更正或任何异议都阻止志愿者撤回覆盖

**常见错误与处理：**

- 撤回后超时不能重交：联系授权管理者核实，不伪造新任务
- 统计仍是旧值：刷新相同范围并核对有效状态
- 网络失败：先查询实际状态再决定重试

**核对依据：**SRC-MINIAPP、SRC-CORRECTION、SRC-REPORT，详见[证据清单](EVIDENCE.md)。

## W08　提出学生异议与被驳回后重新申诉

**实现状态：已实现**。小程序源码已实现；未发起真实申诉。

**入口与前置条件：**小程序 → 考勤记录 → 异常记录“提出异议”；允许时“重新申诉”。 本人异常有效考勤、开放学期、仍在服务端异议期内且无进行中异议；当前默认创建记录后 7 天，以实际服务端为准。

**测试数据：**D-OBJECTION；合成理由和证明 PNG（见[测试数据说明](TEST_DATA.md)，未在本轮批量建立）。

**操作步骤：**

1. 核对异常考勤，点“提出异议”
2. 填写“异议理由”，按需添加“证明材料（选填，最多3张）”
3. 点“提交异议”；当前页面诉求固定为正常出勤，没有改判类型选择器
4. 在记录中查看结果；被驳回且仍在期内时点“重新申诉”，补充依据后“重新提交异议”

**预期结果：**

- 成功产生待一次审核异议，不立即自行改考勤
- 同一考勤有进行中异议时不能重复提交
- 重新申诉创建新异议，旧处理结果保留；过期不能绕过
- 发起任何异议即保护相关任务，志愿者不能再覆盖

**常见错误与处理：**

- 空理由：当前小程序表单要求填写，不能按后端选填规则留空
- 原本已正常：没有相同状态改判需要
- 409/过期：刷新原记录并核对期限，不另绑账号申诉
- 希望改为迟到/请假：当前小程序不提供该诉求选择，联系授权管理员核实
- 附证明图提交异常：源码存在大文件编号被转成数值的兼容风险，尚未真机复核；保留失败信息交维护者，不为通过而丢弃有价值的证据。任务 5 见 J28

**核对依据：**SRC-MINIAPP、SRC-ATTENDANCE、SRC-CORRECTION，详见[证据清单](EVIDENCE.md)。
