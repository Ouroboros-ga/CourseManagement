## C01　Web 登录、续期与退出

**实现状态：已实现**。PAGE-01；登录由用户完成。

**入口与前置条件：**/login；完成后进入工作台；窄屏先展开功能菜单。 已有有效 Web 登录名和密码。负责人先完成本人学生绑定与有效任命，由教师配置 Web 密码；绑定码不是登录密码。

**测试数据：**D-ACCOUNT（见[测试数据说明](TEST_DATA.md)，未在本轮批量建立）。

**操作步骤：**

1. 在“管理账号（工号 / 登录名）”“登录密码”填写本人已有凭据
2. 点“进入工作台 →”
3. 需要修改本人密码时，从“账号与权限”点“修改我的密码”，填写“当前旧密码”“设定新密码”“确认新密码”，点“确认修改密码”；成功后按会话提示重新登录。绑定码不是密码。
4. 确认工作台与授权学院；操作完成从菜单点“登出 →”

**预期结果：**

- 有效凭据进入工作台；普通学生和志愿者不因微信绑定获得后台管理权限
- 会话过期后正常续期或要求重新登录；退出后管理页面受登录保护

**常见错误与处理：**

- 账号或密码错误：核对登录名，不连续猜测；停用/锁定由授权管理员处理
- 负责人无法进入：检查学生绑定、任命有效期、在读学院和 Web 凭据，而不是另建重复账号

**核对依据：**SRC-NAV、SRC-PERMISSION，详见[证据清单](EVIDENCE.md)。

## C02　切换学院、学期、教学周与刷新权限

**实现状态：已实现**。PAGE-01。

**入口与前置条件：**各业务页面顶部；窄屏先展开菜单再进入所需页面。 账号至少有一个有效工作区；只能选择服务端返回的学院和学期。

**测试数据：**D-ORG、D-ACCOUNT（见[测试数据说明](TEST_DATA.md)，未在本轮批量建立）。

**操作步骤：**

1. 先确认顶部学院；多学院账号选择目标学院
2. 在“业务学期”选择验收学期，支持周次的页面再选“教学周”
3. 授权变化后点“刷新学院权限”，必要时重新登录
4. 切换前处理未保存表单提示，重新核对新范围

**预期结果：**

- 新页面显示目标范围，旧学院的数据和未提交预览不应串入
- 当前学生档案不会因切换学期重建或清空

**常见错误与处理：**

- 没有学院选项：可能只有单学院或没有有效授权，联系超管核对
- 旧预览失效：重新读取当前学院资料，不返回旧页面强行保存

**核对依据：**SRC-NAV，详见[证据清单](EVIDENCE.md)。

## T01　Excel、文件夹与 ZIP 统一资料导入

**实现状态：已实现**。PAGE-03；上传后的预览/确认由源码补证。

**入口与前置条件：**教务资料 → 资料导入 → 统一资料导入中心。 有目标类型的导入及管理权限；负责人通常只能办理已授权课表导入，不能凭 import.execute 导入学生或教职工。学院/学期/目标教学班按资料要求明确。

**测试数据：**D-IMPORT（八类表格详见 TEST_DATA）（见[测试数据说明](TEST_DATA.md)，未在本轮批量建立）。

**操作步骤：**

1. 点“下载标准模板包”，按真实表头填写合成资料，学号/工号设为文本
2. 点“选择文件／补充修正文件”“选择文件夹”或“选择 ZIP 压缩包”
3. 核对识别类型，无法唯一识别时明确选择，不按文件名猜类型
4. 进入资料组读取与预览，核对新增、修改、无变化及问题内容
5. 只在 QA 点击本组“确认导入 N 个文件”；完成后切换下一资料组，最后按需要单独发布课表

**预期结果：**

- 预览阶段未保存正式资料；确认后保存当前资料组并显示结果
- 学生、教职工、责任关系、标准/网格课表、资格、补充名单和选修资料走相应解析器
- 各组独立保存；成功组保留，未导入文件不会被静默忽略，也不会因缺席某学生就自动删除他

**常见错误与处理：**

- 识别为无权类型：明确提示无权限，不自动换成课表类型；交给有权人员
- 模板/压缩包超限：按页面大小及数量限制拆批；网格课表必须保留受支持结构
- 预览过期或换学院/学期：重新读取，不复用旧确认结果

**核对依据：**SRC-IMPORT，详见[证据清单](EVIDENCE.md)。

## T02　导入重名、编号冲突与失败文件处理

**实现状态：已实现**。PAGE-03 帮助实见；具体问题预览由源码补证。

**入口与前置条件：**资料导入 → 本组预览；首页有“重名、编号不符或缺少档案，怎么处理？”帮助。 已有目标类型权限；存在可复现的合成问题文件；责任关系涉及人员必须有明确身份依据。

**测试数据：**D-IMPORT、D-STAFF 的重名/编号不符/缺档案对照（见[测试数据说明](TEST_DATA.md)，未在本轮批量建立）。

**操作步骤：**

1. 在预览点“查看问题与内容”或“查看内容与关联提示”，核对文件、行号、学号/工号及姓名
2. 先保存缺少的档案，或在本地补准确工号/学号后添加修正文件重新预览
3. 不处理的文件明确点“暂不导入（保留待修正）”；需要时点“重新纳入”
4. 确认有阻断问题时保存不可用；无阻断后只确认准备好的资料组

**预期结果：**

- 同名人员不自动合并，不默认选择本院同名教师
- 责任关系不明确时拒绝保存；课表授课姓名待关联可按明确提示保留，但不授予该教师权限
- 修正失败组不重复导入已成功组

**常见错误与处理：**

- 同名无法确定：向资料提供者核对工号，不靠学院或姓名推断
- 任期重叠或负责人换人：去“班级负责人”办理明确交接，不用重复导入覆盖
- 没看到问题：展开对应文件详情而不是只看成功计数

**核对依据：**SRC-IMPORT、SRC-STAFF，详见[证据清单](EVIDENCE.md)。

**入口与前置条件：**教务资料 → 课程类型；教学班分类在“教学班与分类”。 有相应本院类型/教学资料维护能力；不是按“早自习”等文字自动赋予特殊规则。

**测试数据：**D-ORG、D-COURSE（见[测试数据说明](TEST_DATA.md)，未在本轮批量建立）。

**操作步骤：**

1. 在“课程类型”新建或编辑本院类型，填写名称等现有字段并保存
2. 到“教学班与分类”查询目标教学班，点“编辑”，选择唯一课程类型并保存
3. 停用或删除前阅读引用及未来任务影响；需要恢复时从“已删除记录”检查可恢复项

**预期结果：**

- 教学班只选一个类型，名称相同不等于跨院同一授权
- 改名不重写历史快照；停用不删除正式课表，也不消除本人课程冲突
- 有引用或未来任务时执行后端保护，不通过强删绕过

**常见错误与处理：**

- 名称重复：改为本院唯一名称
- 旧预览失效/存在未来影响：重新预览并到“未来变更处置”逐项处理
- 菜单缺失：核对类型读取/维护能力

**核对依据：**SRC-ACADEMIC，详见[证据清单](EVIDENCE.md)。

**实现状态：已实现**。设置及日志源码核对；归档未执行。

## 本轮操作补充

- 资格导入成功会准备无微信、无Web密码的排班底册身份。对旧导入缺失底册，重新读取原文件时会显示“修改”，确认后补全；不会认领用户名恰好相同的他人账号。
- 自习排课确认后必须回正式课表选择对应周次查询；仅生成课表和名单，不自动下发任务或免到。重复生成同一范围不新增相同排课。
- 考勤更正理由初始为空，可主动选择常用理由，必须核实真实依据；不要把常用理由当作已经发生的审批事实。
- “暂不导入（保留待修正）”仅把文件排除出本次保存，仍保留在队列，可修正后“重新纳入”。
- 截止历史“办理账号”显示账号编号；系统初始记录标为系统默认，编号不等于姓名。
- 窄屏从“展开功能菜单”查看当前身份并点“登出→”；身份按有效管理角色优先显示。
