## 三种实现状态

- **已实现**：代码中存在完整功能路径和可达页面。Web 页面已随基准版本部署；小程序单列“源码已实现、微信版本/真机未核实”，不能把后端部署当作小程序已发布。
- **有后端但无页面入口**：服务端已有接口，但当前端侧没有可达页面，或组件未挂载/页签被隐藏。用户不能按不存在的按钮操作；接口验收交给测试人员在 QA 完成。
- **尚未实现**：未发现相应端到端实现；仅需求或设计不能作为操作入口。非本期目标和明确取消的方案另行说明，不承诺开发。

实现状态与本轮验证状态是两回事。“已实现”不表示所有角色已经登录实测，也不表示所有写入验收已通过。本轮浏览器使用用户提供的现有管理会话；负责人、志愿者、普通学生的限制同时依据路由、页面条件与服务端规则核对。任务5/6使用独立合成教师和负责人账号实测Web；志愿者和普通学生微信客户端按用户要求排除。

## 页面使用约定

1. 宽屏从侧栏进入；窄屏先点左上角“展开功能菜单”。七个日常入口是“工作台、教务资料、学生与班级、志愿者组织、查课安排、考勤与异议、统计报表”。辅助菜单按权限出现。
2. 先核对顶部学院、业务学期和教学周。页面中的“管理对象学院”不等于顶部正在办理业务的学院。无权学院不能通过改网址访问。
3. 所有操作以当前账号可见按钮及服务端返回为准；按钮看不到时，先核对功能授权和学院，不要求重新建号。修改授权后可能需要重新登录。
4. 页面提示“预览”不等于已经正式保存；导入中心按资料组分别保存，其他组成功后不会因某组失败全部撤销。少数预览会保存临时草稿或排班计划，不把它们称为完全无写入。
5. 提交即生成正式考勤，不再等待人工审核。学生异议为一次审核。旧“提交审核”“初审/终审”字样可能残留于权限文案或历史字段，不代表恢复两级人工审核流程。
6. 两小时纠错从任务**首次成功提交**起算，修改、撤回和重交不重置；只认服务端截止。任何已发起异议或管理员更正都会保护该任务结论，志愿者不能覆盖。
7. 任务、照片、当前考勤和历史版本是不同对象；撤回退出当前统计，历史与截止考核事实仍保留。

## 常见错误的共同处理

| 现象 | 处理 |
| --- | --- |
| 登录过期/401 | 正常刷新或重新登录；不要反复提交同一写操作。先查看结果确认是否已成功 |
| 无权限/403、资源不可见/404 | 核对本人身份、学院及具体功能权限；不借用他人账号绕过 |
| 数据已变化/409 | 关闭旧预览，刷新当前记录，重新核对再提交；不强行覆盖别人的新结果 |
| 表格或字段错误/422 | 按文件名、行号和字段提示修正；学号/工号按文本保留 |
| 能力未启用/503 | 联系系统管理员核对业务开关与资料准备；不反复点保存，也不改用无学院的旧接口绕过 |
| 照片加载失败 | 刷新记录/重试获取短期链接；不要长期保存签名地址或把对象键当下载地址 |
| 页面没有数据 | 先检查学院、学期、周次、搜索和状态过滤；“没有记录”不是系统故障的充分证据 |

所有带“确认、保存、导入、派发、审批、更正、撤回、删除、解绑”的动作都可能改变正式数据。手册中的测试步骤是任务 5 的执行方案，本轮没有实际执行这些写入。
