## W01　微信登录和绑定本人学生身份

**实现状态：已实现**。小程序源码已实现；未核实发布版本或真机。

**入口与前置条件：**小程序 → 微信一键登录。 对应微信版本已发布并配置合法域名；本人已有学生档案和有效绑定码；不是 Web 密码。

**测试数据：**D-ACCOUNT、D-STUDENT；本人独立测试微信和一次性绑定码（见[测试数据说明](TEST_DATA.md)，未在本轮批量建立）。

**操作步骤：**

1. 点“微信一键登录”
2. 首次绑定填写“学号”“绑定码”，点“确认绑定”
3. 返回首页核对本人身份；失败时不要改填其他同学学号

**预期结果：**

- 本人学生身份绑定成功；志愿者入口仅在有效资格具备时显示
- 前端选择不能把普通学生变成管理员或志愿者

**常见错误与处理：**

- 绑定码错误/过期：联系本院授权人员重发
- 微信登录失败：维护者检查已发布版本和域名，不要求用户提供 Token
- 身份不符：停止提交，用个人中心重新绑定并核对

**核对依据：**SRC-MINIAPP、SRC-PERMISSION，详见[证据清单](EVIDENCE.md)。

## W07　查询本人考勤和异议进度

**实现状态：已实现**。小程序源码已实现；未真机验证。

**入口与前置条件：**小程序首页 → 考勤记录。 已绑定本人身份；只读取本人记录。

**测试数据：**D-ATTENDANCE；S1/S2/S3 分别登录，不能共享身份（见[测试数据说明](TEST_DATA.md)，未在本轮批量建立）。

**操作步骤：**

1. 进入“考勤记录”，核对课程、日期和状态
2. 点异议状态“详情”，查看“异议进度与详情”
3. 阅读办理结果后点“我知道了”

**预期结果：**

- 只显示本人考勤；撤回或失效记录不冒充当前生效结论
- 显示当前异议进度；历史初核/终审标签不代表现在要两级审核

**常见错误与处理：**

- 无记录：核对身份和时间范围，不重新绑定他人
- 历史结论与当前不一致：结合记录状态和办理历史阅读
- 他人记录访问被拒：属于应有保护，不请求取消权限检查

**核对依据：**SRC-MINIAPP、SRC-ATTENDANCE，详见[证据清单](EVIDENCE.md)。

## W08　提出学生异议与被驳回后重新申诉

**实现状态：已实现**。小程序源码已实现；未发起真实申诉。

**入口与前置条件：**小程序 → 考勤记录 → 异常记录“提出异议”；允许时“重新申诉”。 本人异常有效考勤、开放学期、仍在服务端异议期内且无进行中异议；当前默认创建记录后 7 天，以实际服务端为准。

**测试数据：**D-OBJECTION；合成理由和证明 PNG（见[测试数据说明](TEST_DATA.md)，未在本轮批量建立）。

**操作步骤：**

1. 核对异常考勤，点“提出异议”
2. 填写“异议理由”，按需添加“证明材料（选填，最多3张）”
3. 点“提交异议”；当前页面诉求固定为正常出勤，没有改判类型选择器
4. 在记录中查看结果；被驳回且仍在期内时点“重新申诉”，补充依据后“重新提交异议”

**预期结果：**

- 成功产生待一次审核异议，不立即自行改考勤
- 同一考勤有进行中异议时不能重复提交
- 重新申诉创建新异议，旧处理结果保留；过期不能绕过
- 发起任何异议即保护相关任务，志愿者不能再覆盖

**常见错误与处理：**

- 空理由：当前小程序表单要求填写，不能按后端选填规则留空
- 原本已正常：没有相同状态改判需要
- 409/过期：刷新原记录并核对期限，不另绑账号申诉
- 希望改为迟到/请假：当前小程序不提供该诉求选择，联系授权管理员核实
- 附证明图提交异常：源码存在大文件编号被转成数值的兼容风险，尚未真机复核；保留失败信息交维护者，不为通过而丢弃有价值的证据。任务 5 见 J28

**核对依据：**SRC-MINIAPP、SRC-ATTENDANCE、SRC-CORRECTION，详见[证据清单](EVIDENCE.md)。

## W09　个人中心退出与重新绑定

**实现状态：已实现**。小程序源码已实现；未执行解绑。

**入口与前置条件：**小程序 → 个人中心。 本人身份；重新绑定会解除当前微信联系，旧学生历史不能丢失。

**测试数据：**D-ACCOUNT 两个独立测试身份，严禁绑定真实他人（见[测试数据说明](TEST_DATA.md)，未在本轮批量建立）。

**操作步骤：**

1. 核对当前显示的本人身份
2. 需纠正绑定时点“重新绑定账号”，按确认提示继续，返回登录按 W01 办理
3. 只结束使用时点“退出登录”

**预期结果：**

- 解绑不删除学生档案、考勤或历史；旧会话不得继续写入
- 退出与解除绑定区别明确；重新绑定不会赋予他人历史访问权

**常见错误与处理：**

- 绑定冲突：联系授权管理员核对本人档案与绑定码
- 退出后找不到任务：重新登录核对本人身份，不另建志愿者
- 不要通过清手机缓存声称完成服务端解绑

**核对依据：**SRC-MINIAPP、SRC-PERMISSION，详见[证据清单](EVIDENCE.md)。

## B02　本人个人课表、云端备份与教务站内通知

**实现状态：有后端但无页面入口**。源码核对；本轮未执行正式写入。

**入口与前置条件：**当前小程序无个人课表/教务通知页面；API_ACCEPTANCE.md 的 B02。 本人绑定；教务发布开关开启；个人课表只供本人使用。

**测试数据：**D-ACCOUNT、D-COURSE；两个独立学生（见[测试数据说明](TEST_DATA.md)，未在本轮批量建立）。

**操作步骤：**

1. 接口读取已发布官方来源，初始化本人课表
2. 读取版本后新增/修改本人条目、保存备份并复读
3. 教师再次发布教务后读取站内通知及本人副本，核对原个人内容

**预期结果：**

- 只访问本人副本；个人编辑不作为排班、免到、资格或报表输入
- 教务更新不隐式覆盖本人保存内容；仅简单站内通知，不承诺微信推送
- 当前无小程序按钮，不能验收为端到端已交付

**常见错误与处理：**

- 无页面：等待小程序接入，不教用户手改 API
- 409：读取本人新版本再编辑
- 通知为空：核对是否有正式发布，不把导入当发布

**核对依据：**SRC-ACADEMIC、SRC-MINIAPP、SRC-API，详见[证据清单](EVIDENCE.md)。
