# Web 管理端建设路线（2026-09-29）

> 2026-09-29 后端补全规划：见 [BACKEND_COMPLETION_PLAN.md](./BACKEND_COMPLETION_PLAN.md)。下文负责人只读、周报可选等描述保留为当前实现快照；最新目标权限以该计划第 2 节为准，尚未在代码与数据库生效。

## 定性结论与范围

产品 V1.0 的业务范围已经可以作为 Web 管理端开发基线：以根目录《查课管理系统V1.0建设说明》（V1.01 合并版）为产品依据，以 `docs/PERMISSIONS.md` 为授权依据，以当前后端路由、`docs/API_CONTRACT.md` 和 `docs/API_INDEX.md` 为接口依据。排班冻结规则见 `docs/SCHEDULING_RULES.md`。这表示**核心业务方向已定**，不表示所有运行参数、正式表格模板和后端读取接口都已完成。

当前仓库没有 `apps/admin-web/`。微信小程序属于独立前端，不可把其页面数或模拟测试当成 Web 管理端进度。Web 技术栈按既定方案采用 Vue 3、TypeScript、Vite、Vue Router、Pinia、Element Plus；先交付浏览器版，同源 HTTPS + FastAPI API，Electron 不进入 V1.0 Web 实现路径。

## 已定的产品规则

- 超级管理员可以管理教师管理员和学生工作负责人；教师管理员只可授予或撤销学生工作负责人，不能互授或撤销教师角色。学生与志愿者身份不通过该角色分配页手工操作。
- 学生工作负责人覆盖当前学院全部年级。`statistics.read`、`report.read`、`objection.initial_review` 三项可选权限默认关闭，由有权限的管理员逐人开关；统计读取不等于周报读取。
- 任务五种当前状态由后端返回。允许逾期补交，截止时的“逾期未执行”考核事实单独保留；界面分别展示当前状态与考核结果。
- 任务生成、自动排班、人工改派遵循后端规则；前端展示未分配原因，但不在浏览器重算排班或把原因码当成全量诊断。
- 初核不更正考勤；终审改判须有 `attendance.correct`，并按当前版本提交。周报版本不可覆盖，需展示最终版本修改时间与历史版本。
- Web access token 只存在内存；refresh token 由 `HttpOnly` Cookie 承载。业务 ID 保持字符串；所有权限、范围和归属最终由后端判定。

## 页面与交付顺序

| 波次 | 可验收的用户工作流 | 主要页面 | 后端依赖与验收重点 |
| --- | --- | --- | --- |
| W0 登录与只读工作台 | 管理员登录、刷新会话、按权限进入任务列表，查看任务详情及状态 | 登录、应用框架、任务列表/详情 | `/auth/web/login`、`/auth/refresh`、`/me`、`/inspection-tasks`；先证明 Cookie、401 串行刷新、403/404、权限撤销后的菜单与数据刷新 |
| W1 基础数据与导入 | 建立学期、节次、校历例外、班级/学生/课程/教学班/课表/资格；下载模板、预览错误、确认导入 | 学期与课表、学生与班级、志愿者资格、导入向导 | `academic` 与 `imports` 现有接口；正式学校模板样例需验收，预览和确认不可合并为一步 |
| W2 任务与排班 | 正向勾选查课班级或课程、预览/生成、自动排班、查看未分配原因、人工改派、调班审核、截止修改与结算 | 任务生成、任务总览、排班、调班、日截止 | `inspection` 现有接口；版本冲突后重取，保留筛选后仍已选的班级；不得通过前端绕开体育排除和冲突规则 |
| W3 审核与认定 | 发现待审提交、读详情与附件、通过/驳回、调整应到、查看及更正考勤、初核/终审异议 | 提交审核、考勤、异议 | **先补管理侧提交列表/详情读取接口**；已有审核写接口不可单独构成工作台。附件只调用 `/files/{id}/access` 获取短时 URL |
| W4 统计与周报 | 读到课/缺勤统计和未完成清单、生成学院周报、列出历史版本并下载 | 统计、未完成、周报版本 | **先补周报主记录列表或按学期/周次定位的读取接口**；V1.0 客户端仅发送 `scope=COLLEGE`。源修订覆盖补齐前不得把“未落后”解释为全部输入未变化 |
| W5 人员权限与验收 | 管理角色、负责人三项可选权限、绑定码/解绑；全角色端到端与 900 人规模峰值验收 | 角色、可选权限、绑定管理 | 使用服务端返回的目标选择器和 `lockVersion`；正式参数、备份恢复、双端联调与性能判据须独立验收 |

每波次以真实 API + 隔离 MySQL 验证该工作流，页面测试覆盖权限变化、空列表、分页、409 冲突与重试边界。页面隐藏按钮仅优化交互，不能作为授权证明。先做桌面浏览器布局，再用微信小程序承接志愿者/学生移动场景；不在 V1.0 管理端同时建设一套移动后台。

## 需要并行补齐而不应伪装成已交付的能力

1. `submission.review` 的管理侧待审提交列表和详情读取缺失；`GET /me/submissions` 与现有 `GET /submissions/{id}` 是本人路径，不能给管理审核页面复用。
2. 周报现有版本列表要求已知 `report_id`，但没有周报主记录发现入口；版本历史页不能依赖浏览器本地保存的 ID。
3. 当前无审计日志查询路由，也无通用 `system_config` 管理 API。日截止已有专用 API；照片要求、保留期限和全局当前学期等设置不得先画成可保存的假表单。
4. `scope=CLASS` 的周报聚合尚未实现；源修订只覆盖部分写路径。Web 页面先展示学院周报并如实说明落后判定范围。
5. 生产截止时间、材料保留期、日/周上限、学校 Excel 模板及文件存储部署方式仍需业务/运行验收；这些参数不妨碍 W0–W2 开发。

W0 的文件级实施步骤见 `docs/ADMIN_WEB_W0_IMPLEMENTATION_PLAN.md`；后续波次各自拆独立计划，不把所有 CRUD 堆成一个任务。

三个管理角色的首页、菜单与按钮差异见 `docs/ADMIN_WEB_ROLE_UI_DESIGN.md`；实现上按有效权限组合，同页复用，不维护三套前端工程。


## 2026-09-29 补充：按周选择查课范围与一键下发

当前后端：课程查课按学期、周次或日期范围、教学班生成，覆盖目标教学班范围内符合课表及校历的课次；体育课排除。早晚自习按行政班及节次生成。当前接口没有逐个课次勾选，也没有“每班自动抽 N 次”参数。已取消任务不会因再次生成而恢复。

Web W2 目标流程：选择本周 → 勾选班级/课程 → 展开具体日期和节次，勾选本周需查的课次 → 预览 → 一键生成并排班 → 展示已分配及未分配清单。筛选不能清空隐藏的已选项；不引入独立的永久“这门课是否查”开关。所谓临时增加，是把本周原先未选的某次实际课程纳入本次计划，不是覆盖校历或体育排除规则。

待补后端：可分页查询候选课次，以及生成请求接受精确课次选择；服务端重新校验学期、课表、日期、节次与可查规则，不能信任客户端快照。现有 preview/generate/auto API 可复用，但当前预览样本不能直接当成完整的课次选择列表。

“一键下发”是产品入口：依次生成选定任务并分配志愿者。现有受派任务立即进入志愿者可见列表，没有额外发布审批阶段。生成与排班目前是分开的事务；后一步失败必须显示已生成、待分配状态并允许重试，不得宣称全部失败或全部成功。排班仅针对本次确认的任务 ID，不得误处理本周其他任务；超出接口批量上限需拆批并汇总结果。无需额外承诺微信推送消息。

学生工作负责人执行生成、排班、手动改派和取消，仍需按最新业务决策补齐后端权限配置；当前角色默认授权尚不覆盖上述操作，不能仅显示 Web 按钮。所有人工原因输入标为“选填”，保留自动审计记录。
