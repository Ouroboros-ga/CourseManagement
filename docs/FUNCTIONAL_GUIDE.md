# 功能说明与角色工作流

截至 2026-09-29，本说明以 `backend/app/main.py` 实际注册的后端路由、各模块 schema/Service 为准。后端覆盖身份与权限、基础数据、两步导入、查课任务与排班、提交审核、文件、考勤异议、统计和版本化周报。完整接口与权限入口见 [API_INDEX.md](./API_INDEX.md)，字段和错误语义见 [API_CONTRACT.md](./API_CONTRACT.md)，角色矩阵见 [PERMISSIONS.md](./PERMISSIONS.md)。这是代码功能说明，不代表部署、真实前端联调或学校验收已完成。

## 共同约定

- Web 管理端用账号密码登录；小程序登录接口用微信 `code` 换会话，受 `WECHAT_LOGIN_ENABLED` 控制。当前后端有微信换码与绑定逻辑；真实微信环境及小程序页面联调仍待完成。首次无学生绑定且无角色的账号处于受限态，只能读取本人身份、绑定、刷新和登出。
- 权限按当前账号的角色与两项个人可选授权实时计算。账号同时持有多个角色时，功能权限取并集；涉及本人提交、本人考勤和本人异议的服务端归属限制仍逐条执行。负责人可选项是 `statistics.read`、`objection.initial_review`，默认关闭；`report.read` 与 `report.generate` 属负责人默认权限。
- 业务 ID 对外用字符串。常规 JSON 成功响应为 `data` 与 `requestId`，错误含稳定 `code`；204 操作和文件下载另按各接口响应。需要版本号的写操作应先读最新值再提交，遇 `VERSION_CONFLICT` 或排班输入冲突须刷新后重试。
- 当前管理类范围按服务端管理权限执行；账号与学院的强制行级归属尚未落地，不能把“当前可看管理范围”解释为多学院隔离已经完成。

## 超级管理员与教师管理员

1. 登录后通过 `GET /api/v1/me` 获取实时角色和权限。超级管理员可管理教师管理员与负责人角色；教师管理员可管理负责人角色，不能授予、撤销教师或超级管理员角色。学生与志愿者角色由绑定及资格流程决定，不能手工授予。分配角色与设置个人可选授权采用目标选择器、版本检查与审计；撤销负责人角色会清掉其个人可选授权。
2. 超管可经 `/teacher-accounts` 创建、修改/停用教师账号及管理重置口令；教师管理员无此管理权限。密码账号可经 `/me/password-change` 自助改密。教师维护学期、节次、校历例外、行政班、学生、课程、教学班、名单、课表和志愿者学期资格。教学班列表支持 `administrative_class_id` 筛选；课表 XLSX 可按学期/教学班导出，基础模型暂无任课教师字段，因此教师列为空。
3. 对名单、课表、志愿者资格可先取模板，再上传 xlsx 得到预览批次、错误与告警；确认时重校验引用并整批提交。导入同时要求 `import.execute` 和目标资源的管理权限；有阻断错误、过期批次或引用变化时不得确认。
4. `GET /inspection-course-occurrences` 返回本周候选课次、`selection_scope` 与全范围修订；预览/生成精确模式原样提交该范围、修订和勾选的 `occurrences`。生成结果含每个任务 ID 与 `assignable_task_ids`，自动排班只传本次可排 ID。人工分配/改派受冲突与周上限约束，历史受派保留。取消任务后可通过显式 restore 恢复未开始、无执行事实且快照兼容的任务，恢复后为未分配状态。调班申请通过后仍需另行改派。
5. 志愿者提交后，管理端可经 `/management/submissions` 发现待审提交、读取详情与照片文件 ID，并通过 `/submissions/{submission_id}/review` 审核。通过后按提交使用的名单版本生成当前考勤与历史版本；驳回保留提交事实。`/me/submissions` 与 `/submissions/{id}` 仍强制本人范围。管理者可调整当前应到人数，具备 `attendance.correct` 者可更正考勤。截止时考核是历史快照，与后来补交后推导的当前任务状态并列显示。
6. 具备 `objection.final_review` 者终审异议；通过且改变考勤类型时还需 `attendance.correct`，并检查异议发起时与当前考勤版本一致，防止覆盖新认定。
7. 具备 `statistics.read` 者读取考勤聚合和未完成清单；具备 `report.generate` 者为学期周次同步生成新版本；具备 `report.read` 者查看版本、源数据/规则/模板落后提示并下载已发布的 Excel 或 JSON 快照。生成版本不可覆盖旧版。周报业务内容只含考勤汇总；固定格式 Word 文档尚待实现，当前 Excel 为通用工作簿。V1 请求仅允许 `scope=COLLEGE`；`CLASS` 返回 422，后续须设计明确班级隔离键和聚合口径再开放。

## 学生工作负责人

- 负责人必须绑定有效学生身份；解绑或学生停用会撤销负责人角色、可选授权和旧会话。默认可查询课表、导入/导出课程课表、精确生成/取消/恢复任务、自动排班和人工改派，并生成/读取/下载学院考勤周报；没有提交审核、教师账号管理、学生维护和截止修改权限。其两项个人可选权限由超管或教师管理员逐人开关。
- 开启 `objection.initial_review` 后可读取管理范围异议并初核；初核只改变异议初核状态，不更正考勤。关闭后下一请求失去这条管理读取路径。负责人不能凭初核权限终审；`statistics.read` 与周报权限分别判定。

## 志愿者

1. 学生完成绑定且当学期资格有效后取得志愿者执行资格。资格停用会阻止后续执行；已有历史按原归属读取，不应把历史提交误认为现任执行者的材料。
2. 读取本人受派任务及可见的名单快照。对本人当前受派发起调班申请，并查看本人申请状态；通过申请后等待管理者另行改派。
3. 按任务要求上传受限材料，提交正常或异常结果。异常提交至少含一名当前名单学生及异常类型；文件需为本人、对应类别、`READY` 且未过期。本人提交历史可查；审核通过后形成正式考勤，驳回的提交仍保留。

## 学生

1. 首次微信登录如提示 `need_binding`，凭学号与一次性绑定码完成本人绑定。绑定码由有权限的管理者线下核验后签发；换绑/解绑会撤销旧会话。
2. 查看本人考勤与版本。对本人考勤在配置的异议窗口内提出异议，可关联本人未过期的证明材料；同一考勤未完成异议不能重复创建。
3. 查看本人异议进度与结果。初核不会修改考勤；终审驳回保留原认定，终审通过且需改判时追加新的考勤认定版本。未完成异议引用的证明材料暂缓到期清理，关闭后重新纳入保留期规则。

## 排班结果怎样解释

`POST /api/v1/assignments/auto` 返回目标数、成功数、未分配数，以及每个未分配任务的 `reason_code` 和消息。候选须满足启用志愿者身份、学期资格、本人课表冲突、本班回避；排班器再检查已受派及本轮任务时段、可配置日/周上限。静态无候选时记录确定性的一个拒绝原因；存在候选但无法排入时，记录动态约束的一个原因。这个字段不是每位候选人的全量诊断，也不表示算法找到全局最优。日上限的公开码为 `DAY_TASK_CAP`；内部规划器码 `DAY_CAP_EXCEEDED` 在响应前转换。取消或已受派任务在自动目标查询时被过滤，任务/候选输入在提交前变化则整批报冲突重试。详见 [排班规则](./SCHEDULING_RULES.md) 和 [API_CONTRACT.md](./API_CONTRACT.md) 附录 C。

## 统计、周报与运行边界

- 正式考勤统计只取审核通过且未取消任务的当前有效考勤，待审核异常不算正式缺勤；无有效分母时比率为 `null`。班级按任务名单快照聚合，无法推导的人工总人数调整不强行分摊班级比例。
- 未完成清单区分“当前无审核通过提交”与“截止时逾期未执行”两个指标；后续补交不能改写既有截止快照。周报版本记录源修订号与规则、模板版本，影响考勤汇总的有效考勤变更或配置更新后提示旧版落后，需要有生成权限者另建版本。周报只含考勤汇总；任务总数、未完成和逾期数量留在独立统计接口。任务新建/取消及逾期结算本身不推进周报源修订。
- 当前 `FILE_STORAGE_BACKEND=local` 的本地文件上传与短时 HMAC 签名访问已实现：签发时按父业务资源归属校验，过期或已清理材料不可再读取。配置值 `object` 仅是占位，`ObjectStorage` 构造时抛 `NotImplementedError`；COS/OSS 接入尚未完成。清理由部署脚本按计划任务触发，API 进程自身不启动清理定时器。备份恢复与负载验收需按真实学校数据规模执行。
- 管理审核读取及管理基础接口已在本地代码落地，综合 MySQL 回归和管理端页面联调仍待完成。学生停用会解绑、撤销相关资格/权限/会话，未来尚未执行且无事实的受派任务回到待重排；历史受派、提交、考勤与截止事实保留。固定格式 Word 模板、真实规模压测、备份恢复与学校环境验收尚未完成。

## 三角色接口联调示例

以下 ID、日期与令牌均为示意，联调时先从列表读取当前 ID 和版本，再按服务端返回值提交。

1. **超级管理员管理教师**：`GET /api/v1/teacher-accounts?page=1&page_size=20` → `POST /api/v1/teacher-accounts`，请求体 `{"username":"teacher01","display_name":"教师甲","initial_password":"示例口令至少八位"}` → 停用前读取目标 `lock_version`，再 `PATCH /api/v1/teacher-accounts/{id}` 提交 `{"status":"DISABLED","lock_version":0}`。教师管理员调用创建接口应被拒绝。
2. **教师管理员审核**：`GET /api/v1/management/submissions?review_status=PENDING&page=1&page_size=20` → `GET /api/v1/management/submissions/{id}` 查看名单版本与照片文件 ID → 需要预览照片时调用 `/api/v1/files/{file_id}/access` → `POST /api/v1/submissions/{id}/review` 提交 `{"decision":"APPROVED"}`。已被另一管理员处理的提交返回 409。
3. **已绑定学生的工作负责人排班**：`GET /api/v1/academic/teaching-classes?administrative_class_id=1` 找教学班 → `GET /api/v1/inspection-course-occurrences?semester_id=1&date_from=2026-09-28&date_to=2026-09-30&teaching_class_ids=101` → 将响应的 `selection_scope`、`selection_revision` 与勾选的 `occurrences` 原样传给 `/api/v1/inspection-tasks/preview` 和 `/generate` → 仅用生成响应中的 `assignable_task_ids` 调用 `/api/v1/assignments/auto`。负责人可用 `/api/v1/reports` 查看学院周报，但默认不能调用管理审核接口。
