## 文件所有权与顺序

1. GPT：`identity/authorization.py`、`role_scope.py`、各业务 Service/Repository、模型和迁移。按“资源学院＋当前动作”过滤，查询、详情、计数、批量写均一致；本人接口保留受派/绑定；未知归属不可作为通配。不得使用全局 Session 隐式过滤。
2. T01：独占新增 `backend/tests/unit/test_scoped_authorization_lifecycle.py`。明确合同见 `tmp/agent-handoffs/20261014-campus-p2-p4/T01-isolation-tests/`；复用既有 SQLite 夹具，补撤权、学院停用、到期、禁用与已有 Service 对象重新校验。源码失败交回 GPT。
3. GPT P2：文件签发按关联任务/异议的学院和动作核验；未绑定/停用不能用旧 token；上传者及本人考勤访问保留。继续查课生成/受派/提交、导入预览确认、导出报表与历史版本、审计及旧管理旁路。跨院复合动作不能拼接。Web 接入包待入口契约稳定后生成。
4. GPT P3：学院/学期版本化时间配置和学院校历；新增发布采用预览修订及事务锁。教学班唯一动态类型；实际课次统一计算。任务生成固化时间/类型/来源配置快照，已生成历史不得用当前配置重算。排班和改派在实际分钟半开区间判断，不按跨院相同节次判断；缺时间拒绝未来排班。
5. GPT P4：成员按组/学期/有效日期管理，允许多组；支援范围明确授权。先授权及组类型/班级范围筛选，后配额抽查，不足整批拒绝不跨类型补齐。冲突匹配具体教学班例外→本人课程类型→组默认；仍检查所有组既有受派与日周上限。预览修订覆盖成员、来源、授权及配置，写入串行锁定学院/学期/任务。
6. 简单执行包：在上述接口定稿后，给单一文件 owner 交付有限 Web API/表单接入、契约同步或明确验收测试。每个包记录真实脏文件哈希，RESULT 和 patch，GPT 独立验收后才 accepted；执行者不能替主模型宣布阶段完成。
