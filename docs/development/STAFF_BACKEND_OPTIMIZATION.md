# 教职工后端可靠性与查询优化

日期：2026-10-18。实施基线：`dev-main / b7e0ca1`。本文记录本地代码与验证，不表示已经提交、推送或部署。

## 业务目标与兼容边界

教职工应能够可靠核销工号绑定码，快速读取本人课程和责任区考勤，并导出与页面一致的记录。
本次不修改微信小程序或管理端页面，不增加角色，不改变任职有效期、学院范围、名单快照或写入版本规则。
账号仍由微信登录创建或复用，教职工绑定关联当前账号；不预建第二个账号、不按姓名合并账号。

没有更改默认学期/日期筛选，也没有增加拒绝整学期查询的限制。没有新增数据库索引、迁移、缓存或队列。
现有迁移 head 为 `f26a1018s006`，本次未执行数据库迁移或写入真实业务库。

## 本次实现

### 绑定可靠性

`identity/staff_binding.py`：

- 核销结合工号定位档案，不再要求短码摘要在全表只能命中一行；不同档案使用相同随机短码不会导致多结果异常。
- 历史失效重复码不遮蔽唯一有效码；若仍有多个有效匹配则返回 422，不猜测关联对象。
- 签发时在档案行锁内检查该档案历史短码，重复则重新生成，最多 8 次，耗尽返回 409。
- 保留此前已签发的其他有效短码，不暗中改变多凭证有效期规则。
- 核销采用账号→档案→凭证锁序，作废也先锁档案再锁凭证；持锁后重新核验工号、状态、过期、账号关联及学院有效性。
- 绑定结果、档案版本和审计保持同事务提交，不因绑定获得学院管理权限。

### 考勤卡片、明细与汇总

`inspection/staff_record_query.py` 与 `inspection/staff_record_scope.py`：

- 卡片先按授权分页，再批量读取正式考勤状态、待审核状态和各类人数，不逐卡片发起人数查询。
- 新增可跨任务使用的学生可见 SQL 谓词，复用原有授课关系授权和冻结教学班归属。
- 卡片人数、明细、汇总和导出使用当前名单版本及相同的学生可见范围。
- 汇总由 SQL 按学院与考勤类型聚合，不再将全部任务和学生明细加载到 Python 后逐条累加。
- 合班任务仅呈现本人可见学生；历史缺归属学生保留既有只读边界。读取不产生更正权限，更正仍执行原写服务的完整归属/版本检查。
- 未形成考勤、待审核、取消状态继续与已认定零人区分；责任区统计继续按名单中的班级快照计算，不使用当前学籍推断历史。

### 导出

`inspection/staff_record_query.py` 与 `report/staff_export.py`：

- 在 SQL 中先限定当前名单版本和可见学生，避免读取历史名单后再丢弃。
- 每批读取 500 行标量，不累计全量考勤/名单 ORM 对象及明细列表。
- 使用 write-only 工作簿，避免保留全部单元格；数据暂存内存超过 1 MiB 后自动转入临时文件，退出上下文时清理。
- 暂存期间累计列宽，再写入表头与数据，保留中文列名、学号前导零、版本数值及表格样式。
- 最终 XLSX 响应仍是字节文件，不把此实现描述成全链路零内存导出；超大导出的队列化需实际使用量证明后另行设计。

### 正式课次日历

`academic/occurrence_location.py`：

- 继续按正式课表、校历、作息和逐日授课关系解析可见课次，并保持最长 31 天的原有规则。
- 解析后先分页，仅加载当前页课次对应的地点覆盖与候选任务。
- 对已有课次键快照进行精确 JSON 匹配，保留共享课次对其他视图任务的关联。
- 对缺快照的历史任务批量读取来源，消除逐任务来源查询。
- 区分 MySQL 的 SQL NULL、JSON null 和空数组，保留历史回退；数字形式的共享课次键不强行转换为超出 BIGINT 的历史课表 ID。

### 身份契约

`identity/router.py` 与 `identity/schemas.py`：`GET /me` 显式声明 `{data, requestId}` 响应模型，使已有 `app_context` 出现在 OpenAPI 中。实际字段和旧绑定标志值保持兼容，未新增 `identity_state`。

文档明确 `need_binding` / `binding_required` 保留旧学生流程语义；教职工可用身份读取 `/me.app_context`。没有任课或责任区的有效档案仍是教职工。学生、纯教职工、双身份及管理员均有 HTTP 兼容回归。

[API 契约](../API_CONTRACT.md)及 [OpenAPI](../openapi.json)已同步。核对路由索引仍为 330 个路径、391 个操作，本次无新增路由。
