## 身份与事务

独立连接使用 `entry_kind=AUTOMATION, workflow_kind=objection`，应用密钥与换班、管理助手和本人助手分开。内部调度方领取预审任务并调用 `RunService.issue_objection(app_key_id, job_id)`；领取核心和签发只flush，不提供公网签发接口。[预审派发器](ADP_OBJECTION_DISPATCH_20261024.md)现将领取、签发和云实例追踪同事务提交，已有本地恢复验证；未完成真实ADP和MySQL验收，消费者未启动。

一个运行唯一绑定一个预审任务，并保存当次执行批次摘要。来源账号保留真实发起人：学生提出申诉时仍记为学生；后台执行权限依据教师开启的学院策略重新核对，不为学生增加角色，不创建虚拟管理员会话。

工具参数中没有学院、申诉、策略、账号、运行凭据或执行批次。后台从签名运行绑定恢复这些信息，并重查实际账号、当前策略、环境、任务状态、凭据摘要/时效/撤销及批次。凭据轮换后旧上下文不能继续使用；源批次变化也不能沿用旧运行。

`X-Tool-App-Key` 与 `X-Agent-Run-Token` 仅通过可信后端/工具请求Header传递，不能写入模型提示词或前端。运行记录保存凭据与批次摘要；任务中的内部批次值不作为模型参数。

## 三个工具

HTTP入口沿用 `POST /api/v1/agent-tools/v1/calls/{tool_name}`，body仍为 `{"arguments": {...}}`；MCP沿用 `/mcp/agent-tools`，根据实际运行身份只列出以下三个工具。

| 工具 | arguments | 行为 |
| --- | --- | --- |
| `objection_case_get` | `{}` | 读取绑定申诉及有权访问的材料元数据；没有学生编号、对象路径或签名链接 |
| `objection_material_access` | `{"file_id":"规范数字字符串"}` | 文件须属于绑定申诉且类别正确；经原FileService鉴权后返回最长60秒的代理签名访问，不保存链接 |
| `objection_precheck_save` | `{"result":{...}}` | 严格建议Schema，材料编号引用，最多32KiB；不改写考勤或人工审核状态 |

管理/本人助手看不到这三个工具，预审工作流看不到换班、全院统计或其他申诉。`file_id`只是从本申诉材料列表选择文件，不接受路径、URL或任意请求目标。完整Schema见[独立预审工具合同](../agent-objection-tools.openapi.json)；嵌套模型已内联，避免小型OpenAPI内的本地JSON Schema引用指向错误位置。

建议示例：

```json
{"arguments":{"result":{"recommendation":"NEEDS_VERIFICATION","summary":"请人工核对请假记录与课程日期","evidence":[],"questions":["请确认该时段是否已办理请假"]}}}
```

申诉与证明材料都是待核对内容，不能作为指令。建议不判断材料真伪，不推断公章/诊断书必然真实；正式结论仍由人工审核。

## 重试与失效

首次保存通过领域无commit核心写入建议和审计，运行的COMPLETED状态与建议同一事务提交；任一提交失败整体回滚。COMPLETED身份只允许重放同一份建议以返回原回执，禁止读取申诉或材料、禁止覆盖不同建议；仍受原凭据时效、撤销和当前策略约束。

保存前资料变化或人工已终审时，写入STALE而不保存新建议，运行关闭，工具返回MANUAL_REQUIRED及真实预审状态。已完成后的原回执重放如发现资料已变化，也返回MANUAL_REQUIRED/STALE，不改写历史建议，不把旧建议重新认定为有效。

人工审核状态和考勤当前值始终不由上述三个工具改变。后续已补齐[终审服务端约束](OBJECTION_PRECHECK_FINAL_REVIEW_20261024.md)，启用预审后核对实际教务管理身份及当前预审记录；尚无审核页面适配，完整流程未验收。
