# Web 换班申请工作台

## 当前边界

本地候选，尚未提交、推送或部署。保留同工作区的“执行异常”增补。本轮仅后端与Web，小程序原申请入口/协议继续兼容。

入口：查课安排 → 换班申请，URL `/dashboard/inspections?tab=change-requests&workspace_id={cid}`。具备当前学院 `assignment.change_review` 才显示；改派还需要 `assignment.manage`，没有该权限时可驳回，不能承诺改派成功。

## 页面和操作

- 默认当前学院、当前学期“待处理”，覆盖该学期所有周次，不受顶部当前周限制；可切换已通过、已驳回和全部记录。服务器每页50条，最新申请在前。
- 列表直接展示申请人姓名/学号、课程、班级、日期时段、教室、申请说明、申请时间，以及处理人/时间/意见。姓名缺失显示未登记，不以用户UID替代姓名。
- 点击“处理申请”，重新读取任务和候选人员，核对仍是该申请对应的当前受派。选择顶班人员、可选填写意见，点击“同意并改派”；驳回保留原受派。没有顶班人员时可暂不处理，不提供只通过却不改派的按钮。
- 组任务共用现有 `confirmGroupAssignment` 预览与确认，普通兼容任务共用现有 assignment API。资格、本班回避、本人课程/其他任务冲突、负载上限及已确认软规则仍由原后端执行，页面不另写排班算法。
- 失效受派、已取消/删除、异常、已有提交及归档任务显示不可处理原因；历史结果保留。已有异常任务应先按异常恢复流程恢复，再评估换班。
- 账号/学院/学期/授权版本切换会清空旧列表和弹窗；迟到响应不得回填新工作区。组计划确认同时检查弹窗上下文，关闭或切换页面后旧预览不得继续自动提交。

## 后端及并发

沿用 `GET /api/v1/assignment-change-requests` 及学院路径；新增可选 `semester_id`，管理状态筛选限定PENDING/APPROVED/REJECTED。范围、状态、学期均在COUNT和LIMIT之前过滤。分页后最多三次批量查询补齐任务、关联人员和提交状态，不逐申请取名单/照片。

列表 `items` 在既有字段上新增：`requester_name/requester_student_no/processor_name/semester_id/inspection_date/course_name/class_name/classroom/start_period/end_period/time_snapshot/activity_start_at/activity_end_at/can_process/blocked_reason`。复用标准 `data/requestId` 包装，所有ID字符串化。

管理读取以只读范围授权，已归档学期仍可查历史。处理申请仍是写授权；锁顺序为账号/学期→任务→受派→申请，处理后递增任务 `lock_version`，审计记录版本。另一管理员的驳回将使旧改派预览失效，避免预览在申请已处理后继续使用。列表的 `can_process` 只用于提示，写入仍有服务端校验。

无新增角色、权限、表或页面专属迁移。与当前未发布异常增补一起发布时，仍必须先验证并应用其 `f26a1023x001` 迁移，不能据此认定整个工作区无需迁移。
