# 管理助手排队与模型调用限流

日期：2026-10-25。分支：`future/agent-dev`。本地候选，默认关闭，未部署。

## 调用链与职责

登录发送接口只保存 `QUEUED` 轮次并返回快照；浏览器通过会话 GET 查看后续状态。独立 `chat_worker` 按轮次编号 FIFO 领取、复核真实登录及原业务范围、轮换工具凭据，再调用 ADP。调用结束另开事务保存受尝试令牌约束的回执。模型请求期间不持有数据库会话或容量锁。

排队直接复用 `agent_turn`，没有再创建代表同一对话的 `AgentTask/AgentJob`。模型调用工具提交的报表／资料核对仍使用原读取任务队列。聊天消费者与读取消费者分别运行，避免模型等待子任务时占住唯一读取执行通道。后台换班／预审仍使用原独立派发器及其容量配置。

队列不决定角色和学院权限。进入队列、领取、保存结果及查询时继续复用原会话和业务权限校验。等待期间没有可用工具凭据；真正领取时才轮换并绑定90秒发送期限。成功、失败、未知结果均收回本轮凭据，已登记读取任务继续受真实来源登录与当前权限约束。

## 容量与恢复

`AGENT_CHAT_QUEUE_LIMITS` 为严格 JSON：

```json
{"max_active": 1, "max_queued": 100, "max_wait_seconds": 600}
```

作用域是数据库、环境和 MANAGEMENT 工具应用标识；不是全腾讯云账号配额。并发范围1—10，等待数1—1000，最长等待30—3600秒。每会话仍最多100轮，同时仅一个排队或发送轮次。容量满返回429，客户端保留请求键并适度退避；已登记请求同键同内容仍返回原轮次。

| 状态 | 行为 |
| --- | --- |
| QUEUED | 无云端请求；排队超时后 FAILED / CHAT_QUEUE_EXPIRED，会话可继续 |
| SENDING | 已持久化唯一发送尝试；计入并发，截止前允许唯一回执 |
| SUCCEEDED / FAILED | 正式结果／明确失败；释放并发名额 |
| UNCERTAIN | 网络结果不明或发送过期；保留名额、冻结原会话、不自动重发 |

未知调用不能靠新建会话或重启消费者释放配额。实际远端查证、取消和恢复名额的受控流程尚未接通；未知名额占满时应保持暂停并人工查证，不能直接改表清空或提高并发掩盖。云配置暂停时消费者不领取，已排队记录仍保留；恢复后处理到期记录。业务日期按请求入队时间及系统配置时区计算，跨午夜等待不将“今天”静默换成执行日。

MySQL 用专用连接上的短 `GET_LOCK` 协调准入／领取，容量计数在该连接查询，避免另一 ORM 事务的旧快照。状态提交后在同一连接释放锁，释放不确定则丢弃连接。依据 [MySQL 官方锁文档](https://dev.mysql.com/doc/refman/8.4/en/locking-functions.html)，命名锁属于数据库会话，提交不会自动释放；这里只支持同一 MySQL 实例，不能据此宣称跨实例协调。SQLite 退化为进程内锁，仅适用于本地开发测试。

## 迁移、运行和回退

候选迁移 `f26a1025a011`，前驱 `f26a1025a010`：扩展轮次状态约束，增加轮次队列及会话池索引，不新增容量表。存在 QUEUED 时降级在任何 DDL 前拒绝。上线前需先在隔离真实 MySQL 验证迁移、两消费者竞争、撤权和崩溃恢复；SQLite 与离线 DDL 不能代替该门禁。

仅在迁移、实际腾讯云 Header／日志隔离和配置验收通过、获得部署授权后，分别运行：

```bash
python -m app.modules.agent.chat_worker
python -m app.modules.agent.worker
```

两者都有 `--once` 单次模式。聊天需要 `AGENT_WORKER_ENABLED`、工具／ADP开关、管理对话配置与已验证 Header 门禁。读取任务消费者不调用模型。systemd 样例 `deploy/production/course-agent-chat-worker.service` 和原读取服务分开，当前未安装或启动。

回退先停新入口与领取，核对在途和未知调用。优先回退代码并保留历史，不清表；需回到 a010 时先确认无 QUEUED，再执行受保护降级。API存活不表示消费者已运行，也不表示真实云端闭环已经验收。
