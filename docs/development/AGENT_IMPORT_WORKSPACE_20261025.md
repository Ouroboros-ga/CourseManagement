# 智能资料导入：持久原件工作区

日期：2026-10-25。分支：`future/agent-dev`。前后端候选，默认关闭，未部署。

## 当前业务链

本批接通“登录上传ZIP／Excel／CSV原件 → 私有存储及数据库排队回执 → 独立消费者 → [固定整理子进程](AGENT_IMPORT_INSPECTION_20261025.md) → 保存清单与问题 → 本人查询／取消”。整理成功为 `READY`，表示来源清单可查看，不表示创建预览或写入正式教务资料。

已补管理端“资料工作区”及原件到原预览的交接：添加资料、查看后台状态、继续核对；清单按类型分组，每组最多100份，未知类型由人选择，已识别类型不允许切换解析器。教学班／课程类型使用原核对页设置，之后复用原变化预览、冲突处理与人工确认。上传原件不用先发送自然语言，也不会把原件送往ADP。当前没有新增模型工具或自动审批通路，工具合同保持9项。

## 最小数据与身份

只新增 `agent_import_workspace` 一张表；工作区记录本身承载整理队列，不再为同一原件创建第二套AgentTask／AgentJob生命周期。原件复用 `FileObject` 和既有本地／对象存储适配器；真实用户、来源登录、学院、学期、环境和应用绑定复用 `AgentRun`。

每份原件保存一次规范请求标识、输入摘要、原导入授权摘要、状态、结构化清单、错误分类、尝试计数／令牌、租约及24小时工作区访问期限。运行凭据创建后立即失效，原文丢弃，浏览器和模型都拿不到该凭据。

入口、存储完成后、领取、发布和读取均回查真实登录及原 `import.execute` 写范围，纳入学院配置修订和学期状态；仅当前有效学期可添加。类型识别不授予具体类型管理能力，后续原解析／确认仍需其组合权限。工作区仅对原上传账号和原来源登录开放；换学院／学期、其他登录或用户不能凭编号访问。

原件对象键由服务端随机生成，使用保留私有前缀 `private-import/`，上传名仅作元数据。通用文件访问明确拒绝此类原件，不能绕过工作区来源登录生成签名下载链接，关闭助手开关也不会恢复通用访问。对外响应不包含FileObject编号、对象键、AgentRun编号、运行凭据或存储链接。

## 登录接口

路径仅在 `AGENT_TOOLS_ENABLED=true` 且 `AGENT_IMPORT_WORKSPACE_ENABLED=true` 挂载，并有运行时关闭检查。沿用原Bearer与来源Session依赖；成功响应 `Cache-Control: private, no-store`。

| 操作 | 输入 | 返回 |
| --- | --- | --- |
| POST `/api/v1/assistant/management/imports` | multipart：`college_id`、`semester_id`、`request_key`、单个`file` | 工作区编号、QUEUED及当前元数据 |
| GET `/api/v1/assistant/management/imports/{id}` | 当前学院、学期query | 当前状态；READY时返回经校验清单 |
| POST `/api/v1/assistant/management/imports/{id}/cancel` | JSON：当前学院、学期 | 当前回执；仅取消QUEUED／PROCESSING，已完成状态不倒退 |
| GET `/api/v1/assistant/management/imports/by-request/{request_key}` | 当前学院、学期query | 仅查询本来源登录的上传回执，刷新页面后核对未知结果，不自动重传 |
| POST `/api/v1/assistant/management/imports/{id}/previews` | 当前学院／学期、target、member_nos、request_key；可选教学班／课程类型 | PREVIEW_QUEUED与分组回执；只排队，不在请求中解析或保存正式资料 |

取消也适用于PREVIEW_QUEUED／PREVIEW_PROCESSING，回执同步标记CANCELED并撤销尝试令牌。已完成原预览与更早成功分组保留。

上传ID为规范正BIGINT字符串；拒绝额外或重复multipart字段。客户端不能提交用户、角色、应用、工具、存储路径或来源运行。请求键1—64位字母、数字、下划线或连字符，统一小写；同来源登录、同键、同学院／学期／文件名／内容摘要返回原回执，变更资料409，不重复存储或建运行。明确发起另一份资料需新键。

当前每账号同时有效的24小时工作区最多20份，取消不绕过原件容量约束；输入沿用ZIP 50 MiB、单表格10 MiB等原预算。入口从管理对话配置中读取本环境MANAGEMENT工具应用标识，仅用于绑定身份；这条固定整理链不调用ADP，不要求ADP在线，也不向云端传原件。

## 事务、执行和恢复

- 上传先做授权及幂等预检，再释放事务执行存储I/O；存储后按用户行串行复核授权、配额和同键请求。FileObject、运行、工作区和审计同事务登记。
- 失败且尚未尝试提交时清理本次未引用对象。提交结果不确定时保留随机对象，避免删除可能已被数据库引用的原件；客户端沿用原请求键核对。存储清理失败只记固定日志，孤儿对象对账仍是运维接入门禁。
- 固定消费者按环境／工具应用领取最早队列项，MySQL使用行锁／SKIP LOCKED；领取前核验权限及原件事实。120秒租约、随机尝试令牌，崩溃过期可重领，累计最多3次。明确的存储／解析失败记录FAILED，不无限自动重试。
- 原件存储读取与清单整理子进程不持有数据库会话。字节数及SHA-256必须与原件一致；结果必须通过固定清单协议。发布再次检查权限、来源摘要、文件状态、当前尝试及未过期租约。取消、旧尝试和迟到结果不能覆盖状态。
- 预览阶段复用同一工作区队列，由消费者启动固定 `import_preview_process` 后端子进程。启动门先绑定OS限制，随后才解析和访问数据库：512MiB、45秒CPU、最长60秒墙钟，超时／异常关闭回收。该可信业务执行器需要实际后端数据库配置，通过私有stdin传递，不放命令行、日志、结果文件或模型上下文；与无数据库权限的清单整理子进程职责不同。
- 预览子进程重新核对来源、类型组合权限、教学班与学期，释放工作区领取锁后调用原解析；本组ImportBatch与成功回执同事务提交，提交前以锁定读取再次检查租约与尝试令牌。取消不会等待整个解析持有工作区锁，失效尝试的草稿回滚。原解析增加内部 `commit=False` 选项，默认接口语义不变；该阶段仍需数据库事务及原业务快照锁，真实MySQL锁行为与最重分组预算尚待验收。
- 分组请求键绑定类型、成员和参数；同键重试返回原回执，变参拒绝。前端遇未知响应保留原键，人工重试；后台轮询只读取，不自动重复发起。后台只能生成PREVIEW，正式写入仍由原确认接口重查权限与核对版本。
- 原件保留期沿用现有IMPORT_FILE策略（默认30天）；工作区访问期为24小时。原文件到期清理后不可继续整理或读取结果，不把清理状态当作正常结果。

独立消费者命令：

```bash
python -m app.modules.agent.import_workspace_worker
python -m app.modules.agent.import_workspace_worker --once
```

CLI还要求 `AGENT_WORKER_ENABLED=true`。systemd样例 `deploy/production/course-agent-import-worker.service` 为独立进程组，按父进程＋512MiB解析子进程设置1024MiB预算，未安装或启动。不能放进原384MiB API服务并声称隔离了整组OOM。实际发布前还需核对入口请求体上限与文件／multipart预算，本批没有改Nginx或生产配置。
