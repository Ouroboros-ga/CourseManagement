# 查课执行异常：产品规则、实现与验收

## 已确认需求与范围

志愿者现场发现换教室、停课或无人等情况，可上报统一的“异常”，提交后立即生效，不经管理员审核。复用现有查课安排、任务详情和统计报表；不增加统计页面。本轮改后端和 Web，交付小程序接口说明，不修改或发布小程序。

“异常”描述任务执行情况，不是学生考勤类型。异常任务保留原受派、课次和名单，不生成学生考勤，不算正常完成；当前有效应查和漏查统计排除它，异常次数单列。查课安排的“计划总任务”和受派数仍保留这项计划，不能拿计划总数直接当有效应查分母。

## 状态与历史

- 当前状态优先级：取消 → 异常 → 已完成 → 待审核 → 已逾期 → 待执行。异常报告禁止覆盖任何已存在的提交或考勤，包括已驳回/撤回历史。
- 仅当前有效受派人、有效账号、有效志愿者角色和本学期资格可以上报；沿用普通提交的资格和执行日校验，不允许提前报告未来日期任务。说明选填，最长512字符。
- 上报、管理员恢复均校验任务 `lock_version` 并加任务行锁，审计和报表源修订与修改同事务。归档学期拒绝写入。无新增角色、权限或自动审核。
- 上报后普通提交、排班计划、人工改派、换组、任务编辑和新调班申请被阻止；管理员恢复后才能继续。原受派保留，既有排班占用/负载约束保持不变，恢复不隐式改派。
- 截止前上报且截止时仍异常，截止快照结果为 `EXCEPTION`。截止后上报先结算原截止事实，已有 `OVERDUE_UNEXECUTED` 不改写，但当前统计不再列作漏查。
- 误报由具有本任务学院 `inspection.cancel` 权限的管理员恢复，保留上报/恢复审计和既有截止快照；恢复后按真实截止时间重新派生当前态，可能为“已逾期”。恢复不等于正常完成。
- 取消、删除继续走原业务。异常不取消课程本身，也不改变其他同课次任务、学生正式忙碌或历史报告版本。

## 后端与 Web

结果提交和异常上报复用实时身份、受派、资格校验。SQL 和详情装配同时派生异常，筛选在分页前完成；统计共享原学院/类型/班级/时间范围条件。

Web 原任务页增加异常筛选与次数提示；详情显示上报人、时间、说明和“恢复查课”，异常态不重复标红逾期，也不展示改派按钮。恢复确认途中切换学院/账号/任务会丢弃旧上下文操作。原统计报表显示异常次数；教工记录接口额外返回 `attendance_state=EXCEPTION`。
