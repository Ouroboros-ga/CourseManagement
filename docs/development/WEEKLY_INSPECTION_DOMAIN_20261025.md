# 每周督查排班：策略与业务执行候选

日期：2026-10-25。分支 `future/agent-dev`。默认关闭，未部署。此记录只描述已有领域能力；常驻定时器、登录API、管理页面和腾讯云工作流仍需继续实施。

## 本批实现

产品仍为“每周生成草案、人工发布”。新增 `weekly_inspection_plan` 与 `weekly_inspection_execution` 两张业务表；执行记录保存本周期事实，不再复制一套AgentTask／AgentJob队列。

计划明确学院、学期、执行组、班级配额、课程类型、有效教学周、每周运行日／时刻、拍照要求及实际负责人。每班1—50次、合计最多500次；没有硬编码每班三次。计划只能使用 `DRAFT_ONLY` 模式，不能由模型或客户端提交负责人、角色或自动发布模式。

首期时间语义为 **Asia/Shanghai，在指定星期／时刻生成下一个教学周**，教学周起点复用学期 `first_monday`，具体课次继续服从原校历、执行组和课程规则。到期后可在目标周开始前恢复；目标周已开始则记录MISSED，不自动补写过去课次；授权前已经开始的周不会伪造成计划漏跑记录。这里不是通用cron表达式或用户可执行脚本。

## 身份与版本

- 保存和执行复用 `inspection.generate`、`assignment.manage` 及实际 ResourceScope，不给“教师角色”无条件全院权限。执行组范围授权仍被限定在原类型／班级边界；教学班限定授权不能被扩展成按类型覆盖任意教学班的周期计划。
- 负责人来自真实保存操作者。后台每次重新读取账号状态、实际角色和当前授权，不创建机器人管理员，也不依赖原网页保持在线。
- 计划修改／暂停递增版本，执行记录保留原配置和负责人。暂停、负责人停用或撤权、发布的组规则改变、教学周起点改变均会阻止旧执行继续写入。核对授权与取得策略锁之间发生版本变化时要求重读，不能用旧负责人的权限执行新计划。
- 每个环境／学院／组／学期只有一份策略；每份策略的目标教学周只有一个执行记录，策略修改不重建同周身份或覆盖已生成课次。旧周期需要修复时保留事实，交人工核对，不默默重抽。

## 原业务复用及事务

| 阶段 | 已有入口 | 提交结果 |
| --- | --- | --- |
| 保存／暂停 | `WeeklyInspectionService.save/pause` | 策略版本、实际负责人、审计同事务 |
| 到期登记 | `register_due(plan_id)` | 固定目标周、日期、运行时间与配置快照；同周去重 |
| 精确生成 | `generate(execution_id)` | 原课次、名单快照、截止记录、原审计与周执行回执一起提交 |
| 人员草案 | `prepare(execution_id)` | 原排班计划与周执行回执一起提交；不创建受派 |
| 人工重新核对 | `refresh_draft(actor, execution_id)` | 固定复用原task_ids，重查当前权限和人员，替换未发布草案；保留旧记录及审计 |

任务生成新增内部 `GroupSamplingService.generate_in_transaction` 和 `_materialize(commit=False)`。原公开生成入口仍自行一次提交。新增可选 `course_type_ids` 精确过滤，明确选择时拒绝组外／停用类型，缺额不借其他类型补足；未传时保留原按组筛选行为。

生成阶段失败会回滚整批课次、名单、截止与回执。人员草案阶段失败只回滚本次草案，已成功生成的任务保留，重试复用原task_ids；候选不足由原排班器给出未安排原因和警告，不伪造安排成功。

若所抽课次已被人工受派，当前原排班器会拒绝自动覆盖；已有任务保留。混合已受派／未受派课次的自动拆分和对应覆盖摘要尚待后续调度接入补齐。

原人员确认草案有效期10分钟。过期时后台prepare明确要求人工重新核对；重核只处理固定课次，不重新抽课。新旧草案替换和旧草案失效同事务完成，旧页面不能再发布旧草案；如果原草案已由人发布，返回原发布回执而不创建新草案。正式发布继续走原AssignmentPlanService的修订、资格、冲突、警告确认和提交事务。

## 迁移与关闭
