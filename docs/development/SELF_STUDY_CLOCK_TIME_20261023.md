# 普通课节次与自习独立时段修复

## 已确认的业务边界

- 普通课仍使用学校真实教学节次。第1节08:10上课，不给早自习重新编号，也不移动普通课编号。
- 早晚自习按课程类型、行政班、周次、星期、起止时间和教室批量生成。界面先预览确认，再保存。
- 教学班、名单、校历、实际课次、执行组、查课任务、考勤与排班规则继续共用；时间来源分为 `PERIODS` 与 `CLOCK`。
- 自习的内部单时间槽仅为复用已有时间解析器，不是学校第1节；Web与API按实际时刻显示。
- 同一班级、星期、周次的重复生成幂等；已存在不同时间时拒绝隐式覆盖/叠加。先在正式课表明确处置原排期，再生成。修改作息方案仍走已有版本预览与发布，历史任务保留快照。
- 不自动删除截图中的旧第13节，不改已有普通课、人员、任务、考勤或个人课表。

## API与小程序交接

`POST /api/v1/colleges/{cid}/academic/teaching-classes/batch-self-study` 新调用示例：

```json
{"semester_id":"1","study_type":"EARLY","class_ids":["101"],"weeks":[1,2],"weekdays":[1,2,3,4,5],"start_time":"07:30","end_time":"07:50","default_classroom":"A101"}
```

不要同时提交 `start_period/end_period` 和 `start_time/end_time`。人员、班级和学期ID继续用字符串传输。

时间响应新增兼容字段：`time_basis: "PERIODS" | "CLOCK"`、`time_label`（例如 `07:30—07:50`）。任务详情与排班预览在 `time_snapshot` 中包含同样字段；教工查课卡片、课次与正式课表直接提供字段。考勤任务摘要及分组也提供字段。

小程序：若 `time_basis === "CLOCK"`，显示 `time_label`，不能将内部 `start_period=1` 画作普通课第1节；普通课保留原节次显示。`starts_at/ends_at` 仍是带UTC偏移的绝对时间，客户端按北京时间格式化。本轮不修改或发布小程序代码，需开发者按此字段适配并真机验证。
