# 管理端预审意见与终审表单

日期：2026-10-24。状态：本地候选，未提交、部署或开启。入口为“考勤与异议→学生异议”；教工本人责任区复用同一组件。后端合同见[终审衔接](OBJECTION_PRECHECK_FINAL_REVIEW_20261024.md)。学院策略开关页面和学生本人进度尚未接入。

## 本次实现

`/api/v1/me/campus-runtime` 增加只读 `objection_precheck` 布尔值，只报告功能是否启用，不返回连接或凭据。标记关闭时维持原审核交互，不发起预审请求；开启后预审读取失败会阻止提交，不根据404或网络失败推定功能关闭。

`ObjectionPrecheckCard` 展示尚未预审、等待、进行中、完成、失败和资料失效。仅展示当前有效建议、材料编号/页码/依据、待核验问题；按原材料入口查看附件。状态与正式审核结果分开，AI建议不替代最终决定。

状态读取和重试由 `useObjectionPrecheck` 管理。重试携带所见 `expected_job_id`，不重复点击、不自动重发；请求失败时清除旧状态，要求显式刷新核对。刷新清除确认；切换账号、学院、学期、权限版本、申诉或卸载组件后，旧请求不得回写，人工原因一并清空。责任区读取使用响应中的实际负责学院。

正式表单须勾选“已核对当前预审状态与原始材料”，提交所见 `precheck_job_id`。服务端要求人工例外时另填原因，不能用普通审核备注代替。进行中、无权、读取失败或未确认时禁止提交。409后保留正式判定和备注供核对，但刷新预审并清除旧确认，不自动提交决定。

损坏或缺少的建议不能显示为正常成功建议；服务端明确要求人工核验的异常结果不展示原始坏数据，保留人工原因流程。普通教工不能通过该表单获得教务终审权限，后端仍逐次复核。
