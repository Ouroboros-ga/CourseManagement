# 腾讯云ADP换班工作流接入候选

日期：2026-10-24。状态：本地SDK适配器与工作流配置规格，未创建/发布真实云端应用，未向腾讯云发送业务运行或凭据。

## 采用的接口版本

使用官方Python产品SDK `tencentcloud-sdk-python-adp==3.1.190`及common同版本，固定`adp.v20260520`。SDK负责TC3签名，固定HTTPS端点，不提供由用户输入云API地址的入口。原有依赖版本未升级。

创建使用`CreateWorkflowRun`，对应应用需为单工作流模式；字段为`AppId`、`Domain`、`Query`、`CustomVariableList`及`UserId`。`Domain`的1/2分别对应开发/生产，不能套用旧版LKE的`AppBizId/RunEnv`。依据：[新版创建接口](https://cloud.tencent.com/document/api/1759/139333)。

查询读取`WorkflowRun.WorkflowRunSummary`下的实例归属和状态；状态1—5映射排队、运行、成功、失败、取消。未知状态、旧字段、应用/实例/环境不一致均拒绝；不把云端成功直接解释为改派成功。依据：[新版查询接口](https://cloud.tencent.com/document/api/1759/139330)、[数据结构](https://cloud.tencent.com/document/api/1759/132545)。

## 云端应用与节点配置规格

创建一个后台换班单工作流应用。此流程执行已授权的小任务，不开放自由对话和任意工具选择，也不添加用于决定正式改派的LLM节点。复杂交互助手仍按总体架构独立建设。

| 节点 | 输入与固定配置 | 输出/下一步 |
| --- | --- | --- |
| 开始 | API参数`agent_run_token`，仅由可信后端传入；不从用户文本抽取 | 进入准备方案 |
| 准备方案：HTTP工具 | POST固定网关`/api/v1/agent-tools/v1/calls/change_prepare`；Body固定`{"arguments":{}}` | 读取`data.data.status` |
| 条件判断 | PREPARED进入执行；SUCCEEDED直接返回已有回执；MANUAL_REQUIRED进入人工结果；其他状态进入异常出口 | 不用自然语言猜测是否允许写入 |
| 实际改派：HTTP工具 | POST固定网关`/api/v1/agent-tools/v1/calls/change_apply`；相同Header，空参数 | 返回原子改派回执 |
| 结束 | 仅投影业务状态、执行编号和回执标识 | 不输出Header、凭据、工作流元数据或完整原始响应 |

两次HTTP工具调用均将`X-Tool-App-Key`绑定到云端受保护环境密钥，将`X-Agent-Run-Token`绑定到API参数；URL由部署配置固定。平台工具节点支持Header参数引用，但实际变量绑定、隔离与脱敏必须用账号验证。依据：[工具节点配置](https://adp.tencent.com/zh/document/216860825579573248)。这张表是人工配置规格，不是可直接导入控制台的官方DSL。

409/403等错误进入异常分支，不能伪造“已换班”或把申请直接改成拒绝。没有候选人时保留原受派与待处理申请。最终是否改派仍以本系统执行回执和受派事实为准。

## 凭据验收门禁

`AGENT_ADP_ENABLED`默认false，`AGENT_ADP_CONFIG`默认null。配置由受保护环境注入，包含app_id、region、domain、secret_id、secret_key，可附临时session_token和最长30秒的正数请求超时。

运行创建另受`header_binding_verified`控制，默认false时在出站前拒绝。该字段是上线门禁，填写true本身不是验证证据。必须验证：

1. 两个并发运行的Header各自取本次API参数，不能变成连接器共享全局值。
2. 运行凭据不进入模型提示词、输出、可见调试日志及历史详情。官方查询结构包含自定义变量元数据，因此必须实际检查其脱敏和访问控制，不能假定变量名会自动保密。
3. 普通客户端没有直接启动此后台应用并注入任意运行凭据的通道；云端UserId只是本地运行编号映射，不是授权。
4. 本系统侧即使已完成入口认证，改派时仍检查当前凭据摘要/有效期/撤销、策略版本及授权人权限。

以上任一项无法满足，不启用此动态凭据方案；继续按总体设计评估“云端输出结构化意图、后端按原任务身份执行”的接入方式，不把token移到Query、工具参数或固定共享MCP Header中绕过门禁。

MCP本地协议与权限已验证，当前官方接入说明支持自定义Header，但尚无逐运行安全绑定的本项目证据。HTTP节点为待联调路径，MCP不能先宣称已通过。依据：[MCP接入说明](https://adp.tencent.com/zh/document/216860848528707584)。

## 本地客户端行为

- `AdpWorkflowClient.from_settings`在开关关闭或缺配置时拒绝创建客户端。
- `start_change`使用固定Query，仅在API变量中传本次运行凭据，UserId使用后端生成的不含姓名/学号的运行引用；创建结果只保留实例ID及请求ID。
- SDK固定`NoopRetryer`，创建只尝试一次。网络/内部异常或缺失创建回执标记`ambiguous=true`且不声明可自动重试，后续派发器不得据此直接重建云实例。明确鉴权/参数/限额拒绝与结果不确定分开返回；异常文本不透传。
- `describe`只返回受校验的归属、状态和请求ID，丢弃元数据、流程图、自由文本及节点输出。
- `wait`最多10次轮询，默认3次，时间预算最多30秒，按剩余预算缩短下一次请求超时。预算/次数耗尽返回当前快照，不自动取消、不自动新建实例，也不把业务标成失败。这是轮询边界与网络超时控制，不是可强杀所有网络情形的硬执行期限。
- SDK原始请求/响应日志在敏感调用上下文中被过滤，即使应用打开DEBUG也不输出载荷；错误只返回固定代码。
