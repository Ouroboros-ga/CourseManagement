# 统一列表分页与查询链路整改

基线：`ecec959`。本轮为本地开发，不代表已推送、部署或启用生产功能。

## 1. 展示和操作规则

- 正式记录列表统一默认每页 **50 条**，显示当前范围、总数、页码和跳页。窄屏隐藏跳页输入，保留前后翻页。
- 大数据列表在后端授权、筛选、计数后分页。不能只获取前 100/200 条，再在前端搜索并把它当作全部记录。
- 配置目录、已经生成的核对快照、任务名单及报表快照使用同一分页外观，最多渲染 50 行；它们的完整快照仍供核对、统计、导出或整批确认使用。**渲染分页不等于 SQL 分页**。
- 日历网格、编辑作息时段的表单、最多 20 个文件的上传队列、最多 10 条的“最近导入”摘要不按 50 条拆页。下拉选择器采用受限候选查询或完整的小型参考目录，不能只保留前 50 个选项而让其他人员无法选择。
- 任务、学生和审核列表的批量操作限定当前页，翻页清空勾选；审核按钮明确标注“本页”。具体课次选择允许跨页勾选，按稳定课次标识提交完整选择集合；改变筛选条件或发现来源版本变化时清空选择。
- 任务导出使用独立导出查询，导出**完整筛选结果**；不能因页码改变而只导出当前 50 条。统计继续使用完整授权范围，不从当前页人数推导全量统计。

## 2. 页面与取数链路

| 页面/资料 | 本轮处理 | 取数边界 |
| --- | --- | --- |
| 查课任务与排班 | 所有视图统一后端分页；关键字、日期、状态、待处理调班在 SQL 中筛选；稳定日期、ID 排序 | 授权谓词同时进入列表、总数、摘要与导出；原来普通视图最多取 200 条 |
| 具体课次选择 | 每次返回 50 条；保留跨页精确选择及完整抽查范围 | 后端仍按整段校历和正式名单构建一致的选择版本；分页不缩小智能抽查范围 |
| 正式课表 | 默认每页 50 条；普通查询 SQL COUNT/LIMIT；周次先在 SQL 中筛选 | 指定行政班时，仍按日期学籍核算完整候选后分页，不能用当前班级替代历史归属 |
| 考勤、学籍历史、教职工档案、学院基础数据 | 请求和显示数量同步改为 50，统一分页控件 | 保留原有学院/日期学籍/本人范围 SQL 守卫 |
| 任课教师、班主任/辅导员责任区 | 新增兼容的 `paged=true` 模式，后端分页并批量返回人员和班级名称 | 消除前端逐行查班级/拉全体教职工补名字；原数组模式继续兼容 |
| 教工和管理员账号 | 统一 50 条；教工页面显式按角色先筛后分页 | 避免把负责人混入一页后再前端剔除，造成数量和页面不符 |
| 负责人账号与委任候选 | 负责人列表后端分页；候选按关键字远程查找，最多显示 50 位 | 可选权限只读取本页账号，并在 SQL 中再次叠加授权范围 |
| 学生名册与本学期资格 | 每页 50 人；附加资格、绑定账号只批量查询本页学生 | 志愿者总数独立计数；整院资格只在用户明确导出绑定码时读取，不能拿本页资格代替整院导出 |
| 学生异议 | 统一 50 条分页；选中后读取对应考勤详情 | 不再为一页最多 50 条异议并发拉取全部考勤详情；责任区仍使用其已授权响应 |
| 提交审核兼容页 | 从“先取前 100 条再筛选”改为 SQL 筛选和分页 | 摘要在 SQL 分组计算；审核明确只处理本页；该兼容组件当前不是主导航入口 |
| 志愿者组织 | 列表和成员显示分页；组织总览使用批量学期摘要 | 不逐组下载完整成员及最多 5000 个教学班参考项；成员详情仍在进入组织后读取 |
| 抽查预览、生成结果、排班结果 | 每页最多渲染 50 条 | 整份不可变预览、精确任务集合和确认版本继续保留；不能只确认可见的一页 |
| 导入核对、人员关联核对 | 改为统一 50 条显示 | 解析、阻断检查和整批确认仍针对完整文件，不把分页当作分批保存 |
| 统计报表与明细抽屉 | 班级/任务/异常/学生卡片分页显示 | 本轮保留按周的完整聚合快照；没有把快照的页面切片冒充数据库分页 |
| 课程类型、删除记录、校历历史、授权来源等配置列表 | 统一的受限渲染分页 | 保持已授权配置集合和原操作上下文，编辑表单不分页 |

## 3. 深层查询整改

1. **账号关联加载**：账号读取只加载其角色，不沿 `Role.users`、`Role.permissions` 反向扩展。会话有效性、停用和有效权限仍逐请求查询，不引入权限缓存。定向用例确认单账号及其角色读取为两次 SQL。
2. **学生列表**：当前页学籍和班级名称批量查询；“已批量查过、该生没有日期学籍”与“尚未查询”分开，不再对无日期学籍的每个学生重复查询。
3. **任务装配**：只取本页日期对应的截止记录和当前版本，不搬运整学期及全部版本历史；列表关闭未使用的名单历史关联加载，班级显示索引限制到本页任务所属学院。关联班级去重后再装配。
4. **列表/计数/摘要共用谓词**：任务过滤抽成同一 SQL 构造器，提交审核同样处理。受限学院和组的计数不能因摘要或导出绕过授权。
5. **组织摘要**：一次读取授权组织，批量解析默认/已确认学期规则，按参考日期 `COUNT(DISTINCT student_id)` 计算有效成员数。学期规则不能被后来修改的默认规则覆盖；不返回成员档案。组织目录本身也批量读取配置，消除 `_dto` 的逐组查询及列表读锁。
6. **显示投影**：授课和责任关系一次批量返回姓名、工号和班级名称；可选权限通过一份批量查询装配，不逐负责人查询。
7. **按需与竞态**：异议详情延迟加载；任务详情取消重复 watcher 请求，独立资料并行读取。分页、筛选、账号/学院变化使旧响应失效，不能用旧响应覆盖新上下文。
8. **显式完整快照**：任务考勤明细、班级学生底册不再静默截断为前 200 人。必要的完整核对使用有界分页读取，检查空页、重复 ID、总数变化及过期上下文；普通列表不能调用此完整快照工具。
9. **GET 无写副作用**：遗留志愿者资格读取不再扫描整学期学生并自动补角色、提交事务。账号与角色开通留在明确的资格维护/绑定写流程，遗留数据修复应明确执行。

## 4. API 增量

- 共用 `page_params` 的默认 `page_size` 从 20 改为 50；单独声明的审核/报表/教工列表默认值同步。原最大值和显式指定的旧页大小仍兼容。
- `GET /inspection-tasks` 及学院别名新增 `keyword`（≤128 字）、`status=NOT_STARTED|OVERDUE|SUBMITTED|REVIEWED|CANCELLED`、`pending_change`。新增 `summary`：`total,assigned,unassigned,reviewed,pending_change,dates`。摘要保留学院、学期/周次、名单和待办范围，忽略关键字、单日、状态及调班筛选；列表 `total` 则遵守全部筛选条件。
- `GET /inspection-tasks/export` 及学院别名返回同一筛选范围的精简导出列，不装配名单、照片或版本历史，忽略页码。
- `GET /management/submissions` 及学院别名新增 `keyword,result=NORMAL|ABNORMAL` 和完整窗口的 `summary`；原 `review_status` 继续适用。
- 学院 `teaching-staff-assignments`、`class-staff-responsibilities` 新增 `paged=true&page=...&page_size=50`；分页响应为 `items,total,page,page_size`，行附加 `staff_no,staff_name,class_name`。未指定 `paged` 仍返回原数组。
- `GET /teacher-accounts` 新增可选 `role_codes`，先按允许的管理角色过滤再计数分页；未传时保留原范围。
- `GET /role-assignment-targets` 及学院别名新增可选 `student_ids`（最多 200 个），以及 `paged=true,keyword,role_code,student_candidates` 模式；分页响应增加 `total,page,page_size`。候选和过滤不能扩大原管理范围。
- `GET /optional-permission-targets` 及学院别名新增可选 `user_ids`（最多 200 个），与原可见范围取交集。
- 志愿者资格列表及学院别名新增可选 `student_ids`（最多 200 个），仅作批量缩小范围，不授权跨学院读取。
- 正式课表列表增加 `page,page_size` 和对应响应元数据。
- `GET /colleges/{cid}/volunteer-groups/semester-overview?semester_id=...&as_of=YYYY-MM-DD` 返回 `items` 字典；每组包含 `configuration,member_count,specific,error`。成员数是参考日有效成员去重计数，**不是最终可排班人数**。
- 学期准备来源接口支持 `include_teaching_classes=false` 省略参考目录；常规复制默认保持兼容。当前组织总览已使用更小的批量摘要接口。

具体路径与参数见 [API 契约](../API_CONTRACT.md)、[索引](../API_INDEX.md) 和 [OpenAPI](../openapi.json)。小程序页面未改动；显式页大小继续有效，省略页大小的客户端应按响应 `total/page/page_size` 翻页。

## 5. 索引和性能边界

- 检查了任务、受派、提交、日期学籍、任职关系的主键、外键及现有索引路径；优先消除全量加载、逐条查询和不必要关系加载。本轮**不增加数据库迁移，不盲目添加索引**。
- 对普通任务页的定向用例：列表 COUNT、当前页和摘要共三次 SQL，读取 105 条样本时每页 50 条，查询次数不按行数增长；不会自动读取名单版本历史。
- 页码跳转仍使用 OFFSET。学院、学期、周次先缩小范围；含 `%关键字%` 的文本检索也不声称能依赖普通 B-tree 索引实现全文检索。
- 正式课次仍需按完整校历/名单构建选择版本；指定行政班的正式课表仍需日期名单核算；报表保留完整的按周聚合快照。它们是本轮明确保留的全量业务计算，不包装成“只计算当前 50 条”。若真实数据下成为热点，应另行度量并优化共同算法。
- 本地 Docker 引擎未运行，未执行 MySQL `EXPLAIN/EXPLAIN ANALYZE`、生产容量测试或线上耗时对比。因此没有线上提速百分比、索引命中率和数据库负载下降的实测结论。部署前可对有代表性的学院/学期只读采集查询计划，再决定是否需要复合索引。

## 6. 验证和发布

- 定向数据库用例覆盖超过一页的数据、后续页搜索、字面 `%/_`、授权范围与总数、精简导出、提交筛选、任职名称投影、日期学籍批量装配、固定学期组织规则和组范围授权；不触碰生产数据库。
- Node 用例覆盖分页边界、过滤复位、完整快照拒绝残缺/重复/过期数据、查询与导出参数一致，以及摘要跨上下文失效。
- Edge/Playwright 在完全模拟 API 的本地页面核对任务翻页、后续页搜索/导出、跨页勾选下发、课表翻页、任职分页、批量组织摘要、学生名册的本页附加查询；不向真实后端写入。
- 结果与构建状态以 [实施状态](IMPLEMENTATION_STATUS.md) 为准。浏览器最初发现新增分页条打断 Vue `v-if/v-else-if` 相邻关系，已修正后通过生产构建与交互检查。
- 新 Web 依赖新增后端过滤、摘要和导出能力，必须作为同一版本发布；回滚也应同时恢复前后端。没有数据库结构变更和生产业务开关变更。
