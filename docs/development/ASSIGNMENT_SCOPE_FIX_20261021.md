用户反馈：2026-10-20；发布：北京时间 2026-10-21 00:00。正式入口为 `https://course.zsitai.xyz`，服务器 `101.34.52.163`。

## 证据和根因

只读查询最近的排班确认计划，未修改任务、成员、资格或受派：

- 反馈中的 2026-10-23 第 5—6 节任务，没有进入最近一次实际确认的自动计划。该自动计划目标 50 项，日期分布为 10月19日46项、10月20日4项。
- 另有一份目标 98 项的自动预览，拟分配 17 项，包含上述任务，且选中了与后来人工计划相同的志愿者；该预览状态为 READY，没有确认提交。
- 原组织模式入口必须先勾选任务；分页后全选仅选择本页50项，而“智能排班”按钮与预览没有清楚表达范围。日期选择器还用本页长度显示“本周全部”。预览只提示未分配数量，未展示逐项原因，容易把缩小范围或没有提交误认为算法无法分配。

## 已实现行为

1. 主按钮“智能排班（筛选全部）”在用户显式触发时，跨页读取当前授权及筛选范围内的未分配任务；每次读取50项，最多500项，包含后续页任务，不在普通列表加载时拉取全量。
2. 独立“排班已选”入口仅使用明确勾选的未分配任务。已受派和取消任务跳过；已有任务的执行组仍由后端校验，不擅自换组。
3. 组织计划确认展示目标总数、日期范围、具体任务/志愿者、警告和逐项未分配原因。清楚说明只有点击“确认并派发”才保存；返回调整、关闭或零分配计划均不提交。
4. 学院、账号、授权修订、学期、筛选或选择在读取/确认中变化，停止旧计划后续提交。跨页总数变化、重复或不完整分页拒绝继续。
5. “本周全部”显示完整范围统计，不再显示本页长度。多组仍逐组确认并独立保存，取消剩余组不抹除已确认结果。

资格、日期学籍、有效成员/支援、本人正式课程、本班回避、任务重叠、日/ISO自然周配额继续由服务端裁决；动态稀缺优先、公平域、时间片/楼簇软评分及一层有界换位继续复用原模块。未分配码是代表原因，不能解释成全体候选同一种拒绝。
