# 学生本人资料与教工查课范围/时区修复

## 反馈与根因

- 学生 `/api/v1/me` 只有账号名称和教工摘要，没有学生资料摘要；不是学生未绑定。增量提供 `student_no/college_name`，以及 `app_context.student` 的学生ID、姓名、学号、当前行政班/学院和学籍状态。只按账号绑定ID取本人，不按姓名、角色或 username 猜配，不增发权限。
- 教工卡片的嵌套 TaskScheduleSource EXISTS 缺少跨层关联：只要教师自己的任意任务有来源映射，该来源就可能误使其他任务卡片可见。学生明细的范围谓词仍正确，因而出现“RECORDED、人数0”却管理端有正式考勤的矛盾。修复显式关联外部 InspectionTask 与 TeachingClass，卡片、详情入口、汇总及导出共用修正后的范围。
- 只读核对反馈任务265：存在21条正式考勤、21条v1名单与来源归属、1次通过提交；当时唯一已绑定教工账号不覆盖该教学班，卡片却错误放行。修复应拒绝不属于该教师的卡片，不能硬补21人或自动创建任职；实际任职仍须由正式导入/配置确认。
- 时间库内为UTC 10:50—12:25，对应北京时间18:50—20:25。旧接口输出没有时区的字符串；修复返回带 `+00:00` 的ISO时刻，并增加小节字段。Web教工页复用北京时间格式化，避免把UTC误作本地时刻或重复转换。

## 兼容与验证

- 学籍采用当前日期时间线；没有时间线的旧学生才允许展示当前档案。已有时间线但当前空缺时学院/班级保持null，不能用未来班级猜补。解绑后下一次 `/me` 摘要为空；纯教工原摘要不变。
- 学生顶层字段是 `app_context.student` 的同源便利字段。未绑定时摘要及字段均null；学院字段只供显示，不授权、不充当学院工作区参数。
- 新增失败回归先复现4种缺陷：越界任务卡片误入、缺少时区、缺少学生摘要与空摘要字段。修复后与现有身份组合、本人范围、合班、统计/导出及批量查询测试共49项通过；前端时间4项及Vue类型/构建通过。未变更现有失败断言制造通过。
- 本轮不修改小程序页面、不补造授课任职、不改写21条考勤、名单或作息快照，不新增迁移。小程序接入说明见 [接口交接](../integration/WECHAT_ME_STAFF_FIX_20261021.md)。
