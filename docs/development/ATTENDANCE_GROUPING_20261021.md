# 考勤结果分组实施方案

目标：默认按具体查课任务汇总，支持行政班汇总与学生明细；先看整体，再读取单次名单及照片。

## 实施边界

- [x] 后端新增同权限的 `/attendance/groups` 及学院别名，按 task / administrative_class 分组，默认50组；计数、当前认定汇总在完整授权和筛选范围内计算。
- [x] 公共过滤支持日期、课程类型、班级历史快照、姓名/学号/课程搜索、认定/仅异常。分组及名单共用查询谓词；未知历史班级单列，不用当前学籍猜补。
- [x] 优先采用正式通过提交的名单版本；无通过提交的遗留考勤回退任务名单版本。名单连接最多一行，避免多版本重复计数。
- [x] Web：AttendanceRecords负责视角和检索；AttendanceGroupTable展示课次/行政班；AttendanceRecordTable复用学生明细；AttendanceRecordDetail保留照片及原归档更正。单次详情按需分页读取，不全量拉取。
- [x] 行政班点开后查看本班各课次，课次点开后展示本次名单和照片；状态筛选明确只统计符合筛选的考勤记录，不伪造应到人数或出勤率。
- [x] 19项后端定向回归覆盖学院范围、历史转班、不同任务不合并、多名单版本、HTTP参数/旧入口拒绝及原照片授权；5项前端用例覆盖筛选与字符串ID传递、分页。类型检查及构建通过，保留既有大chunk提示。
- [x] Edge虚构数据验证61个课次分两页、2个行政班汇总、行政班下钻、单次名单分页、异常筛选、学生姓名检索及详情空照片状态。本地模拟证据位于 `tmp/attendance-grouping-20261021/`；不代表生产名单。
- [x] 同步API资料并成套发布，版本与回退记录见下文。

沿用现有身份、照片授权、当前有效考勤及版本更正。不新增数据库结构、统计报表模型或审核流程，不实现小程序页面。

分组查询使用列投影与SQL聚合，分页前计算完整筛选集合；每页仅补查本页任务执行人。读取学生明细时才装配照片，不把组列表拆成逐组人员或照片请求。班级以历史ID稳定分组，同ID多个历史名称时显示已有快照名称之一；不据此重写快照。无ID资料即使有文字班名，也保留“历史班级待核对”分组，不据文字推断身份。

首次受限测试在HTTP夹具挂起后终止，未算通过；正常权限内存库定向回归通过。首次Web构建发现新表格行键回调缺少类型，修正后类型检查与构建通过。浏览器检查后给课次名单增加固定表头和52vh滚动区域，避免名单撑出弹窗。
