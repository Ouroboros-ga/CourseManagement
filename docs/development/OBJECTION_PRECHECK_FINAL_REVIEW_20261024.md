日期：2026-10-24。状态：服务端本地候选，默认关闭，未提交、部署或启用。[管理意见与终审表单](OBJECTION_PRECHECK_UI_20261024.md)已有本地候选，学院策略页面及小程序尚未适配，不作为完整产品交付。关联：[管理接口](OBJECTION_PRECHECK_MANAGEMENT_API_20261024.md)、[工具与运行身份](OBJECTION_PRECHECK_RUNTIME_20261024.md)。

## 身份与入口

启用 `AGENT_OBJECTION_PRECHECK_ENABLED` 后，最终审核要求数据库中的实际 TEACHER_ADMIN 或 SUPER_ADMIN 身份，并满足现有 `objection.final_review` 动作及任务范围。不新增权限系统或机器人管理员。普通教工和学生负责人仍按已有范围读取；持有历史审核权限或客户端角色标签不能替代实际教务身份。

以下既有入口共同调用原审核事务核心，路径前缀均为 `/api/v1`：

- 学院入口：`POST /colleges/{cid}/objections/{rid}/review`。
- 原管理入口：`POST /objections/{id}/review`，兼容别名 `/final-review`；原入口开关和权限守卫继续生效。
- 教工责任区入口：`POST /me/responsible-objections/{id}/review`；同时满足原责任区与教务终审范围，无关记录仍不可见。

关闭预审功能时保留原审核请求与原角色行为。功能开启后不能只依赖前端隐藏按钮；各入口和共用核心都校验授权上下文。

## 审核条件

| 预审事实 | 服务端行为 |
| --- | --- |
| 当前资料的有效 SUCCEEDED 建议 | 允许教务终审，必须确认当前任务编号；教师可作出与建议不同的正式决定 |
| 当前 QUEUED / RUNNING | 阻止直接终审；填写原因不能跳过正常执行中的任务 |
| FAILED、STALE、建议结构无效或资料已变化 | 人工核验后可终审，必须填写例外原因；也可按重试条件重新预审 |
| 无任务且策略、配置就绪 | 要求先通过管理接口发起预审 |
| 无任务，或从未签发运行身份的 QUEUED，且配置不可用 | 须填写人工核验原因；同事务保留 FAILED / PRECHECK_UNAVAILABLE 记录，不能伪记为预审成功 |
| 已归档、已结案或考勤撤回 | 拒绝写入，按原权限查看历史 |

配置不可用是现有配置门禁判断，不代表检测到实时服务故障。RUNNING 不因配置关闭而直接转成人工结案。

原审核请求新增两项可选字段，但开启预审后有以下业务约束：

- `precheck_job_id`：管理状态接口返回的当前任务编号，规范数字字符串；无任务才可为 null。编号已变化返回 409，须刷新核对。
- `manual_precheck_reason`：人工例外核验原因，去除首尾空白后不能为空，最多 512 字。正常有效建议不强制填写。

原 `decision`、`current_version`、`comment` 等字段及考勤版本冲突约束保持有效。预审确认不是同意 AI 建议，也不代替考勤版本确认。

## 页面合同

管理状态接口增加 `can_final_review`、`manual_reason_required`、`review_block_reason`。页面先读取当前状态和有效建议，再按这些字段展示审核、重试与原因输入。提交携带所见任务编号；409 后重新读取，不能自动替换编号重发审核决定。

责任区列表的 `can_review` 先反映真实身份与原责任区资格；具体预审就绪条件从管理状态接口读取，提交时再次由服务端裁决。共用管理表单已接入这些行为，模拟学院场景已验证；责任区独立浏览器验证待补。

## 事务与迟到结果

授权上下文绑定真实人员、学院任务范围、申诉和当前数据库事务。先校验权限，再按学期→任务→考勤→异议取得源记录锁，之后校验最新预审任务及材料。不能从 HTTP JSON 构造上下文，也不能跨事务复用。

正式审核、必要的失败/失效记录、运行撤销、人工审计、考勤改判版本与报表源修订在同一事务提交；任何一步失败整体回滚。审计记录 AI_ASSISTED 或 MANUAL_FALLBACK、所见任务及人工原因。历史建议保留；失效建议不重新变为有效。

关闭执行写权限不代表云实例已取消。云实例追踪及容量占用仍由派发器管理，不删除历史或假定释放容量。迟到工具调用仍检查撤销和正式审核状态。AI 工具目录没有终审工具。
