## 2. 已实现查询接口及使用边界

```python
teaching_class_condition(user_id: int, *, occurrence_on, as_of: date)
teaching_class_covers_range(user_id: int, *, date_from, date_to, as_of: date)
responsible_class_condition(
    user_id: int, *, administrative_class_id, as_of: date,
    review_college_id=None,
)
```

这些函数返回 SQL 表达式，不执行请求、提交事务、缓存权限或返回全院 ID 列表。`user_id` 必须来自有效服务端会话；`as_of` 必须是服务端 `business_today()`，不能取客户端日期。`occurrence_on` 可以是服务端解析的日期或外层查询日期列。调用方在查询中先加谓词，再计数、分页和导出。

授课谓词的外层实体是 `TeachingClass`。LOCAL 只匹配指定本地班；SHARED 只通过已确认的 `TeachingClass.academic_offering_id` 扩展，并核对共享身份、教师学院及目标学院的学校和学期。课程名、教师姓名、教室都不参与授权匹配。账号、档案、学院、教学班均须有效；关系同时覆盖当前日和该课次日。

`teaching_class_covers_range` 与逐日谓词共用同一套锚点、学院与学期判定，只把“覆盖某一天”换成“与区间相交”，供本人正式课次日历先收窄教学班；日历随后**逐日**再用 `teaching_class_condition` 过滤，因此列表里能出现的课次必定能被 PATCH 修改，任命区间之外的课次不会因为当前仍在任而混入。两处必须是同一实现，不允许出现第二套区间算法。

责任谓词以**任务当时的名单快照行政班**为输入，核对当前有效责任关系及同院行政班。`review_college_id` 省略时仅表达只读班级范围；审核必须传任务真实负责学院并在写服务重新校验。不要将 `None` 当成允许审核外院记录。材料权限另外按文件所属事实检查。

当前谓词只实现本人当前任职范围。离任后的历史只读授权尚未实现，不能用历史关系恢复写权限；后续若产品需要历史只读，新增明确守卫及回归后再接入，不直接放宽这些谓词。

示例只读组合：

```python
query = select(TeachingClass).where(
    teaching_class_condition(
        actor.id, occurrence_on=server_occurrence_date,
        as_of=business_today(),
    )
)
```

这不是完整写授权。事务内的账号/关系锁、归档、课次、考勤版本和材料校验仍不可省略。下一次请求执行新的 SQL 会重读状态；不能据本次局部测试宣称所有 HTTP 或旧会话撤权闭环已经完成。

## 3. 后续写入的固定合同

以下是 T01—T05 必须落实的设计，**本次未实现这些服务或路由**。

### 身份、档案及关系

- 本轮不增加基础 STAFF 角色。`/me` 通过关联的有效档案增量提供模式/视图摘要；普通教工不继承 `TEACHER_ADMIN`、`academic.read` 等全院权限。新增档案管理能力使用学院显式 scope，管理员身份继续走原路径。
- 教工依赖独立于学生 `BindingCompleteDep`。`pre_binding` 的既有学生语义保持兼容；本人教工接口回查档案，受限微信会话仅放行明确身份白名单。
- 教工绑定凭证新增独立表，只存摘要；服务锁定账号、档案、凭证，核对有效期/状态/失败次数并单次原子核销。冲突不按姓名自动合并账号。解绑、停用和撤销必须由下一次服务端请求重新拒绝。
- 所有档案/任命/交接写入都检查当前版本。按固定顺序锁账号、相关学院、档案，再按 ID 排序锁稳定父资源，之后锁关系及业务记录。关系为空时仍锁父行，不能依赖空结果的 `FOR UPDATE` 防重。
- 班级同职责任职重叠禁止；同班不同职责允许。授课一班多教师允许；同一教职工相同锚点重叠重复任命禁止。LOCAL 和 SHARED 同时覆盖同一资源也需在预览提示及写入检查，避免职责来源歧义。
- 接班在一个事务内结束旧关系、建立新关系、审计并提交。日期为半开区间，因此交接日同时是旧结束日和新开始日。导入的无 commit 内部写入单元由既有确认集合统一提交。

### 教师更正与责任区审核

- 将现有考勤版本写入复用为领域事务单元，授权在入口分别完成，不能向普通教工临时拼接全局 `attendance.correct`。
- 教师写入须锁定并复核账号、档案、授课关系、考勤行；`current_version` 过期 409。归档规则、原提交、版本链、操作人及审计保留。统计修订仍属于原任务学院。
- 辅导员审核另外核对责任班级与任务负责学院交集；异议和考勤版本都须检查。教师更正不自动结案待处理异议，复用既有唯一审核状态机。
- 更正、审核共用同一考勤行作为并发锚点。版本、事实、审计和源修订单次提交，失败整体回滚，不能先提交部分更正后失败。

### 指定课次地点

- 正式完整授课日历复用真实课次解析，不能拿可抽查课次集合当作教师课程全集。
- 课次键由服务端生成；共享课程使用已确认的共享 meeting 映射及日期，未确认则本地 schedule/日期，不按名称合并。
- 地点覆盖及不可变变更链单独持久化，不改原始导入。地点修订与任务 `lock_version` 分别命名。
- 地点命令和任务生成消费同一个当前覆盖层；改动时联动未完成任务。完成/取消等任务状态应逐条核对既有状态机，不按笼统字符串推断。已完成任务继续读原快照。
- 地点修订进入课次选择摘要，旧生成预览返回过期冲突；共享映射/时间不一致先拒绝，不盲目跨视图修改。
- 来源查询、排班/任务生成和地点变更需约定同一个稳定课次锁；真实 MySQL 并发验收覆盖“生成与换教室同时发生”，不能只测两个顺序调用。

## 4. 列表与 Web 交接合同

新增教工列表显式接收 `view=teaching/responsible`，不默认并集；静态 summary/export 路由在 `{task_id}` 前注册。task/record/submission/objection ID 分别命名，均为字符串。

责任视图统计只包含本人可见学生；未形成正式考勤时 counts 为空，未查课不算出勤或缺勤。列表、详情、统计、导出使用同一个查询构造器；照片与异议证据走独立短期授权接口。跨院记录保持任务学院独立展示。

Web 的请求上下文含账号、模式、工作视图、学期、相关筛选和授权修订，复用 ContextEpoch。视图变更先清理敏感数据和待提交表单，再加载新数据；旧请求不能回填。普通教工导航依据本人能力，不为显示菜单发全院权限。
