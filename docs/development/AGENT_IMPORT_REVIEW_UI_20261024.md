# 助手资料核对结果与原导入页面衔接

日期：2026-10-24。分支：`future/agent-dev`。本地 Web 候选，未部署。

## 用户操作

已有 `import_preview_review` 读取任务完成后，管理端可打开固定页面：

```text
/dashboard/academic?tab=imports&assistant_task_id=<本人任务编号>
```

页面读取原登录任务接口，展示等待、执行、失败或核对结果。完成后按资料类型显示组和问题数量；点击“核对这一组”才读取相应已有预览，不触发保存。有阻断问题的组也能打开，让教师查看具体原因。

一组预览全部读取成功后，交给原 `ImportWizard`。原确认集合接口重新检查当前数据，展示原文件名、差异与冲突。教师可查看内容、移除文件、重新核对，再点击原“确认导入”按钮。保存使用这次核对得到的 revision，不使用助手任务时的结论或任意模型字段。各资料类型分组确认，保留原有独立保存方式。

“返回统一导入”移除当前任务参数，回到原文件夹／ZIP／表格入口。无任务参数时仍是原导入首页；没有新建菜单。

## 组件职责

- `assistantImports.ts`：验证任务业务结果，保留固定字段，并通过原登录接口读取预览。
- `useAssistantImportReview`：读取任务状态、按类型恢复完整一组预览、错误处理及上下文隔离。任一预览失败，不将已读取的半组交给页面。
- `AssistantImportReviewCard`：显示摘要和继续核对按钮，向父页发送已重新读取的预览。
- `ImportHome`：根据可选任务参数展示卡片，组合原导入页面。
- `useImportWizard.resumeMany`：恢复同类型、同学期的多个预览并重新核对，复用原保存方法；原单份最近记录恢复也调用该方法。

同时修正原 `resumeBatch` 监听在组件首次挂载时没有执行的问题；恢复入口现在首次挂载即启动核对。课程类型的异步默认值不会覆盖恢复中的资料类型上下文。

## 身份和结果边界

- 只读取后端认定属于本人的任务；任务编号始终为规范 BIGINT 字符串。前端不接收模型提供的任意请求路径。
- 结果须匹配固定 `IMPORT_PREVIEW_REVIEW` 类型、当前学院、当前运行学期及人工确认标志。工具现在额外返回 `semester_id`；缺少该字段的旧结果须重新发起，不能推断其学期。
- 每份预览的编号、类型、状态与非空学期须再次匹配。原后端仍是权限和保存规则的最终裁决者。
- 账号、学院、学期、角色、授权／配置版本、能力或任务参数变化时清除旧页面状态；迟到任务／预览响应及组件卸载后的响应不能重新打开旧资料。
- 队列未完成、任务失败、读取403或结果不完整时不展示可继续的旧操作；错误后须显式刷新。打开组的重复点击受控。
- 任务摘要不当作最终核对结果，文件内容仍按原组件以普通文本展示。没有自动点击保存或注册 AI 确认工具。

- 44项相关 Node 测试通过，包括新增任务状态/合同/迟到响应检查、多份恢复、切学期、并发恢复，以及原导入、权限路由、工作区 HTTP 和报表卡回归。

- 后端21项导入工具定向测试通过，补充验证任务结果学期字段。
- Browser 插件不可用，使用 bundled Playwright + Edge。全模拟 API 验证桌面及390px窄屏：排队无动作、显式打开两份预览、首次挂载恢复、重新核对、没有自动保存、人工使用新 revision 保存、冲突禁用保存、403清除动作、授权变化丢弃迟到预览。截图已查看，未发现卡片横向溢出或页面运行错误。

本地浏览器证据位于忽略目录 `tmp/import-review-ui-20261024/`。模拟成功保存只是 UI 请求验证，不是实际业务数据库写入验收；原后端导入保存测试另行提供领域证据。
