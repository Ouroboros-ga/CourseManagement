# 已确认增量模块与接口

状态：本次发布源码；实际发布结果、备份、源码tree/commit和迁移证据以服务器发布目录CAMPUS_RELEASE.json为准。本说明不代表完整业务验收。此前学校作息模板增量一起保留。所有路径前缀 `/api/v1`，沿用原认证、错误格式与本人/学院授权。ID响应为字符串；请求中的ID支持合法数字字符串。

## 1. 全校汇总独立授权（最终决定）

权限码 `statistics.school.read`。不属于教师默认权限，不因绑定主学院或具有本院 `statistics.read` 而获得。超管沿用校级默认能力；管理员通过已有教师账号管理权限创建教师时，可明确勾选“允许查看全校汇总”。不扩大谁能创建教师账号的既有授权。

- `POST /teacher-accounts` 增加可选布尔字段 `can_view_school_summary`，默认false。
- `PATCH /teacher-accounts/{user_id}` 可显式授予/撤销，仍要求 `lock_version`；撤销同时撤销目标有效会话。字段省略保留原授权。
- 创建、更新、教师列表响应增加 `can_view_school_summary`；教师授权及审计在同一事务，密码不写审计。
- Web教师创建弹窗新增未预选的勾选项。其余新模块本轮主要提供API，不做页面改版和小程序页面。
- `GET /statistics/school-summary?semester_id=…`：仅有效超管/具有独立权限的教师可调用，逐请求重读实际权限；返回学院、任务历史类型、组维度的任务量、受派/提交/正式完成量及正式考勤计数。未确认学院归属单列。没有学生、学号、名单、附件或跨院写接口。
- 该接口依赖学院配置及正式业务开关。普通教师仍通过学院统计入口查看授权学院，不能用此权限读取其他学院的学生明细；原先各业务模式的兼容入口不因此获得新授权。

创建例：`{username,display_name,initial_password,college_id,can_view_school_summary:true}`。只看全校汇总不等于开放学校配置、教师账号管理或跨院修改。

## 2. 初始类型与默认导入

每个学院初始三条配置数据：普通课、早自习、晚自习。`CourseType.builtin_key`分别为`regular/morning_study/evening_study`，用于稳定识别初始配置，不是封闭枚举。仍可通过原课程类型API新增任意类型、改名和停用；初始类型不直接删除，以免默认来源丢失。自定义类型保留原删除规则。

增量迁移为已有学院初始化这些类型；新建学院在同一事务初始化。已有同名类型复用原ID，不重分类历史教学班或任务。初始类型即使改名，builtin_key仍保持；停用默认普通课后导入会明确拒绝，不能静默恢复管理员停用的配置。

院级导入新建教学班时默认普通课；已有教学班明确分类不会被重复导入重置。不解析课程名称，不提供自动类别识别或文件类别映射。

前端“创建本学期早自习/晚自习”按钮：GET `/colleges/{cid}/course-types` 得到实际类型ID，调用已有学院教学班创建接口，传 `course_type_id`；再创建正式课表，传学期、星期、周次、节次和教室。早晚自习仍走统一课程链，不使用旧独立 `inspection_type` 分支。普通教学班未传类型时也默认普通课。前端可组合多个请求；本轮没有新增跨请求的整学期批量创建事务。

同时修复教务网格导入映射：只从学院默认作息版本读取，命名方案不再遮蔽默认小节映射。

## 3. 人员改派与任务换组

本组内换人仍走既有排班计划预览/具体WARN确认/提交。

新增：

- POST `/colleges/{cid}/inspection-tasks/{tid}/execution-group/preview`：`{target_group_id,lock_version}`。
- POST 同前缀 `/execution-group/confirm`：增加预览 `revision` 和可选 `reason`。

需操作者同时有原任务及目标组资源范围内的 `assignment.manage`。目标组必须本院、有效、已发布范围，任务日期、当前来源分类和名单均符合目标组及操作者上限。取消、历史、缺可靠来源或已有任何提交/考勤的任务拒绝换组。

预览明确是否撤销已有受派；确认保留同一任务ID、课次身份、原实际时间与名单，撤销原受派、使原待处理调班申请失效，更新执行组/规则及未执行任务分类快照并审计。确认后为待派，**不自动选人**；随后通过目标组的既有确认计划复核成员/支援、冲突、配额和WARN。过期版本/revision返回409。

目标组也可选择当前组，用来显式确认旧待执行任务采用当前规则/分类。新排班不再直接沿用过期组规则或变更前分类：发现不一致先拒绝，要求明确确认；已受派/历史事实不自动改写。

## 4. 查询维度与本组履职

考勤管理列表、异议列表、考勤统计和即时统计导出增加可选 `course_type_id/group_id/teaching_class_id`。适用于原管理路径及 `/colleges/{cid}` 路径。先执行原授权与SQL范围，再追加维度，最后分页、计数/聚合/导出；前端不得只过滤当前页。类型和组按任务历史快照，不按当前课程名称猜测。

`GET /colleges/{cid}/groups/{gid}/statistics/performance?semester_id=…`：需要该组的 `volunteer.group.read`，并保持冻结资源授权上限，返回任务、受派、提交、正式完成和未完成数量；不包含学生考勤或志愿者个人隐私。实际任务及受派名单继续由已有 `inspection.read` 等权限控制；本接口不会补授这些权限。

完整班级/任务明细导出仍要求原权限；全校汇总权限不会开放这些出口。**已归档的周报版本仍是整份不可变历史快照**，此次维度筛选用于即时统计/导出，不在旧周报上假装切片，也未新增“按任意维度归档周报”的协议。

## 5. 个人课表恢复和单次修改

沿用本人绑定身份和个人学期聚合 `current_version`，所有写入只保存个人表。

| 方法 | 路径 | 请求 / 行为 |
| --- | --- | --- |
| GET | `/me/timetable/deleted-entries?semester_id=…` | 本人可恢复删除列表和当前聚合版本 |
| POST | `/me/timetable/entries/{eid}/restore?semester_id=…` | `{current_version}`；恢复原ID、删除前个人内容及保留的单次例外 |
| PUT | `/me/timetable/entries/{eid}/exceptions/{day}?semester_id=…` | `{current_version,cancelled?,target_date?,course_name?,teacher?,classroom?,start_time?,end_time?,note?}` |
| DELETE | 同上日期例外路径 | `{current_version}`；撤销单次修改，恢复该日原重复规则 |

`day`为原课程实际发生日，必须命中本人保存的日期集合或周次/星期；`target_date`可将该次移到同学期另一天。开始/结束为同日有效本地时刻。取消该次用`cancelled:true`，与删除整条课程不同。

本人读取条目新增`exceptions`数组，每项为`{date,target_date,cancelled,values}`。前端展示时先展开基础规则，再移除对应原date；未取消的例外按target_date显示values。例外是当次完整显示快照，不改其他日期。删除整条课程后不再显示，其例外保留供恢复。

若已有日期例外，修改整条课程的周次/星期/日期集合先返回409，要求先撤销例外，避免悄悄丢失或生成幽灵课程。整条名称、备注等仍可编辑，当次例外保留已明确保存的显示内容。现有已保存条目上限500、可恢复删除上限500、单学期日期例外总数上限2000；超限拒绝，不清除历史凑容量。

## 6. 学籍变化通知复用现有接口

`GET /me/academic-notices`仍为唯一列表。新增`kind`区分`ACADEMIC_PUBLICATION`和`ENROLLMENT_SOURCE_CHANGED`；后者展示“你的教务归属已变化，个人课表不会自动更新”。仅本人已生效且未取消的TRANSFER事件产生，按事件ID稳定去重；不新增消息状态表、不改个人课表。

列表以SQL合并两种来源后统一排序、分页和计数。教务发布通知保留原id和内容；学籍提示id为`enrollment:事件ID`，视为不透明字符串，`version=0`、`semester_id=null`（学籍变化不一定绑定某学期）。小程序需按kind展示，不应把所有id解析成整数或把null学期拼入课表请求。
