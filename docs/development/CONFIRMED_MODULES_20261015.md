# 已确认模块补齐方案（2026-10-15）

GPT直接实现，不启用子agent、不操作生产。本轮以API和共用业务逻辑为交付，不重构页面；只对教师创建补必要授权选项。只做合理静态校验/构建，业务验收交由虚构数据手工流程。

1. 导入默认普通课；学院初始普通课/早自习/晚自习，可自定义课程类型。前端按钮调用统一建课和课表API，不在后端按名字识别、自动筛选或新增导入类别映射。
2. 组内改派复用现有确认计划；新增任务换组预览/确认，保留任务身份，禁止已有提交/考勤的任务换组，撤销原受派并回到待派，按新组明确排班。
3. 筛选由前端传条件，后端按学院权限和历史任务维度先过滤再分页/计数/聚合/导出。组负责人只看本组履职。
4. **最终授权决定**：独立 `statistics.school.read`，管理员创建教师账号时明确授权，默认false，旧教师不自动授予；教师本院默认权限不得隐式扩大为全校。全校接口只返回汇总，不授予跨院明细/修改。
5. 个人课表保存可恢复删除和日期例外，聚合乐观锁；所有个人修改仍完全独立于正式业务。
6. 转班转院提示复用现有本人通知列表；无已读/未读状态，不覆盖个人课表。学院沿用停用，不加归档；组织学期复制/负责人完整交接不做。
7. 修复导入误取命名作息映射与旧任务新派发范围复核问题，避免把历史快照当成当前派发授权。

当前先落实独立全校汇总授权与创建教师账号的授权入口，再接后续模块。具体实施状态及接口以代码和后续交付记录为准，不把本计划当完成证据。
