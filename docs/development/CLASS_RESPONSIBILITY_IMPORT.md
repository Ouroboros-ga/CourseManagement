# 学校责任区原表导入契约

## 业务与入口

本格式对应《二级学院学生责任区辅导员、班主任名单》，建立已有行政班与已有教职工档案之间的责任关系。统一资料入口识别为 `class_responsibility`，沿用原草稿、差异预览、确认及交接流程，不另建导入系统。它不建立教学班任课教师授课关系，不创建登录账号。

## 文件与字段

支持 Excel `.xlsx`、`.xls`；允许标题、空行、说明在表头上方。解析首个工作表的前15行，定位同时具备班级列及班主任/辅导员姓名或工号列的表头。学生学号表头不按此格式识别。仍保留统一入口对多业务工作表的检查，不套用课堂考勤表只采用Sheet1的特殊规则。

| 列 | 处理 |
| --- | --- |
| 序号 | 原表定位参考，不作为人员或班级ID |
| 学院 | 可省略；填写时须唯一对应当前工作区，同校学院简称、全半角和空格规则与学生名单共用 |
| 班级 / 行政班 / 班级代码 | 必须提供，匹配当前学院已有行政班；准确代码/名称优先，已有简称规则仅在唯一匹配时采用 |
| 班主任 | 关联已有有效教职工；同校同名必须补班主任工号 |
| 辅导员 | 关联已有有效教职工；同校同名必须补辅导员工号 |
| 班主任工号、辅导员工号 | 可选，文本存储保留前导零；有工号时优先且姓名须一致 |
| 生效日期、结束日期 | 可选；开始默认本次导入当天，结束为空表示未指定，结束日不再生效 |
| 核对备注 | 人工说明，不产生责任关系或权限 |

班主任/辅导员两组中至少填写一组姓名或工号。班级、人员均不凭空创建；缺档案、重名、外院或停用人员按现有规则阻止确认，提示补档案或工号。班级名称相似不代表同班，不以模糊包含规则匹配。

## 冲突与保存

- 同一行政班、同一职责、生效区间重叠，人员不同或区间不一致：明确指出来源行并阻止确认，不以后一行覆盖前一行。
- 同一职责、人员、区间完全相同的重复行：提示并跳过，不重复任命；不重叠的有效区间保留原有处理。
- 原照片序号13为机电2501、序号15为机自2501，两个不同班级，分别保留对应责任人；首次转录曾误读，交付文件已按原图复核更正。
- 教职工已存在时，唯一姓名解析为档案ID/工号再保存关系；姓名本身不作为人员主键。空白责任列或未出现的班级不撤销已有关系。
- 预览只保存草稿；正式确认继续检查来源版本、权限、学院范围、任职基线与交接约束。不得通过重导旧表绕过已确认的变更。

## 交付与验证

照片转录文件保存在本次会话的忽略目录，39条数据、表头第4行，补充可选工号和核对备注列；照片中的手写勾选、括号不作为结构化数据。真实姓名需人工对照原件校对，不把照片和真实责任名单提交到Git，也不自动导入生产。

实现：`responsibility_format.py`负责表头定位，`college_names.py`共用学院名称规则，`staff_adapter.parse_class_responsibility`复用档案解析/责任关系模型。用合成数据覆盖原表识别、唯一班级简称及真实确认、同班不同责任人冲突、外院文本拒绝，保留既有教职工与导入回归。Excel交付由内置artifact工具生成并检查渲染、39行与来源位置；未在本机Excel客户端作验收。
