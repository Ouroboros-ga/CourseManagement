# V1.0 排班规则冻结基线

冻结日期：2026-09-27。本文固化本轮代码的规则与接口语义；验证结果见 [发布验收记录](./RELEASE_ACCEPTANCE.md)。冻结不等于已经部署，运行参数仍需按学院制度配置。

## 1. 目标和边界

采用纯 Python「动态稀缺优先 → 公平域内择优 → 有界单任务换位」算法。优先保证合法分配，再考虑完成数量、公平、时间集中和楼簇偏好；不引入大型求解框架，不声称全局最优。

生成与排班分开：生成把选定范围的有效课程发生格变成任务；自动排班只分配范围内未取消、尚未受派的任务。它不按“每班固定三次”自动抽样，也不重新优化既有受派。连堂课程作为一个任务；单人周任务数按任务条数计，不按节次数计。

来源：`inspection/service.py` 的生成与 `auto_assign`，`inspection/scheduling/`。

## 2. 日期、课程与候选输入

- 教学日由学期首周周一、日期及校历覆盖共同确定。STOP 不生成课程；MAKEUP 使用来源教学周与来源星期。旧记录缺来源周时沿用实际周，缺来源星期则不猜测。
- 体育不作为 COURSE 类型被查目标。预览、生成、历史体育任务的人工/自动分配均执行该规则。体育仍保留在志愿者本人课表中，用于冲突检查。
- 体育识别使用 `course_policy.py` 明确名称及有限规范化模式，不把所有含“体育”字符串的课程都排除。
- 自动排班范围至少指定一种；同时传入时，实际优先级为 `task_ids > inspection_date > date_from/date_to`，日期区间闭合。已受派、已取消、其他学期或不存在的 ID 不进入目标集合。
- `candidate_user_ids` 缺省或空列表表示本学期启用资格对应的志愿者池；非空表示候选子集，仍检查身份、资格和冲突。
- 单请求最多 500 个目标任务、500 名候选；超过上限返回 422。生成的独立上限由 `INSPECTION_GENERATE_MAX_TASKS` 控制，当前默认 2000。

## 3. 硬约束

| 约束 | 冻结语义 |
|---|---|
| 学期与任务 | ACTIVE 学期；任务未取消；自动只处理尚未分配任务 |
| 身份资格 | ACTIVE 账号、VOLUNTEER 角色、ACTIVE 学生、本学期启用资格 |
| 本班回避 | 当前任务名单所含学生的行政班不能包含志愿者本人行政班；合班也执行 |
| 本人课程 | 按校历解析出的教学周/星期检查本人教学班课程，包括体育 |
| 任务重叠 | 既有与本轮受派均不得重叠；节次使用半开区间 `[首节, 末节+1)` |
| 单日上限 | `ASSIGNMENT_MAX_TASKS_PER_DAY > 0` 时自动与人工均不得超限；0 不限 |
| 每周上限 | `ASSIGNMENT_MAX_TASKS_PER_WEEK > 0` 时自动、换位、人工及锁内复核均强制；0 不限 |

周上限按实际日期的 ISO 自然周（周一至周日），不是校历来源教学周。启用时加载目标周全部既有未取消受派，包括范围外日期与其他学期同周受派。本学期既有未取消任务的累计负载用于公平评分；是否抵扣本周名额取决于任务实际日期，同一自然周内其他学期未取消受派也占用周名额。

当前数据库冲突判断依赖统一节次体系；真实分钟来自学期节次配置，用于时间/地点软评分。跨学期不同作息的分钟快照不在本轮范围内，不能宣称支持任意不同作息的严格分钟冲突判断。

## 4. 选择顺序与有限修复

1. 每次先选当前合法候选最少的任务；同数按日期、开始节次、任务 ID。
2. 对该任务的合法候选取学期累计负载最小值，仅保留负载不超过最小值加 1 的公平域。本轮已派计入动态负载。
3. 公平域内依次最小化：新增时间片成本、相邻任务楼簇变化成本、当日任务数、学期累计负载、志愿者 ID。
4. 分配后更新受影响任务的合法候选，不每次对所有任务候选重新查数据库。
5. 对剩余任务按日期、开始节次、ID 重试直接分配；再尝试搬动一个本轮已派任务，使分配数量净增 1。不可搬动数据库既有受派，不做多层回溯。
6. 换位最多累计 1000 次试探，按次数而非墙钟时间计数，确保固定输入可复现。为增加完成数量，换位允许离开前述公平域，但仍优先低负载替代人且不突破硬约束。

公平是局部候选集内的选择规则，不承诺所有人最终任务数绝对相等。修复预算耗尽不等于无解；未分配不代表任何算法都无法分配。

时间片为上午 `[00:00,12:00)`、下午 `[12:00,18:00)`、晚上 `[18:00,24:00)`，跨片任务累计涉及的片。缺失作息时仍有未知片成本，不伪装成零成本。

楼簇默认：13/14/15，7/8/9，1/2，3/4，5/6，10；由 `ASSIGNMENT_BUILDING_CLUSTERS` 配置。同簇相邻成本 0，异簇一般 1、已知间隔不超过 30 分钟为 2，地点未知为 1。比较插入任务前后相邻边的增量；不将未知地点作硬拒绝，也不假设已知真实步行时间。

## 5. 未分配原因与接口契约

接口每个未分配任务返回 `task_id / reason_code / message`。一个码是**按稳定顺序选择的代表原因**，不是所有候选的共同原因，也不是全部阻塞条件。

| API reason_code | 含义 |
|---|---|
| COURSE_NOT_INSPECTABLE | 历史体育课程任务不允许分配 |
| NOT_VOLUNTEER | 指定候选账号不存在、停用或不具 VOLUNTEER 角色 |
| NO_QUALIFICATION | 无本学期有效资格、学生身份无效；空候选池也使用此兜底码 |
| OWN_CLASS_CONFLICT | 与候选本人课程冲突 |
| SELF_CLASS_AVOID | 被查名单含候选本人行政班学生 |
| TASK_TIME_CONFLICT | 与既有或最终本轮任务冲突；有限换位未找到分配 |
| DAY_TASK_CAP | 达到配置的单日上限；算法内部码为 DAY_CAP_EXCEEDED |
| WEEK_CAP_EXCEEDED | 达到配置的自然周上限 |

静态候选全被排除时，使用按候选 ID 升序的首个静态拒绝原因；单人静态检查顺序为账号/角色→资格→本人课表→本班回避。存在静态候选但最终不能分配时，按候选 ID 取首个动态拒绝原因；单人动态检查顺序为任务重叠→日上限→周上限。同一人可能同时触发多个条件，接口只返回优先命中的一个。

客户端显示“本轮未分配：代表原因……”，不应把它改写成“所有人都没有资格”或“仅增加周上限一定能分配”。真实数据验收另按每个候选的最终状态做完整分类，不改变当前 API 形状。不新增“公平失败”等不存在的错误码。

数量必须守恒：`target_task_count = assigned_count + unassigned_count`；两个任务 ID 集合互斥且覆盖目标集合。已派与未派数组各按任务 ID 稳定排序。被范围过滤掉的 ID 不计作未分配。

## 6. 事务与冲突返回

- `assignment.manage` 授权后锁学期；独立只读连接建立新快照，避免旧 RR 快照和业务连接池大小为 1 的自阻塞。
- 提交前锁志愿者/日期锚点；周上限启用时扩展整周，再锁任务、当前读受派及资格/课程输入，验证原计划。
- 任务版本变动、任务已受派或硬约束失效，返回 409 并整批回滚；不静默采用过期计划。
- 部分合法分配是正常 200 响应：可分配集合原子落库，其他任务返回原因。事务“全成全败”指本次拟写集合，不代表每个目标必定分配。
- 人工改派使用相同资格/冲突/日周上限规则，加任务乐观版本，不能借人工绕过硬约束。

## 7. 本轮真实场景与后续变更

固定种子 20260926；14 名志愿者；每人既有学期任务 3 次，假定均发生于目标周以前。目标日期为 2026-09-28—30、2026-10-12—18，10-01—07 放假不排；六个被查班与输入文件固定，个人资料只保留在忽略提交的本地测试目录。

测试显式设置周上限 3；代码默认仍为 0，未修改业务 `.env`。实际录入课程、名单、教学周与体育缺周次资料的假设见 [真实资料验证](./SCHEDULING_VALIDATION.md)。最终分配与原因验收结果由 [发布验收记录](./RELEASE_ACCEPTANCE.md) 记载。

冻结后改变硬约束、顺序、公平容差、修复预算、原因语义或 API 范围，必须同时更新本文与对应验收；改变学校运行参数应记录新值并重跑真实场景，不把既有成绩当作新配置的验证。
