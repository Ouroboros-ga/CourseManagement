# V1.0 后续开发路线

日期：2026-09-20。依据：[技术方案 V1.5](../查课管理系统V1.0开发技术方案.md)、[权限策略 V1.1](./PERMISSIONS.md)。本文是开发安排，不表示功能已实现。本轮仅更新文档，不执行迁移或数据库赋权。

## 1. 角色边界

| 操作 | 超级管理员 | 教师管理员 |
|---|---|---|
| 授予/撤销超级管理员 | 允许 | 禁止 |
| 授予/撤销教师管理员 | 允许 | 禁止，包含自己的教师角色 |
| 授予/撤销学生工作负责人 | 允许 | 当前学院内允许 |
| 手工授予学生/志愿者以绕过绑定、资格 | 禁止 | 禁止 |
| 配置负责人三个个人可选权限 | 允许 | 允许，受目标身份与禁止自我提权约束 |

检查角色集合的增删差集，不仅检查新增项。混入禁止操作的请求整体失败。负责人角色撤销时清除个人授权，重新授予不恢复旧开关。管理权限不扩大本人提交、本人异议的范围。

## 2. 当前起点

静态核对：已有 FastAPI 骨架、11 张身份相关表、Web 登录/刷新/退出、本人绑定和身份测试；PermissionCode 只有三个可选项，五角色默认权限为空。微信登录、完整授权管理、审计和业务模块仍需开发。现有代码不能视为已通过新权限基线。

继续采用 Python 3.12、FastAPI、同步 SQLAlchemy 2.x、Alembic、MySQL 8.4、openpyxl；管理端 Vue 3 + TypeScript，小程序 WXML/JS/WXSS。不同业务模块分批验收，不一次铺开全部表和 CRUD。

表中模块目录均相对 `backend/app/modules/`（已给完整路径者除外）。每个模块首次实现时创建模型、schema、repository、service、router、permissions 所需文件，不机械生成空文件。新增模型必须注册到 `backend/app/models.py`。

管理端随各阶段交付对应页面；小程序从 P2 开始联调，不把全部前端工作拖到末尾。先完成每阶段后端契约及越权测试，再接页面。

## 4. P1 的执行顺序

1. 按 [首批实施计划](./superpowers/plans/2026-09-20-permission-foundation.md) 完成 38 项注册、默认角色矩阵和纯角色变更策略。此批不赋权现有数据库。
2. 改造种子同步：将注册表同步和账号创建分开；默认角色关联精确对齐矩阵，重复执行不重复写。移除旧默认关联前输出差异；不删除用户个人授权、不重置既有管理员密码。使用隔离库验证。
3. 增加审计表和用户 `lock_version`（当前 UserAccount 尚无此字段），由新迁移添加，不修改已应用的初始迁移。测试旧结构升级、约束及 metadata 一致性；现有测试仅 create_all，不能替代迁移测试。
4. 实现 `GET /role-assignment-targets`、`PUT /users/{id}/roles`、`GET /optional-permission-targets` 及个人开关 API；前缀 `/api/v1`。PUT 接收完整 `roles`、`lockVersion`、`reason`，返回实际角色及新版本；可选项只接受三个许可 code。账号编辑 schema 不接受 roles/permissions，防止旁路。
5. 变更服务锁定操作者及目标用户（按 ID 固定顺序），事务内重新读取有效身份、权限、目标角色和版本；校验差集后修改关联、清理失效可选项、写审计，再统一提交。repository 不自行 commit。禁止项 403、不可见目标 404、版本冲突 409、未知 code 422。
6. 对会话解析补充 `session.user_id == user_id` 校验；权限每次从当前数据库取得。有效个人权限仅来自负责人身份与三项许可清单；初核带来的 objection.read 为派生结果，不写入额外个人授权。
7. MySQL 集成测试覆盖双方同一目标并发修改（一个成功、另一个 409）、角色撤销与授权同时发生、审计失败整笔回滚、旧会话下一请求权限变化。通过后接管理端受限目标选择器与角色/开关页面。

P1 不能宣称完成 VOLUNTEER 自动身份或所有行级过滤；分别在 P3 及各业务模块验收。

## 5. 其他阶段的关键约束

- P2：增加微信客户端调用依赖时，将 HTTP 客户端放入运行时依赖，不能只依赖当前 dev 组的 httpx。AppSecret/session_key 不进入响应、审计或日志；按 appid+openid 唯一识别。绑定事务核验有效学生、核销码、赋 STUDENT、追加审计；P3 引入资格后同时补齐绑定后的资格同步路径。
- P3：先移植 `docs/legacy_parser_reference/normalize.py` 到 `common/parsing/time_slots.py` 并保留原测试边界，再做课表解析和 DTO→ORM；不直接导入参考目录。默认支持 xlsx，xls 需要单独确认依赖与支持范围。导入权限是目标资源 manage + import.execute。
- P4/P5：截止时间不早于最后相关任务结束；逾期作为独立事实记录，不新增任务状态。任务行锁、版本检查、幂等记录控制重复提交与审核。正式并发验证必须用独立连接和真实 MySQL，不能靠单线程顺序请求证明。
- P5/P7：短时文件 URL 只在签发时鉴权；不增加每次下载重新鉴权或即时撤销下载权限。过期文件清理后保留清理状态与必要审计。照片和证明材料保留期限分别定义。
- P7：无 worker.py、job/、通用队列；受限同步执行，规模超限在写入前拒绝。清理通过部署定时脚本复用文件服务，不在每个 API 进程启动独立定时器。

## 6. 冻结时点与验收纪律

角色互授边界已冻结，不再阻塞 P1。进入 P3 前确定实际导入模板；P4 前确定默认截止时间与排班约束；P5 文件开放前确定照片/证明各自期限和上传上限；P6 前确定异议窗口；P7 前用实际学生数、任务数、峰值同时提交数确定压测目标。尚未给出的业务数值不自行写死为学校制度。

所有阶段运行相关单测、真实 MySQL 集成测试、ruff 和 mypy；数据库不可用导致 skip 不算通过。现有集成夹具会 drop_all，运行前确认 TEST_DATABASE_URL 指向专用测试库，禁止使用开发业务库或生产库。P1 先补该目标保护及 CI 失败门槛，再运行破坏性测试。

最终记录实际执行命令、通过/失败/跳过数量、迁移版本、未验证边界。本轮为文档规划，未运行应用测试、未更改业务代码、未执行种子脚本或迁移。
